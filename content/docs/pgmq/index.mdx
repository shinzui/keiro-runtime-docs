pgmq is a PostgreSQL-native message queue, and **pgmq-hs** is the first-party
Haskell client for it. In the keiro runtime family, pgmq is the queue substrate:
applications create queues, send JSON messages, lease visible messages for a
visibility timeout, then archive or delete the messages after work completes.
shibuya workers consume pgmq through the
[shibuya pgmq adapter](/docs/integrations/shibuya-pgmq-adapter), while keiro's
job layer builds typed background jobs on top of the same primitives.

The current package family is `0.6.1.1`: `pgmq-core`, `pgmq-hasql`,
`pgmq-effectful`, `pgmq-config`, and `pgmq-migration` are released together.
The migration package is a native `pg-migrate` component, not a standalone
schema runner.

<Callout type="info">
  Version 0.6 adds PGMQ 1.12 grouped-head reads, PGMQ 1.13 explicit partition premake and partition
  metrics, and native migrations through 1.13. Version 0.6.1 adds `effectful-core` 2.7 support with
  no Haskell API change; prefer 2.7.1.1+ to avoid the dynamic-effect dispatch regression in 2.7.0.0.
</Callout>

Deployments upgrading from 0.4 must still complete the 0.5 mixed-case-name preflight:
[Remediate mixed-case queue names](/docs/pgmq/how-to/remediate-mixed-case-queue-names).

pgmq-hs is split by concern. `pgmq-core` owns validated names and message
types. `pgmq-hasql` is the direct Hasql client. `pgmq-effectful` lifts the same
operations into an `effectful` dynamic effect and can emit OpenTelemetry spans.
`pgmq-config` reconciles declared queue topology at startup. `pgmq-migration`
exports the native component that installs the pgmq 1.13.0 schema without relying on the PostgreSQL
extension and can explicitly adopt verified predecessor history.

## Source changes awaiting release

The reviewed source also implements queue/archive inspection reads and lost-reply classification.
These APIs are absent from published 0.6.1.1. Their reference sections are marked unreleased:
[inspection reads](/docs/pgmq/reference/hasql-api#unreleased-inspection-reads) and
[disconnect classification](/docs/pgmq/reference/effectful-api#unreleased-disconnect-classification).
Use the [release matrix](/docs/getting-started/compatibility-and-upgrades) for installation.

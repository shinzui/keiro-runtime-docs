---
title: "Queue configuration"
description: "Declarative queue topology and idempotent startup reconciliation from pgmq-config."
---

`pgmq-config` lets an application declare desired queue topology as Haskell
values and reconcile it on boot. Reconciliation creates what is missing, reports
what it will not repair, and mutates already-existing state in exactly one
documented case.

The current package family is 0.6.1. The reconciliation corrections described here shipped in
0.5.0.0; 0.6.0.0 adds explicit partition premake configuration.

## Queue configuration values

```haskell
data QueueConfig = QueueConfig
  { queueName :: !QueueName
  , queueType :: !QueueType
  , notifyInsert :: !(Maybe NotifyConfig)
  , fifoIndex :: !Bool
  , topicBindings :: ![TopicPattern]
  }

data QueueType
  = StandardQueue
  | UnloggedQueue
  | PartitionedQueue !PartitionConfig

data PartitionConfig = PartitionConfig
  { partitionInterval :: !Text
  , retentionInterval :: !Text
  , premake :: !(Maybe Int32)
  }

data NotifyConfig = NotifyConfig
  { throttleMs :: !(Maybe Int32)
  }
```

Use the smart constructors rather than filling every field by hand:

```haskell
standardQueue :: QueueName -> QueueConfig
unloggedQueue :: QueueName -> QueueConfig
partitionedQueue :: QueueName -> PartitionConfig -> QueueConfig

withNotifyInsert :: Maybe Int32 -> QueueConfig -> QueueConfig
withFifoIndex :: QueueConfig -> QueueConfig
withTopicBinding :: TopicPattern -> QueueConfig -> QueueConfig
```

`withNotifyInsert Nothing` uses `defaultThrottleMs`. `withFifoIndex` adds the GIN
index used by grouped FIFO reads. `withTopicBinding` appends a topic pattern to
the queue's bindings.

```haskell
-- | The throttle interval pgmq applies when none is given: 250 milliseconds.
defaultThrottleMs :: Int32
defaultThrottleMs = 250
```

A `NotifyConfig` whose `throttleMs` is `Nothing` means "use this value". The
pgmq-hasql enable statement supplies it with a SQL `coalesce($2, 250)`, and
`pgmq.enable_notify_insert` declares the same figure as its parameter default,
so a `Nothing` config and a stored `250` agree and reconciliation does not flap
between them.

For partitioned queues, `premake = Nothing` preserves pgmq's default. `Just n` calls the explicit
PGMQ 1.13 creation surface with that premake count. This is creation-time configuration; the
additive reconciler does not mutate premake, interval, or retention on an existing queue.

## Reconciliation

```haskell
ensureQueues :: [QueueConfig] -> Session ()
ensureQueuesWithPool :: Pool -> [QueueConfig] -> IO (Either UsageError ())
ensureQueuesReport :: [QueueConfig] -> Session [ReconcileAction]
```

A run snapshots existing state with four read-only queries — queues (via
`listQueuesUnvalidated`, so a foreign queue whose name this client would reject
cannot break startup), topic bindings, notification throttles, and FIFO
indexes — and then, per declared config:

| Observed state | Effect | Reported as |
| --- | --- | --- |
| Queue absent | Created with the declared type | `CreatedQueue` |
| Queue present, shape matches | Nothing issued | `SkippedQueue` |
| Queue present, shape differs | Nothing issued | `DetectedQueueTypeDrift` |
| Throttle row absent | Notify enabled with the declared interval | `EnabledNotify` |
| Throttle row present, interval matches | Nothing issued | `SkippedNotify` |
| Throttle row present, interval differs | Row updated in place | `UpdatedNotifyThrottle` |
| FIFO index declared and absent | Index created | `CreatedFifoIndex` |
| FIFO index declared and present | Nothing issued | `SkippedFifoIndex` |
| Binding absent | Bound | `BoundTopic` |
| Binding present | Nothing issued | `SkippedTopicBinding` |

Queues, bindings, and throttles that exist in the database but are absent from
the config are never touched. Nothing is ever dropped, disabled, or converted.

```haskell
data ObservedQueueType
  = ObservedStandard
  | ObservedUnlogged
  | ObservedPartitioned

data ReconcileAction
  = CreatedQueue !QueueName !QueueType
  | EnabledNotify !QueueName !(Maybe Int32)
  | CreatedFifoIndex !QueueName
  | BoundTopic !QueueName !TopicPattern
  | SkippedQueue !QueueName
  | SkippedNotify !QueueName
  | SkippedFifoIndex !QueueName
  | SkippedTopicBinding !QueueName !TopicPattern
  | UpdatedNotifyThrottle !QueueName !Int32 !Int32
  | DetectedQueueTypeDrift !QueueName !QueueType !ObservedQueueType
```

The skipped constructors are useful in startup logs. They show the desired
topology was already present instead of hiding all no-op work.

`UpdatedNotifyThrottle` carries the queue, the observed interval, and the
declared interval in milliseconds. It is the reconciler's **only** mutation of
already-existing state, issued through `pgmq.update_notify_insert`. That
function also resets the throttle's `last_notified_at` to the epoch, so the next
insert on that queue notifies immediately; this happens at most once per real
configuration change.

`DetectedQueueTypeDrift` carries the queue, the declared type, and the observed
type. It **replaces** `SkippedQueue` for the queue it concerns, so the report
still carries exactly one queue-existence action per declared config. Only the
three-way shape is compared: a declared `PartitionedQueue` against an observed
partitioned queue matches regardless of its interval and retention settings,
because `pgmq.list_queues()` does not report them.

## Effectful integration

When the cabal `effectful` flag is enabled, which is the default,
`pgmq-config` also exposes:

```haskell
ensureQueuesEff :: (Pgmq :> es) => [QueueConfig] -> Eff es ()
ensureQueuesReportEff :: (Pgmq :> es) => [QueueConfig] -> Eff es [ReconcileAction]
```

These functions use the same `Pgmq` effect as the rest of the application, so
queue reconciliation runs through whichever interpreter you install, including
`runPgmqTraced`.

<Callout type="warn">
  Reconciliation does not delete queues, remove topic bindings, disable notify,
  or change an existing queue from standard to unlogged or partitioned.
  Converting a queue between those shapes means dropping and recreating it,
  destroying every message it holds, which a process that runs automatically at
  startup — potentially on several replicas at once — must never do. The drift is
  surfaced as `DetectedQueueTypeDrift` and a human decides.

  The general rule: reconcile automatically only where the repair is
  non-destructive and pgmq's API supports it in place; otherwise report and stop.
  The throttle interval is the one case that qualifies.
</Callout>

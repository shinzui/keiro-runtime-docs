## 0.7.0.0 — 2026-10-26

- **New package — pgmq-inspect:** adds a standalone executable and mountable read-only HTTP server, OpenAPI discovery and shared bounded WebSocket metrics. LISTEN accelerates refresh; polling remains authoritative. Inspection never leases or removes messages.
- **pgmq-core / pgmq-hasql / pgmq-effectful:** publish non-destructive live/archive paging and lookup, `ArchivedMessage`, and disconnect/ambiguous-reply classification. Custom effect interpreters must handle the inspection operations.
- **Breaking — pgmq-config:** handle `DetectedQueueNameCollision` and `UnsupportedNotifyOnPartitionedQueue` in exhaustive reconciliation matches. Collisions refuse alias/resource creation; partition notification requests are reported without installation.
- **JSON:** core records, metrics and reconciliation reports gain stable snake_case encodings with explicit null optional fields. Remove conflicting orphan instances. Preserve exact int64 IDs in browser clients.
- **pgmq-migration:** append-only migration 0007 restricts insert notification fail-open handling to registered ordinary queues. Apply it before traffic; partitioned queues no longer notify. Keep polling enabled.
- **Deployment:** inspection uses separate finite-budget database capacity and explicit database grants. Bounds on page rows do not bound payload bytes or scan cost; measure inspection against worker SLOs.


## 0.6.1.1 — 2026-09-25

- **pgmq-migration:** accepts pg-migrate 1.2 alongside 1.1 without changing the ledger, validators, or public API.
- **pgmq-core / pgmq-hasql / pgmq-effectful / pgmq-config:** coordinated version update; library APIs are unchanged.
  Dedicated-cluster tests use the shared stable temporary root, and the obsolete test-support bounds workaround is removed.

## 0.6.1.0 — 2026-09-16

- **pgmq-effectful / pgmq-config:** support Effectful core 2.7 alongside 2.6 and drop the untested 2.5 support claim.
  Public APIs are unchanged. Upstream recommends 2.7.1.1 or newer for dynamic-dispatch performance.
- **pgmq-core / pgmq-hasql / pgmq-migration:** coordinated version update with unchanged public APIs.
  Database tests use ephemeral-pg 0.3.1 and a stable temporary root to reclaim abandoned clusters.

## 0.6.0.0 — 2026-09-10

- **pgmq-hasql / pgmq-effectful:** add grouped-head reads and polling for PGMQ 1.12 or later, plus explicit partition premake on 1.13 or later.
- **Breaking — pgmq-hasql / pgmq-effectful:** re-exported `QueueMetrics` gains nullable `defaultPartitionLength`; direct constructors must supply it.
- **Breaking — pgmq-config:** `PartitionConfig` gains `premake`; choose `Nothing` for the server default or an explicit positive count on PGMQ 1.13.
  Premake applies only when creating a queue.
- **pgmq-migration:** append-only migrations 0004–0006 reach PGMQ 1.13 while retaining the 1.11 predecessor-history import contract and existing queue data.
- **pgmq-core:** coordinated version update; core types are unchanged.

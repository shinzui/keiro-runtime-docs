## 0.10.0.1 — 2026-10-05

- **shibuya-core:** admits random 1.3 alongside 1.2 for retry jitter.
- **shibuya-metrics:** coordinated version update requiring core 0.10.0.1.

## 0.10.0.0 — 2026-09-21

- **Breaking — shibuya-core:** shutdown configuration gains a total deadline; processing state gains a progress timestamp.
  Configuration/policy errors add duplicate-ID, concurrency, and overflow cases.
  Permanent finalization failure raises `ProcessorFailure`.
- **shibuya-core:** validates configuration before resource acquisition and fixes startup, idle wakeup, keyed-worker ownership, and repeated/concurrent shutdown.
  Ignored processor failures retain terminal lifecycle evidence.
- **Breaking — shibuya-metrics:** health checks gain dependency deadlines; readiness reports application lifecycle.
  Server configuration gains host and subscription limits, and the server defaults to loopback.
  WebSocket types gain terminal outcomes and shutdown state.
- **shibuya-metrics:** exports `combinedApp`, bounds health checks and retained WebSocket selections, and fixes slot cleanup and shutdown notification.
- **Operational boundary:** `inboxSize` does not limit distinct in-progress batch keys; applications must bound externally controlled key cardinality.

## 0.9.0.3 — 2026-09-20

- **shibuya-core:** removes the supervisor link that could kill a surviving caller after all processors finished and a major garbage collection ran.
- **shibuya-core:** delivers processor failure once under `StopAllOnFailure`, preventing duplicate linked exceptions.
- **shibuya-metrics:** coordinated core dependency update; no metrics API change.

## Later source changes

Pause/resume controls, detailed latency/progress metrics, bounded outbound WebSocket queues, CORS, and tracing fixes remain unreleased at this check.
They are excluded from the published entries above.

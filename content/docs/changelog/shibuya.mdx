## 0.12.0.0 — 2026-10-26

- **Breaking — shibuya-core:** `Ingested` gains `deliveryStatus`. Direct constructors supply `pure DeliveryCurrent` to preserve existing behavior; `mkIngested` supplies it automatically.
- Runners check admission once per delivery, including each batch member. `DeliverySuperseded` skips both handler and finalizer and owns no processing metrics slot. The check is a snapshot; it cannot revoke work already admitted.
- **shibuya-metrics:** coordinated dependency update to core 0.12.

## 0.11.0.0 — 2026-10-25

- **Breaking — core:** complete `AppConfig` records supply `metricsDetail`; processor metrics and handles gain detail fields. Handle `Paused` and `InvalidMaxTrackedPartitions`, and new fields on exposed supervised/application handles. Prefer `defaultAppConfig` updates.
- Publishes atomic intake pause/resume, optional bounded latency/in-flight/progress detail, cursor JSON, ingestion/shutdown spans and tracing cancellation fixes. Admitted polls and inbox work may finish while paused.
- **Breaking — metrics:** server configuration gains controls, CORS and output-queue limits; server handles gain shutdown; health adds paused counts and socket messages add `ServerError`. Controls stay disabled by default.
- WebSocket output is bounded by frames and bytes, with overflow followed by a replacement snapshot. Origin checks precede admission. Configure browser origins explicitly.
- Serial intake startup and drain work are reduced. Upstream timing comparisons passed their threshold; observed allocation increases remain unexplained. These measurements do not establish universal overhead guarantees.


## 0.10.0.1 — 2026-10-05

- **shibuya-core:** admits random 1.3 alongside 1.2 for retry jitter.
- **shibuya-metrics:** coordinated version update requiring core 0.10.0.1.

## 0.10.0.0 — 2026-09-21

- **Breaking — shibuya-core:** shutdown configuration gains a total deadline; processing state gains a progress timestamp.
  Configuration/policy errors add duplicate-ID, concurrency, and overflow cases.
  Permanent finalization failure raises `ProcessorFailure`.
- **shibuya-core:** validates configuration before resource acquisition and fixes startup, idle wakeup, keyed-worker ownership, and repeated/concurrent shutdown.
  Ignored processor failures retain terminal lifecycle evidence.
- **Breaking — shibuya-metrics:** health checks gain dependency deadlines; readiness reports application lifecycle.
  Server configuration gains host and subscription limits, and the server defaults to loopback.
  WebSocket types gain terminal outcomes and shutdown state.
- **shibuya-metrics:** exports `combinedApp`, bounds health checks and retained WebSocket selections, and fixes slot cleanup and shutdown notification.
- **Operational boundary:** `inboxSize` does not limit distinct in-progress batch keys; applications must bound externally controlled key cardinality.

## 0.9.0.3 — 2026-09-20

- **shibuya-core:** removes the supervisor link that could kill a surviving caller after all processors finished and a major garbage collection ran.
- **shibuya-core:** delivers processor failure once under `StopAllOnFailure`, preventing duplicate linked exceptions.
- **shibuya-metrics:** coordinated core dependency update; no metrics API change.

# Migration Standards

**Start with the pg-migrate model, then give every service one component, one complete plan, and one migration executable.**

This area is the fleet’s prescriptive guide to database evolution for Keiro services. It covers compile-time plans, immutable SQL authoring, service packaging, deployment, testing, the completed Codd transition, and the release-specific Kiroku `0010` checksum recovery in [migration operations](/docs/runtime-patterns/migrations/operations).

Integrity is layered on purpose: compile-time embedding, a review-time lockfile and body lint, a boot-time startup handshake, and two deploy-time gates — `verify` for the ledger and `verify-schema` for live objects. No layer substitutes for another.

## Start here

1. [The pg-migrate Model](/docs/runtime-patterns/migrations/pg-migrate-model) — components, manifests, embedding, execution, and the ledger.
2. [Service Migration Packages](/docs/runtime-patterns/migrations/service-package) — the standard service component, dependency order, and CLI executable.
3. [Migration Authoring](/docs/runtime-patterns/migrations/authoring) — append-only SQL and manifest rules.

## Test and operate

* [Migration Testing](/docs/runtime-patterns/migrations/testing) — default-build integrity gates, pure construction checks, ephemeral PostgreSQL, and nested results.
* [Migration Operations](/docs/runtime-patterns/migrations/operations) — inspect, apply, verify ledger and live schema, and repair.
* [Codd Transition](/docs/runtime-patterns/migrations/codd-transition) — why persistent fleets imported history ledger-only.

## Upgrade release cohorts deliberately

For Keiro 0.21 and Kiroku Store 0.11, follow the [0012–0015 migration cutover](/docs/runtime-patterns/migrations/operations#upgrade-the-kiroku-store-in-order). This crosses a stopped-writer boundary, stopped-subscription boundary, and transactional index builds; ordinary additive-DDL rollout assumptions do not apply.

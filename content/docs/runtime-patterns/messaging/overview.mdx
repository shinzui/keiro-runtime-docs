# Keiro Messaging Patterns

**How keiro services orchestrate internally and talk to each other: the standards index.**

Use this area for process managers, public integration contracts, transactional handoffs, and the Shibuya transports that carry asynchronous work. Start with the glossary, then follow the path matching the behavior you are building.

## Shared Vocabulary

* [Messaging glossary](/docs/runtime-patterns/messaging/glossary) — domain and integration events, outbox, inbox, acknowledgements, delivery, and transport terms.

## Orchestrating Inside A Service

* [Process managers and durable timers](/docs/runtime-patterns/messaging/process-managers) — saga state, deterministic dispatch, the typed reaction runner (`Keiro.ProcessManager.Reaction`), worker policies, timers, and the orchestration decision ladder.

## Talking To Other Services

* [Integration events](/docs/runtime-patterns/messaging/integration-events) — the public envelope, identity, versioning, ordering, and trace propagation contract.
* [Transactional outbox](/docs/runtime-patterns/messaging/outbox) — safely enqueue outbound integration events, classify terminal rejection, and finalize publication outcomes atomically.
* [Idempotent inbox](/docs/runtime-patterns/messaging/inbox) — deduplicate inbound integration events with their local effects, or delegate the receipt to the downstream state transition.

## The Processing Substrate

* [Shibuya processing](/docs/runtime-patterns/messaging/shibuya-processing) — acknowledgement intent, application dead-letter codes, finalization, concurrency, batching, supervision, and shutdown.
* [Transport selection](/docs/runtime-patterns/messaging/transport-selection) — choose among PGMQ, Kafka, and Kiroku subscriptions.
* [Typed PGMQ jobs](/docs/runtime-patterns/messaging/pgmq-jobs) — background work, required job ordering and FIFO-heads, retry policy, visibility timeout, DLQ retention, and queue identity.
* [PGMQ queue lifecycle and reconciliation](/docs/runtime-patterns/messaging/pgmq-queue-reconciliation) — validated physical names, PGMQ 1.13 schema, additive provisioning, partition premake and spill, drift, notifications, and retry classification.
* [PGMQ connection faults and retry budgets](/docs/runtime-patterns/messaging/pgmq-connection-faults) — what a restart, backend termination, or TCP reset looks like to the runtime, adapter poll and ack budgets, exhaustion under supervision, and idempotent enqueues under lost replies.
* [Kiroku subscriptions](/docs/runtime-patterns/messaging/kiroku-subscriptions) — consume a service's own event log through Shibuya.

## Before Production

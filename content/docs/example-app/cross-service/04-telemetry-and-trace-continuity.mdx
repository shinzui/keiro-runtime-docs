Tracing is opt-in with `SEIHOU_TRACING_ENABLED=true`. Each service passes one configured tracer
through application entrypoints and runtime options; short-lived executables flush before exit.
This chapter distinguishes the Kafka continuity proved by the app from its one-shot PGMQ boundary.

## Kafka parentage

The outbox publisher injects the current `send <topic>` span into W3C Kafka headers. Consumers run
inside Shibuya's `<topic> process` span, carrying `messaging.system=kafka` and typed partition/offset
attributes. The verifier asserts that each selected consumer span is a direct child of its
corresponding producer span. Domain commands run beneath that consumer context.

Do not use the contract payload's historical `traceParent` value as the remote parent. The outgoing
transport header is the authority, and the publisher avoids duplicate stored/live trace headers.

## PGMQ evidence and its limit

Hospital enqueues current trace headers and emits queue publish/receive spans. Its pinned
`runJobOnceWithContext` reads/finalizes directly and does not extract the remote parent or create a
Shibuya job process span. The verifier therefore checks publish, receive, domain command, deletion,
and DLQ evidence without promising one trace continues through this one-shot boundary.

Continuous `jobProcessor`/`runJobWorkers` is a different runtime path. Do not infer its behavior
from this application's one-shot demonstration.

## Collector endpoint semantics

The scenario harness uses the generic OTLP HTTP base `http://127.0.0.1:4318`; the exporter appends
`/v1/traces`. `SEIHOU_OTLP_TRACES_ENDPOINT` maps to the per-signal
`OTEL_EXPORTER_OTLP_TRACES_ENDPOINT`, which is used unchanged and must include the complete
trace path, for example `http://127.0.0.1:4318/v1/traces`.

A retained malformed Kafka message is acknowledged successfully after poison storage, so its
consumer span has `shibuya.ack.decision=ack_ok` and an OK status. Poison retention is observable in
application rows; it is not a transport failure span.

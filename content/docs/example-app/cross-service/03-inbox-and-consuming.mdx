Kafka delivery is at least once. Each service deduplicates accepted integration messages in its
own inbox transaction, and subsequent effects need replay-safe identity. Shibuya owns adapter
finalization; handlers receive read-only messages and return `AckDecision`.

## One-shot application lifecycle

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Integration/KafkaConsumer.hs`
(artifact-level URI pending):

```haskell
runConsumerOnce
  :: (IOE :> es, Error KafkaError :> es, Tracing :> es)
  => Maybe Tracer
  -> IncidentCommandStore
  -> IncidentKafkaConsumerConfig
  -> Eff es (Either IncidentKafkaConsumerError IncidentKafkaConsumeOnceResult)
runConsumerOnce tracer store config = do
  resultVar <- liftIO newEmptyMVar
  state <- liftIO newKafkaAdapterState
  runKafkaConsumer (consumerProperties state config) (subscription config) $ do
    Adapter{adapterName, source, shutdown} <-
      kafkaAdapterWith state (defaultConfig (TopicName <$> config.topics))
    let finiteAdapter = Adapter{adapterName, source = Stream.take 1 source, shutdown}
        processorId = ProcessorId (Text.intercalate "," config.topics)
        appConfig =
          defaultAppConfig
            { ShibuyaApp.strategy = ShibuyaApp.StopAllOnFailure
            , ShibuyaApp.inboxSize = config.inboxSize
            }
    appResult <- runApp appConfig [(processorId, mkProcessor finiteAdapter (processOneRecording resultVar tracer store config))]
    case appResult of
      Left err -> pure (Left (IncidentKafkaApplicationFailed err))
      Right appHandle -> do
        waitApp appHandle
        _ <- stopAppGracefully defaultShutdownConfig appHandle
        recorded <- liftIO (tryReadMVar resultVar)
        case recorded of
          Just (Left err) -> pure (Left (IncidentKafkaHandlerFailed err))
          Just (Right result) -> pure (Right result)
          Nothing -> do
            metrics <- getAppMetrics appHandle
            pure (Left (IncidentKafkaProcessorStopped (Text.pack (show metrics))))
```

The finite adapter takes one message, while `runApp` starts a serial processor under
`StopAllOnFailure`. The caller waits and gracefully stops it before the Kafka consumer scope
closes. It reports handler/startup/stopped-without-result failures rather than assuming success.
Hospital uses the same lifecycle for Incident messages.

## Continuous lifecycle

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Integration/KafkaConsumer.hs`
(artifact-level URI pending):

```haskell
runConsumerUntil
  :: (IOE :> es, Error KafkaError :> es, Tracing :> es)
  => Maybe Tracer
  -> IncidentCommandStore
  -> IncidentKafkaConsumerConfig
  -> IO ()
  -> Eff es (Either IncidentKafkaConsumerError Bool)
runConsumerUntil tracer store config awaitStop = do
  state <- liftIO newKafkaAdapterState
  runKafkaConsumer (consumerProperties state config) (subscription config) $ do
    adapter <- kafkaAdapterWith state (defaultConfig (TopicName <$> config.topics))
    let processorId = ProcessorId (Text.intercalate "," config.topics)
        appConfig =
          defaultAppConfig
            { ShibuyaApp.strategy = ShibuyaApp.StopAllOnFailure
            , ShibuyaApp.inboxSize = config.inboxSize
            }
    appResult <- runApp appConfig [(processorId, mkProcessor adapter (processOne tracer store config))]
    case appResult of
      Left err -> pure (Left (IncidentKafkaApplicationFailed err))
      Right appHandle -> do
        liftIO awaitStop
        Right <$> stopAppGracefully defaultShutdownConfig appHandle
```

The stop action is connected to termination signals in the CLI path. One-shot and continuous
modes share the adapter and handler, keeping offset/retry behavior consistent.

## Ack, retry, and durable poison

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Integration/KafkaConsumer.hs`
(artifact-level URI pending):

```haskell
inboxResultDisposition
  :: Either IncidentInboxFailure IncidentHospitalInboxAccept
  -> InboxDisposition
inboxResultDisposition = \case
  Right{} -> FinishWith (generatedAck GeneratedInbox.InboxAckOk)
  Left IncidentInboxDuplicate -> FinishWith (generatedAck GeneratedInbox.InboxAckOk)
  Left IncidentInboxInProgress -> FinishWith (generatedAck GeneratedInbox.InboxRetry)
  Left (IncidentInboxPreviouslyFailed reason) ->
    generatedPoison "previously_failed" ("previous inbox failure: " <> fromMaybe "unknown" reason)
  Left (IncidentInboxDedupeFailed err) -> generatedPoison "dedupe_failed" err
  Left (IncidentInboxDecodeFailed err) ->
    generatedPoison (decodeFailureClass err) (Text.pack (show err))
  Left (IncidentInboxStoreFailed _err) -> FinishWith (generatedAck GeneratedInbox.InboxRetry)
  Left (IncidentInboxWorkflowSignalFailed _err) -> FinishWith (generatedAck GeneratedInbox.InboxRetry)
```

Accepted and duplicate input acknowledges. In-progress and store failures retry. Malformed or
terminal poison is first upserted to the service's `inbound_kafka_failures` table; only after
that durable write does the handler return `AckOk`. If poison storage is unavailable, it retries.
The Kafka adapter has no DLQ producer, so `AckDeadLetter` would not by itself retain the payload.

Hospital's inbox atomically deduplicates and stores accepted transfer needs; its router/work
dispatch then uses local identities. Incident's response path looks up a pending awakeable by
workflow owner before signalling it, and capacity snapshots feed its local router.

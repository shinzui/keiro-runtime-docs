---
title: "02 — Outbox and publishing"
description: "Enqueue-in-transaction then claim-and-publish: how a private event becomes an outbox row and reaches Kafka."
---

The example's enqueue command reads an already-recorded private event and writes a stable
integration outbox row. That enqueue is transactional, but it is **separate from the original
domain append** in this on-demand example. The generic outbox primitive can also be composed into
an application's append transaction.

## Private event to public envelope

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Integration/Outbox.hs`
(artifact-level URI pending):

```haskell
triageEventToOutboxEvent :: RecordedEvent -> TriageEvent -> Maybe IncidentIntegrationOutboxEvent
triageEventToOutboxEvent recorded = \case
  TransferNeedEmitted transferNeed ->
    let traceParent = defaultTraceParent
        publicMessage = incidentTransferNeedMessage transferNeed traceParent recorded.createdAt
        publicEvent =
          IntegrationEvent
            { messageId = publicMessage.messageId
            , source = incidentIntegrationSource
            , destination = incidentEventsTopic
            , key = Just (Text.pack (show transferNeed.incidentId))
            , eventType = messageType publicMessage
            , schemaVersion = publicMessage.schemaVersion
            , contentType = ApplicationJson
            , schemaReference = Nothing
            , sourceEventId = Just recorded.eventId
            , sourceGlobalPosition = Just recorded.globalPosition
            , payloadBytes = LazyByteString.toStrict (Aeson.encode publicMessage)
            , occurredAt = recorded.createdAt
            , causationId = EventId <$> recorded.causationId
            , correlationId = EventId <$> recorded.correlationId
            , -- No stored trace context: the live producer ("send") span is injected
              -- into the Kafka headers at publish time (KafkaPublisher), the single
              -- canonical source of the outgoing traceparent. Storing one here too
              -- would emit a duplicate header the consumer's first-match lookup could
              -- pick over the live one.
              traceContext = Nothing
            , attributes = Nothing
            }
     in Just IncidentIntegrationOutboxEvent {outboxId = outboxIdForMessage publicMessage.messageId, event = publicEvent}
  _ -> Nothing
```

The public message and outbox IDs are stable, and source-event linkage is retained. Stored
`traceContext` is deliberately `Nothing`: the publisher injects the live producer span into Kafka
headers, avoiding a duplicate stored header that could override it. The payload's legacy
`traceParent` field is not the transport-parent authority.

## Enqueue the recorded event

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Store.hs`
(artifact-level URI pending):

```haskell
enqueueTransferNeedOutboxForTriage :: IncidentCommandStore -> TriageRecordId -> IO (Either IncidentOutboxEnqueueFailure IncidentOutboxEnqueueSuccess)
enqueueTransferNeedOutboxForTriage store triageRecordId = do
  sourceResult <- readLatestTransferNeed store triageRecordId
  case sourceResult of
    Left storeError -> pure (Left (IncidentOutboxStoreFailed storeError))
    Right Nothing -> pure (Left (IncidentOutboxSourceEventMissing triageRecordId))
    Right (Just (recorded, event)) ->
      case triageEventToOutboxEvent recorded event of
        Nothing -> pure (Left (IncidentOutboxSourceEventMissing triageRecordId))
        Just outboxEvent -> do
          result <-
            runIncidentCommandStore store $
              runTransaction $
                enqueueIntegrationEventTx outboxEvent.outboxId outboxEvent.event
          pure $
            case result of
              Left storeError -> Left (IncidentOutboxStoreFailed storeError)
              Right () -> Right (toIncidentOutboxEnqueueSuccess outboxEvent)
```

A missing source event is reported explicitly. The `runTransaction` encloses the enqueue after
the source lookup, so the code does not claim a distributed or append-plus-publish transaction.
The worker's `outbox enqueue-transfer-need` command drives this path.

## Publish after claim

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Integration/KafkaPublisher.hs`
(artifact-level URI pending):

```haskell
publishOutboxRowToKafka :: KafkaPublishConfig -> OutboxRow -> IO PublishOutcome
publishOutboxRowToKafka config row = do
  let record = KeiroKafka.outboxRowToKafkaRecord row
  headers <- liveTraceHeaders record.headers
  result <- publishKafkaProducerRecord config record headers
  pure (kafkaPublishResultToOutcome (first (Text.pack . show) result))
```

Keiro claims the batch, the publisher replaces trace headers from the live context and waits for
Kafka's delivery result, then the outbox records success or retryable failure. A crash between
broker acknowledgement and durable marking may redeliver the message. Hospital publishes response
and capacity-snapshot messages through the symmetric path.

This app is pinned to Keiro 0.3 and does not yet demonstrate the newer terminal-rejection API
in the current [outbox reference](/docs/keiro/reference/outbox).

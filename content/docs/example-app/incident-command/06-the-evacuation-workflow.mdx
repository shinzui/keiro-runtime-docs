title: "06 — The evacuation workflow"
description: "A durable workflow with named steps that parks on an awakeable awaiting Hospital Capacity's acknowledgement, then resumes."
---

The evacuation workflow is a journaled procedure with named steps and a capacity acknowledgement
wait. Generated WorkflowFacts pin its topology; hand-owned functions implement each step.

## Steps and suspension

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/EvacuationWorkflow.hs`
(artifact-level URI pending):

```haskell
evacuationWorkflow
  :: (Workflow :> es, Store :> es, IOE :> es)
  => EvacuationWorkflowInput
  -> Eff es EvacuationWorkflowSummary
evacuationWorkflow input = do
  commandPost <- step (StepName "establish-command-post") (establishCommandPost input)
  transport <- step (StepName "request-transport") (requestTransport input)
  notification <- step (StepName "notify-hospital-capacity") (notifyHospitalCapacity input)
  (_awakeableId, awaitCapacity) <- awakeableNamed (StepName "hospital-capacity-acknowledgement")
  acknowledgement <- awaitCapacity
  step (StepName "mark-evacuation-ready") (markEvacuationReady input commandPost transport notification acknowledgement)
```

Completed steps replay from their stored results. The named awakeable parks the procedure until a
hospital acknowledgement is available, then `mark-evacuation-ready` records the final result.
These local step bodies are example actions, not an external transport transaction.

## Resolve the stored owner

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/incident-command/src/IncidentCommand/Store.hs`
(artifact-level URI pending):

```haskell
signalEvacuationCapacityAcknowledgementWithTelemetry :: ServiceTracer -> IncidentCommandStore -> IncidentId -> HospitalCapacityAcknowledgement -> IO (Either StoreError Bool)
signalEvacuationCapacityAcknowledgementWithTelemetry tracer store incidentId acknowledgement =
  withApplicationSpan
    tracer
    "incident-command.workflow signal hospital-capacity"
    ( baseAttributes
        <> [ ("emergency.incident.id", showText incidentId)
           , ("emergency.acknowledgement.id", acknowledgement.acknowledgementId)
           ]
    ) $
  runIncidentCommandStore store $
    findPendingEvacuationAwakeable incidentId >>= \case
      Nothing -> pure False
      Just awakeableId -> signalAwakeable awakeableId acknowledgement
```

The signalling path looks up the pending awakeable owned by the workflow, then signals the stored
opaque ID. It returns `False` when none is pending. Although a historical deterministic-ID helper
still exists in the workflow module, this runtime path does not reconstruct an ID from names.
The next workflow run replays the completed prefix and resumes the wait.

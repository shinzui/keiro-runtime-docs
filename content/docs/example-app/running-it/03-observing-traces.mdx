After a traced scenario, inspect both service operations and their Kafka parent-child spans.
The application's source runbook is `mori://shinzui/keiro-runtime-jitsurei/docs/observability`.
PGMQ one-shot operations provide separate evidence; they are not promised to join one end-to-end trace.

## Find the services

The compose Jaeger query endpoint uses IPv6 loopback:

```console
curl -g -fsS 'http://[::1]:16686/api/services'
```

Expect `incident-command` and `hospital-capacity`. Search for
`incident-command.cli scenario mass-casualty durable`, `send emergency.incident.events`,
`emergency.incident.events process`, and the corresponding Hospital producer/Incident consumer.
Inspect queue operations such as `receive hospital_capacity_reservation_work` separately.

## Verify the evidence

```console
just verify-traces
nix develop --command just verify-example
```

The default `verify-example` gate checks docs, dependency/spec drift, embedded plans, builds,
and non-live tests. It does not silently run destructive live resets. For the complete live
scenario/poison/DLQ/trace gate, start infrastructure and explicitly select:

```console
SEIHOU_RUN_LIVE_SCENARIOS=true nix develop --command just verify-example
```

That gate resets the named local databases/topics, runs all scenarios, creates uniquely traced
malformed Kafka records and malformed reservation work, verifies durable poison/DLQ rows, and
checks Jaeger. A persisted Kafka poison message ends with `ack_ok`/OK because retention succeeded.

Override the query endpoint with `JAEGER_URL` if your Jaeger is elsewhere. Collector export is
separate: the generic `http://127.0.0.1:4318` endpoint is a base URL; a
`SEIHOU_OTLP_TRACES_ENDPOINT` override must be a full URL ending in `/v1/traces`.

Keiro metrics are also available, but the required evidence here is the checked trace set and
schema-qualified durable rows. See [trace continuity](/docs/example-app/cross-service/04-telemetry-and-trace-continuity)
for the exact proof boundary.

These commands target `mori://shinzui/keiro-runtime-jitsurei` at `e3c800e`. Resolve the app
with `mori registry show shinzui/keiro-runtime-jitsurei --full`, then run commands from its root.
The recipes are in project-relative `justfile` and `process-compose.yaml` (artifact-level URIs pending).

## Enter the shell and start dependencies

```console
nix develop
just dev-up
```

The compose stack starts Incident PostgreSQL on `55431`, Hospital PostgreSQL on `55432`, and
Jaeger. Its Redpanda process **checks** an existing shared broker at `127.0.0.1:9092`; it no longer
creates or shuts down a broker. On the configured host, `redpanda-up` starts that shared service;
if needed, start Apple Container first with `container system start`. Other hosts must supply a
reachable broker. The shared console is `http://redpanda.localhost`, not the retired `18080` port.

Compose creates the named dev databases and runs each service's migration command. `just dev-down`
stops the app-managed processes and leaves the shared broker running.

## Inspect and apply owned plans

```console
cd services/incident-command
just migration-plan
just migration-status
just migration-up
just migration-verify
just migration-check
```

Repeat in `services/hospital-capacity`. Incident composes `kiroku`, `keiro`, `incident-command`;
Hospital composes `kiroku`, `keiro`, `pgmq`, `hospital-capacity`. Root `just migrate-all` delegates
to both plans. Framework schemas belong to their components; application migrations own only
`incident_command` or `hospital_capacity` data. There is no TypeID SQL bootstrap: IDs are parsed
and rendered through `mmzk-typeid` and stored as canonical text.

The app's supported cutover from the retired bootstrap is fresh **local** database recreation.
`just reset-db --confirm` within a service drops its fixed development database. The scenario
`--reset` also recreates both example Kafka topics; use it only when that data may be discarded.

## Build and check

```console
just kafka-topics
just build-all
just test-all
just dsl-check
just contract-compatibility
just scenario smoke
```

Hospital's `reservation-work setup` reconciles its named work/DLQ queues after the PGMQ base
component exists. The scenario runs that step in order.

Hospital Capacity composes aggregate commands, surge orchestration, reservation workflows,
integration inbox/outbox, and PGMQ jobs behind one process-level store resource.

## Open once, interpret repeatedly

From `mori://shinzui/keiro-runtime-jitsurei`, project-relative path `services/hospital-capacity/src/HospitalCapacity/Store.hs`
(artifact-level URI pending):

```haskell
newtype HospitalCapacityStore = HospitalCapacityStore
  (forall a. Eff '[Store, Error StoreError, KirokuStoreResource, IOE] a -> IO (Either StoreError a))

withHospitalCapacityStore :: (HospitalCapacityStore -> IO a) -> IO a
withHospitalCapacityStore action = do
  connString <- connectionStringFromEnvironment
  runEff $
    withKirokuStore (hospitalCapacityConnectionSettings connString) $
      withEffToIO (ConcUnlift Persistent Unlimited) $ \unlift -> do
        let store = HospitalCapacityStore (unlift . runErrorNoCallStack . runStoreResource)
        registration <- runHospitalCapacityStore store registerHospitalCapacityReadModels
        case registration of
          Left storeError -> fail ("failed to register Hospital Capacity read models: " <> show storeError)
          Right () -> action store
```

Read-model registration occurs before the caller receives the runner. The service keeps its
application tables separate from Kiroku, Keiro, and PGMQ schemas. Do not copy framework DDL into
application migrations or create a new pool for each command.

## Executables and migration order

The service ships CLI, worker, and migration executables. The embedded plan orders components as
`kiroku`, `keiro`, `pgmq`, `hospital-capacity`. Apply that plan, then run the worker's
`reservation-work setup` to reconcile named queues. The supported raw-bootstrap cutover is a
fresh local database recreation; it is not a data-preserving import procedure.

The CLI's durable regional-surge scenario demonstrates the process and workflow paths. Workers
consume Incident Kafka messages, publish the outbox, run surge timers, and process reservation
jobs. Kafka continuous mode uses Shibuya `runApp` and graceful stop; reservation work is one-shot.

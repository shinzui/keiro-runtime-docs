## `MermaidOptions` and its two named policies

```haskell
data MermaidOptions = MermaidOptions
    { guardMode :: MermaidGuardMode
    , updateMode :: MermaidUpdateMode
    , labelLayout :: MermaidLabelLayout
    , maxInlineWrittenSlots :: Maybe Int
    , maxInlineGuardWidth :: Maybe Int
    , outputLayout :: MermaidOutputLayout
    }

defaultMermaidOptions :: MermaidOptions
defaultMermaidOptions =
    MermaidOptions
        { guardMode = MermaidGuardPretty
        , updateMode = MermaidUpdatePretty
        , labelLayout = MermaidLabelMultiline
        , maxInlineWrittenSlots = Nothing
        , maxInlineGuardWidth = Nothing
        , outputLayout = MermaidOutputSemicolon
        }

topologyMermaidOptions :: MermaidOptions
topologyMermaidOptions =
    MermaidOptions
        { guardMode = MermaidGuardHidden
        , updateMode = MermaidUpdateHidden
        , labelLayout = MermaidLabelInline
        , maxInlineWrittenSlots = Nothing
        , maxInlineGuardWidth = Nothing
        , outputLayout = MermaidOutputSemicolon
        }
```

Note what the two records tell you by being written out in full: the three truncation and layout
knobs are *shared*, and the only difference between "readable" and "topology" is the first three
fields. `topologyMermaidOptions` exists as a named value rather than an implicit fallback precisely
so that discarding business semantics is legible at the call site.

## The two segment chokepoints

`renderGuardSegment` and `renderUpdateSegment` are the **only** two places in the module that turn a
guard or an update into a string. Both dispatch on their mode field alone — there is no second
spelling to reconcile — and both escape their text before returning it:

```haskell
renderGuardSegment :: MermaidOptions -> HsPred rs ci -> Maybe Text
renderGuardSegment opts g =
    escapeSemanticText <$> case guardMode opts of
        MermaidGuardHidden -> Nothing
        MermaidGuardStructuralSummary -> Just (guardSummary g)
        MermaidGuardPretty -> Just (prettyPred g)

renderUpdateSegment :: MermaidOptions -> Update rs w ci -> Maybe Text
renderUpdateSegment opts u =
    case updateMode opts of
        MermaidUpdateHidden -> Nothing
        MermaidUpdateWrittenSlots ->
            case truncateSlots
                (maxInlineWrittenSlots opts)
                (Prelude.map escapeSemanticText (writtenSlots u)) of
                [] -> Nothing
                xs -> Just (T.pack "w: " <> T.intercalate (T.pack "; ") xs)
        MermaidUpdatePretty ->
            Just (T.pack "u: " <> escapeSemanticText (prettyUpdate u))
```

Two details worth reading off the update side. `MermaidUpdateWrittenSlots` returns `Nothing` for an
edge that writes nothing — an empty `w:` would be noise — whereas `MermaidUpdatePretty` always
returns a segment, because `prettyUpdate` renders `UKeep` as the informative `(keep)` rather than as
nothing. And the segment prefix differs by mode: `w:` for slot names, `u:` for the complete update.
Escaping is applied per slot name in one branch and to the whole rendered update in the other, so it
happens exactly once either way.

The three guard modes produce three flavours of guard text:

- **`MermaidGuardStructuralSummary`** uses `guardSummary` — the constructor-tag walk, e.g.
  `PAnd PInCtor PEq`. It deliberately does **not** print operand terms, because those can hold opaque
  functions and unprintable input-constructor match/build closures:

  ```haskell
  guardSummary :: HsPred rs ci -> Text
  guardSummary = T.intercalate (T.pack " ") . go
    where
      go (PAnd a b) = T.pack "PAnd" : go a ++ go b
      go (PEq _ _) = [T.pack "PEq"]
      go (PInCtor _) = [T.pack "PInCtor"]
      go (PCmp c _ _) = [T.pack "PCmp " <> T.pack (show c)]
      -- … PTop / PBot / POr / PNot likewise
  ```

- **`MermaidGuardPretty`** uses `prettyPred` from chapter
  [01](/docs/keiki/walkthrough/rendering-and-codecs/01-pretty-printer) — domain-readable text.
- **`MermaidGuardHidden`** produces `Nothing`, no segment at all.

Side by side on the same `ConfirmAccount` edge — structural:

```text
RequiresConfirmation --> Confirmed : ConfirmAccount / AccountConfirmed [w: confirmedAt; g: PAnd PInCtor PEq]
```

Pretty, under the default multiline layout — real names, complete assignments, `&amp;&amp;` because
the escaping pass has already run:

```text
RequiresConfirmation --> Confirmed : ConfirmAccount / AccountConfirmed<br/>u: confirmedAt := ConfirmAccount.at, (keep)<br/>g: (ConfirmAccount &amp;&amp; ConfirmAccount.confirmCode == confirmCode)
```

## `escapeSemanticText`: neutralising data before layout

*(keiki 0.8.0.0.)* Once guards and updates carry domain text, a value can contain characters the
Mermaid pipeline treats as structure. The documentation backend decodes XML entities **before** it
parses Mermaid, and it turns both `<br>` spellings *and* a literal `\n` into line breaks — so entity
encoding alone cannot isolate semantic text. A guard containing `<br>` would otherwise become a real
line break.

`escapeSemanticText` runs **exactly once**, inside the two chokepoints, before any renderer-owned
`<br/>` is inserted. It maps into a visible, non-structural alphabet on three tiers:

```haskell
escapeSemanticText :: Text -> Text
escapeSemanticText =
    T.intercalate (T.pack "&lt;lit&gt;")
        . Prelude.map (T.concatMap escapeChar)
        . T.splitOn (T.pack "<lit>")
  where
    escapeChar '\r' = T.pack "\x240D"   -- ␍ control picture
    escapeChar '\n' = T.pack "\x240A"   -- ␊ control picture
    escapeChar '\\' = T.pack "\xFF3C"   -- ＼ full-width
    escapeChar '\'' = T.pack "&apos;"
    escapeChar '"' = T.pack "&quot;"
    escapeChar '&' = T.pack "&amp;"
    escapeChar '<' = T.pack "\xFF1C"    -- ＜ full-width
    escapeChar '>' = T.pack "\xFF1E"    -- ＞ full-width
    escapeChar '|' = T.pack "&#124;"
    escapeChar '{' = T.pack "&#123;"
    escapeChar '}' = T.pack "&#125;"
    escapeChar c = T.singleton c
```

The tiering is the interesting part. **Safe punctuation** (`&`, quotes, `|`, braces) becomes an XML
entity, because the backend can decode those back to themselves harmlessly. **Parser-active**
characters (angle brackets, backslash) become *full-width* forms instead — an entity would be decoded
back into an active character, so the value has to change shape to stay inert. **Raw line endings**
become control pictures, so a newline inside a guard is visible rather than structural.

The `T.splitOn`/`T.intercalate` wrapper around the whole thing is a carve-out for one known token:
the opaque-literal marker `<lit>` is entity-encoded to `&lt;lit&gt;` rather than full-width-escaped,
because it cannot be mistaken for a break tag and should stay visually exact. That is the marker
[`opaqueLit`](/docs/keiki/reference/core#readable-and-opaque-literals) produces.

<Callout type="info">
A full-width character in a rendered diagram is a **signal, not a bug**: it means semantic input was
neutralised at the Mermaid boundary instead of being silently interpreted as structure. The suite
pins this end to end — source line and transition counts, heuristic warnings, recovered SVG text, and
this documentation site's checked-in `beautiful-mermaid` backend.
</Callout>

## `edgeLabelWith`: assembling the label

`edgeLabelWith` owns segment *layout*, *truncation*, and the output rendering — the segment *text*
comes from the two chokepoints:

```haskell
edgeLabelWith opts e@Edge{update = u, guard = g} =
    let base = edgeLabelWithLayout (outputLayout opts) e
        uPart = case renderUpdateSegment opts u of
            Just t -> [t]
            Nothing -> []
        gPart = case renderGuardSegment opts g of
            Just t -> [T.pack "g: " <> truncateGuard (maxInlineGuardWidth opts) t]
            Nothing -> []
        parts = uPart ++ gPart
     in case labelLayout opts of
            MermaidLabelInline ->
                if null parts
                    then base
                    else base <> T.pack " [" <> T.intercalate (T.pack "; ") parts <> T.pack "]"
            MermaidLabelMultiline ->
                T.intercalate (T.pack "<br/>") (base : parts)
```

A few load-bearing details:

- The whole edge `e` is reused for the base label while `u` and `g` are bound by the pattern — that
  is what keeps the existential write-set in `update` from escaping, since the record selector cannot
  be used as a function for it.
- The update segment arrives **already prefixed** (`u: ` or `w: `), because the prefix depends on the
  mode; the guard prefix `g: ` is added here instead, since it is the same in every mode.
- Truncation is asymmetric by design: written slots are truncated *inside* `renderUpdateSegment`
  (before the prefix), the guard *here* (after the chokepoint returns).
- Under the default `MermaidLabelMultiline`, base, `u:`, and `g:` land on separate `<br/>`-joined
  lines. Note the 2-event output keeps its own `;` separator — that is the *base* segment's
  length-based output rendering, not a label segment.
- Under `MermaidLabelInline` you get the single-line bracketed suffix
  `… [w: registeredAt; confirmCode; email; g: PInCtor]`.

Truncation is two small helpers. `truncateSlots` keeps the first `k` and replaces the rest with one
`+{n-k} more` token; `truncateGuard` takes `w` characters and appends `…` (U+2026):

```haskell
truncateSlots (Just k) xs
    | length xs > k =
        take k xs ++ [T.pack ("+" <> show (length xs - k) <> " more")]
    | otherwise = xs

truncateGuard (Just w) t
    | T.length t > w = T.take w t <> T.pack "\x2026"
    | otherwise = t
```

`MermaidSpec` pins both. The only `userReg` edge writing more than two slots truncates to
`[w: registeredAt; confirmCode; +1 more]`; and `ConfirmAccount`'s `PAnd PInCtor PEq` (length 16)
truncated at 10 becomes `[g: PAnd PInCt…]`.

## The output-layout knob

`outputLayout` feeds straight into `edgeLabelWithLayout` (chapter
[02](/docs/keiki/walkthrough/rendering-and-codecs/02-mermaid-core)). The `multiEvt` fixture — a 3-event
edge and a 2-event edge — pins all three layouts:

<Tabs items={["Semicolon (default)", "Multiline", "Counted"]}>
<Tab value="Semicolon (default)">
```text
MS0 --> MS1 : Go / A<br/>B<br/>C
MS1 --> MS2 : Go / A; B
```
Length-based: `;` for exactly two events, `<br/>` for three or more.
</Tab>
<Tab value="Multiline">
```text
MS0 --> MS1 : Go / A<br/>B<br/>C
MS1 --> MS2 : Go / A<br/>B
```
Always one event per line, so the 2-event edge becomes `A<br/>B`.
</Tab>
<Tab value="Counted">
```text
MS0 --> MS1 : Go / 3 events
MS1 --> MS2 : Go / 2 events
```
Two or more events collapse to an `N events` count.
</Tab>
</Tabs>

## `toMermaidWithLabels`: stable ids, friendly display labels

The default path derives both the Mermaid node id and the visible label from `Show`. `toMermaidWithLabels`
splits them via a `MermaidStateLabels` record so the id can stay a legal Mermaid identifier while the
display label carries spaces:

```haskell
data MermaidStateLabels s = MermaidStateLabels
    { stateId :: s -> Text
    , stateDisplayLabel :: s -> Text
    }

toMermaidWithLabels ::
    (Bounded s, Enum s) =>
    MermaidOptions ->
    MermaidStateLabels s ->
    SymTransducer (HsPred rs ci) rs s ci co ->
    Text
toMermaidWithLabels opts lbls =
    renderTopologyWith opts (stateId lbls) (stateDisplayLabel lbls)
```

This is the same `renderTopologyWith` from chapter
[02](/docs/keiki/walkthrough/rendering-and-codecs/02-mermaid-core), now with `idOf = stateId` and
`displayOf = stateDisplayLabel`. The declaration lines that the walk emits are the payoff:

```haskell
declLines =
    [ ind <> T.pack "state \"" <> displayOf s <> T.pack "\" as " <> idOf s
    | s <- vertices
    , displayOf s /= idOf s
    ]
```

A `state "<display>" as <id>` line appears **only** when the display differs from the id. When they are
equal — the `Show`-based default — `declLines` is empty, so feeding identical functions reproduces
`toMermaidWith` byte-for-byte (a fact `MermaidSpec` pins directly). With friendly labels for the two
spaced vertices, the golden gains exactly two declarations and the transitions below are unchanged
(shown here under `topologyMermaidOptions`, so the `u:`/`g:` segments do not obscure the point):

```text
stateDiagram-v2
    state "Potential Customer" as PotentialCustomer
    state "Requires Confirmation" as RequiresConfirmation
    [*] --> PotentialCustomer
    PotentialCustomer --> RequiresConfirmation : StartRegistration / RegistrationStarted; ConfirmationEmailSent
    …
```

### `duplicateStateIds`: the AST-level collision check

Because the caller supplies `stateId`, two vertices could map to the same id and silently merge in the
diagram. `duplicateStateIds` is the pre-flight check that catches it on the AST, before rendering:

```haskell
duplicateStateIds lbls _t =
    let ids = Prelude.map (stateId lbls) [minBound .. maxBound]
     in [i | i <- nubInOrder ids, count i ids > (1 :: Int)]
```

<Callout type="warn">
Rendering itself stays **total** — it never throws on a collision. `duplicateStateIds` is the check you
run *before* trusting a labelled diagram. It returns the colliding ids in first-occurrence order; an
empty result means every vertex maps to a unique id. `MermaidSpec` pins both directions: empty for the
good labels, `["X"]` for a record that collapses every vertex onto `X`. The header notes the sibling
text-level validators in `Keiki.Render` key off the same id token, so the AST check and the text check
agree on what an "id" is by construction.
</Callout>

## The property, formally

Fix a transducer with state set `S`, register file type `RegFile rs`, and command type `ci`.
At a vertex `s` the outgoing edges carry guards `g₁, …, gₙ`, each a predicate over the pair
`(RegFile rs, ci)`. Write `⟦g⟧` for the set of inputs the guard accepts:

```text
⟦g⟧ = { (regs, c) : models g (regs, c) = True }
```

The transducer is **single-valued at `s`** when those accepting sets are pairwise disjoint:

```text
for all i ≠ j :  ⟦gᵢ⟧ ∩ ⟦gⱼ⟧ = ∅
```

and **single-valued** when this holds at every vertex `s ∈ S`. Disjointness is what makes
`step` deterministic — at most one edge ever accepts a given input — and it is the keiki
analogue of the edge guards forming an *effective Boolean algebra*: a `conj` of two distinct
guards must be `bot`. The check `isSingleValuedSym` decides exactly this, by testing
`isBot (gᵢ conj gⱼ)` for each pair (the
[per-pair-per-vertex decomposition](/docs/keiki/explanation/the-symbolic-ci-gate)).

Everything below is about the gap between `⟦gᵢ⟧ ∩ ⟦gⱼ⟧ = ∅` (the truth) and what a given
`isBot` implementation actually decides (the approximation).

## Soundness vs precision: two directions of error

A decision procedure for an undecidable-in-general property can err in one of two directions.
keiki ships two `isBot` implementations, and they err in *opposite* directions:

<TypeTable
  type={{
    "Symbolic isBot (SymPred / z3)": {
      type: "under-approximates",
      description: "Treats fewer pairs as empty than truly are. No false 'single-valued' verdict on a real overlap (sound); may report a spurious overlap (false alarm). This is the gate you put in CI.",
    },
    "Syntactic isBot (raw HsPred)": {
      type: "over-approximates",
      description: "Proves emptiness only by inspecting the predicate AST. Catches only structurally-evident overlaps; cheap, pure, no solver. Misses overlaps it cannot see syntactically.",
    },
  }}
/>

The distinction that matters for trust is **soundness**: never claim single-valued when the
machine is not. The symbolic check is sound. `symIsBot` answers `True` (empty) only when z3
returns `unsat` for `gᵢ AND gⱼ`; for any other outcome — `sat`, or the conservative fallbacks
below — it answers `False`. So the worst the symbolic gate does is fail when the guards really
*are* mutually exclusive: a false alarm, never a false sense of safety.

```haskell
-- symIsBot is True only when no model exists; every other case is False.
symIsBot p = unsafePerformIO $ do
    res <- SBV.sat (mkSymEnv >>= \env -> translatePred env p)
    pure (satResultIsProvablyUnsat res)
```

The two checks are complementary, not redundant. The syntactic check
(`validateTransducer defaultValidationOptions`, used by the v1 `HsPred` carrier) runs in
microseconds with no external process and catches the obvious structural overlaps. The symbolic
check (`isSingleValuedSym . withSymPred`) is the exact, solver-backed answer for the
register-value-dependent and arithmetic overlaps the syntactic one cannot prove.

## Caveat 1 — curated types and the opaque escape

The solver only sees what the SBV translation can express, and the translation is built over a
**curated registry** of types. `discoverSym` recognizes exactly: `Bool`, `Int`, `Integer`,
`Natural`, `Text`, `UTCTime`, and the fixed-width integers `Word8`/`Word16`/`Word32`/`Word64`/
`Int32`/`Int64`. A guard over any of these translates *precisely* — `PEq` becomes `(.==)`,
`PCmp` becomes a real `.<`/`.<=`/`.>`/`.>=` comparison.

<Callout type="info">
  **Being in the registry is not the same as being exactly representable.** *(keiki 0.7.0.0.)* Two
  of those types are faithful for equality and ordering but are **not** whole-carrier isomorphisms:
  `UTCTime` is encoded as picoseconds through POSIX time, which clamps leap-second day times, and
  `Text` exceeds SMT-LIB's U+2FFFF string ceiling. That distinction only matters when a projection
  wants to declare its exact image — `symbolicWholeCarrierExact` is the query, and it holds for
  `Bool`, `Integer`, `Natural`, and the curated fixed-width integers only.
</Callout>

Outside that set, two escape hatches appear in the term language: `TApp1` and `TApp2`, which
wrap opaque Haskell functions. They have no symbolic meaning, so `translateTermSym` maps each to
a **fresh free variable**:

```haskell
translateTermSym _env (TApp1 _f _t)   = SBV.free "app1"
translateTermSym _env (TApp2 _f _a _b) = SBV.free "app2"
```

A `PEq` over a type that misses `discoverSym` is treated the same way — `goEq` emits a fresh
`SBV.free "neq"`. This is normally fine for the *gate*: a fresh variable makes the solver assume
the guards *could* overlap, so the worst outcome is a false alarm (the sound direction).

But there is one subtlety worth stating plainly: because an opaque term becomes a fresh,
unconstrained variable, a pair of guards that branch *only* on the same opaque condition can
look mutually exclusive to the solver when they are not — the solver is free to pick different
values for two occurrences of an opaque application (opaque functions have no `Eq`, so the two
occurrences never share a variable). An opaque guard is therefore **silently under-verified**:
its real single-valuedness was not actually proved.

keiki does not leave this implicit. The `warnOpaqueGuards` audit (opt-in via
`ValidationOptions`) walks the predicate AST and emits an `OpaqueGuard` warning for every edge
whose guard contains an opaque `TApp` term — signposting exactly the edges whose verification you
should not trust:

```haskell
-- Turn on the opaque-guard audit in your validation step:
validateTransducer defaultValidationOptions { warnOpaqueGuards = True } yourAggregate
```

If a type has a natural symbolic representation, the honest fix is to extend the curated
registry to cover it rather than reaching for an opaque `TApp`. See
[Registers vs state](/docs/keiki/explanation/registers-vs-state) for what belongs in a slot.

### Field projections: precision without symbolizing the owner

*(keiki 0.4.0.0.)* There is a third option between "the whole type is in the registry" and "reach for
an opaque `TApp`", and it is the interesting one. A [field
projection](/docs/keiki/reference/core#field-projections) reads **one scalar out of a
consumer-owned value**: only the *result* type needs to be in the curated registry, while the owner
type stays entirely unknown to keiki.

`TFieldProj` translates to a memoized free variable keyed on the typed path (see
[below](#memoization--one-variable-per-slot)), which is a genuine gain over `TApp`: two reads of the
same path *do* share a variable, so `regProj w #owner .== regProj w #owner` is valid rather than
merely satisfiable. And unlike an opaque `TApp`, keiki knows when it is under-verifying and says so
— a result type outside the equality registry is an unconditional `ProjectionResultUnsupported`
finding rather than a silent fallback to an opaque Boolean.

<Callout type="warn">
  What you do **not** get from a plain `fieldWitness` is invertibility. The agreement is deliberately
  **one-way**: every concrete owner can bind a matching symbolic projection value, but an arbitrary
  symbolic model over projection scalars need not correspond to a *constructible* owner. `symSatExt`
  does not reconstruct consumer-owned values from free projection scalars.

  So a satisfying model over projections is evidence about the **scalars**, not a witness command you
  can replay. This is why projections are permitted in guards and rejected in updates and outputs: a
  guard only needs the solver to reason about the scalar, whereas an update or an output would need
  the owner back.
</Callout>

<Callout type="warn">
  **Corrected in keiki 0.7.0.0 — path identity is not proof strength.** Keiki used to treat a
  one-way projection as an *exact* translation whenever its result carrier happened to be
  solver-supported, which quietly overstated what had been proved. It no longer does: a predicate
  containing a `TFieldProj` over a released `fieldWitness` is `UnverifiedOpaque` to
  `verifyPredicate`. Nothing about the gate regressed — the shared-variable path identity above still
  holds, and `symIsBot` can still prove such a predicate empty, since definite unsatisfiability over
  the larger free-scalar domain also proves the smaller concrete domain empty.
</Callout>

### Exact projections: buying the other direction

*(keiki 0.7.0.0.)* An [`exactFieldWitness`](/docs/keiki/reference/core#exact-projections) is the
opt-in that *does* give invertibility. The projection tag declares a
[`ProjectionDomain`](/docs/keiki/reference/projection-domain) — the exact image of its getter — plus
a canonical inverse, and keiki constrains the solver variable to that domain and checks every
satisfying model for domain membership, inverse success, and getter round trip before exposing it.

The price is that **soundness becomes conditional**, and it is worth being precise about which half.
Keiki's model checks catch an inverse that rejects an admitted key or returns a non-round-tripping
owner. They cannot catch a domain that *omits* a key some real owner produces, because that
under-declaration manufactures a false UNSAT before any satisfying model exists — there is nothing
for a check to look at. So `VerifiedUnsatisfiable`, `symIsBot`, a determinism disjointness blessing,
and a dead-edge proof over exact-projection predicates are sound **only conditional on the
declaration laws**, and a generator emitting exact witnesses must emit owner-side conformance tests
with them. Predicates using only the one-way `fieldWitness` keep the unconditional over-approximation
guarantee.

Per-projection exactness is also not predicate-global exactness. One base path may use a single exact
tag repeatedly, but two distinct tags over one owner — or a direct owner read combined with any
projection — stay conservative, since independent solver variables do not encode their joint owner
relation.

## Caveat 2 — the Unknown/timeout rule

z3 can return `Unknown`, `ProofError`, or another non-definitive result. Keiki collapses every one
into the sound direction through `satResultIsProvablyUnsat`: only SBV's `Unsatisfiable` constructor
returns `True`. An unknown, timeout, proof failure, satisfiable, or delta-satisfiable result makes
`isBot` answer `False`, so the gate assumes possible overlap and fails closed. You may see a
spurious failure on a pathological guard; solver uncertainty never certifies a pair as disjoint.

## Caveat 3 — use explicit widths when overflow matters

Keiki 0.2 models `Word8`/`Word16`/`Word32`/`Word64` and `Int32`/`Int64` with exact fixed-width SBV
values. Their symbolic arithmetic therefore preserves modular wraparound. `UTCTime` also keeps its
native picosecond resolution.

```haskell
instance Sym Word64 where
    type SymRep Word64 = Word64
```

`Natural` is modelled as an unbounded SMT integer **constrained non-negative** at every allocation
(`constrainSymDomain`), and its subtraction is total monus in both interpreters — `a - b = max 0 (a - b)`
— because ordinary SMT integer subtraction would return a negative value no `Natural` denotes.

Platform-sized `Int` remains modeled as unbounded `Integer`, because its width varies by target.
If a proof depends on `Int` overflow, use an explicitly sized type instead. The OrderCart money
guards use `Word64`, so both ordinary comparisons and wraparound-sensitive formulas now match the
concrete runtime domain.

## Memoization — one variable per slot

A precise overlap answer needs more than per-type translation; it needs two reads of the *same*
slot to be the *same* value in the solver's eyes. The translation environment (`SymEnv`) carries
a memo cache keyed by a **structural** `SymVarKey`: `TReg` keys on `RegVar <slot>`,
`TInpCtorField` on `InpVar <ctor> <field>`, and `TFieldProj` on a `ProjectionVar` carrying the base
path plus the projection tag's, owner's, and result's `TypeRep`s. The first read of a key allocates
one `SBV.free` variable and caches it; every later read of the same key returns the *cached*
variable:

```haskell
translateTermSym env (TReg ix) =
    memoFree env (RegVar (indexName ix))   -- same key → same SBV variable
```

This is why a guard like `proj #x .== proj #x` is **valid** in every model, not merely
satisfiable: both reads of `#x` resolve to one variable, so `x /= x` is genuinely `unsat`. The
cache is scoped to a single `translatePred` walk, so variables are shared *within* one query and
never leak across independent queries. The opaque `TApp1`/`TApp2` escape hatches are deliberately
*not* cached — their functions have no `Eq`, so two applications cannot be recognized as equal,
which is precisely the under-verification Caveat 1 signposts.

<Callout type="info">
  Keying on the `TypeRep` rather than on a rendered string is what makes projection sharing
  trustworthy: caller-controlled diagnostic strings (`FieldName`, `fieldShapeId`,
  `fieldProjectionPath`) never determine solver identity. The base key also carries the field's
  `indexPosition`, so a hand-built schema with duplicate labels cannot accidentally collapse two
  distinct fields into one variable. The corollary is the rule from the reference: **reuse one
  canonical tag per logical field** — two tags for the same field are sound but the solver treats them
  as independent.
</Callout>

## What a green gate means, exactly

Put the three caveats together and the guarantee is honest and bounded. When
`isSingleValuedSym (withSymPred t)` returns `True`:

<Steps>
  <Step>
    Every pair of **`Live`** outgoing edges at every enumerated vertex was checked, and z3 proved each
    `gᵢ AND gⱼ` `unsat` over the entire (infinite) input space — for the slots and fields the
    guards read through the curated, precisely-translated types. `ReplayOnly` edges are excluded
    because they never compete in forward dispatch; see [edge
    mode](/docs/keiki/reference/core#edge-mode).
  </Step>
  <Step>
    The result is sound: no overlap that the concrete runtime would hit is reported as empty.
    Integer over-approximation, `unknown` results, and the syntactic fallback all err toward
    *failing* the gate, never toward a false pass.
  </Step>
  <Step>
    The one residual gap is opaque guards (Caveat 1). Run the gate together with
    `warnOpaqueGuards` so any edge whose verification was skipped is named, not assumed sound.
  </Step>
</Steps>

That is a far stronger statement than any property test can make, with its boundaries written
down rather than hidden.

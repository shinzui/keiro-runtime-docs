Everything on this page lives in `Keiki.Core`, the pure heart of keiki (継起). It declares the
symbolic-register transducer, the four little languages that author its edges (terms, updates,
predicates, output assembly), the effective-Boolean-algebra plumbing that abstracts the guard
carrier, and the concrete evaluators and run entry points that drive a machine forward or replay it
backward — all with no solver involved.

For the conceptual model behind these shapes, read the
[explanation section](/docs/keiki/explanation): *The SymTransducer* covers the control-graph /
register split and *Registers vs. state* covers why the register file is separate from the vertex
type. This page is the verbatim API surface; the prose there is the "why".

<Callout type="info">
There is **no** `StepResult` type. A successful step is the bare triple `(s, RegFile rs, [co])`:
the next vertex, the updated register file, and the list of emitted output letters (empty for an
ε-edge). `step` wraps it in `Maybe`; `stepEither` wraps it in `Either StepFailure`. Since keiki
0.7.0.0 there is one richer shape: [`stepDetailedEither`](#detailed-forward-success) returns a
`StepSuccess` that also names the edge that fired.
</Callout>

## Slots and the register file

A `Slot` is a label paired with the type of the value stored at that label.

```haskell
type Slot = (Symbol, Type)
```

`RegFile` is a typed heterogeneous tuple indexed by a list of slots. It is a GADT with two
constructors: `RNil` for the empty file and `RCons` to prepend a labelled value.

```haskell
data RegFile (rs :: [Slot]) where
    RNil :: RegFile '[]
    RCons ::
        (KnownSymbol s) =>
        Proxy s -> r -> RegFile rs -> RegFile ('(s, r) ': rs)
```

<Callout type="info">
The slot-value field is intentionally **lazy**. `Keiki.Generics.emptyRegFile` seeds each slot with a
deferred `error "uninit: <slot>"` thunk so that reading an unwritten slot fails loudly with a
targeted message instead of returning a silent bottom. Strictness for *written* slots is enforced on
the write path (`setSlotN`) instead.
</Callout>

`Index` is a type-safe pointer into a `RegFile`: `ZIdx` picks the head slot, `SIdx` skips one slot.

```haskell
data Index (rs :: [Slot]) (r :: Type) where
    ZIdx :: (KnownSymbol s) => Index ('(s, r) ': rs) r
    SIdx :: Index rs r -> Index ('(s', r') ': rs) r
```

`(!)` is the runtime lookup. It has fixity `infixl 9`.

```haskell
(!) :: RegFile rs -> Index rs r -> r

infixl 9 !
```

### Resolving labels to indices

`HasIndex` resolves a label `s` against a slot list `rs` to the `Index` of the value at that slot.
The functional dependency `s rs -> r` ensures a label uniquely determines the slot's type, so an
`OverloadedLabels` `#name` literal type-checks to the right `Index`.

```haskell
class
    HasIndex (s :: Symbol) (rs :: [Slot]) (r :: Type)
        | s rs -> r
    where
    indexOf :: Index rs r
```

There are two `IsLabel` instances that build on `HasIndex`: one producing an `Index rs r` (so `#name`
is a register pointer where an `Index` is expected) and one producing a `Term rs ci ifs r` (so
`#name` is a register-reading term where a `Term` is expected). GHC picks between them by the expected
result type.

## The term language

A `Term` is a pure expression over the register file and the input symbol, yielding a value of type
`r`.

```haskell
data Term (rs :: [Slot]) (ci :: Type) (ifs :: [Slot]) (r :: Type) where
    TLit :: (Show r) => r -> Term rs ci ifs r
    TOpaqueLit :: r -> Term rs ci ifs r
    TReg :: Index rs r -> Term rs ci ifs r
    TInpCtorField :: InCtor ci ifs -> Index ifs r -> Term rs ci ifs r
    TApp1 ::
        (a -> r) ->
        Term rs ci ifs a ->
        Term rs ci ifs r
    TApp2 ::
        (a -> b -> r) ->
        Term rs ci ifs a ->
        Term rs ci ifs b ->
        Term rs ci ifs r
    TArith ::
        (Num r, Typeable r) =>
        NumOp ->
        Term rs ci ifs r ->
        Term rs ci ifs r ->
        Term rs ci ifs r
    TFieldProj ::
        ( FieldProjection projection,
          KnownSymbol (FieldName projection),
          Typeable projection,
          Typeable (FieldOwner projection),
          Typeable (FieldResult projection)
        ) =>
        FieldWitness projection ->
        ProjBase rs ci ifs (FieldOwner projection) ->
        Term rs ci ifs (FieldResult projection)
```

<Callout type="warn">
  **Breaking in keiki 0.8.0.0.** `TLit` now carries a `Show` dictionary, and `Term` gained
  `TOpaqueLit`. Code that matches `Term` exhaustively must handle the new constructor, and a literal
  whose type has no `Show` instance must be built with [`opaqueLit`](#smart-constructors). The two
  constructors have **identical** executable and proof meaning: concrete evaluation, replay
  inversion, pure overlap analysis, symbolic translation, and composition all treat the stored value
  the same way, and no runtime or proof path ever forces `Show`. The only difference is
  presentation — see [readable rendering](#readable-and-opaque-literals).
</Callout>

<Callout type="warn">
  **Breaking in keiki 0.4.0.0.** `Term` gained `TFieldProj`. Code that matches `Term`
  exhaustively must handle it. See [field projections](#field-projections) below.
</Callout>

<Callout type="info">
**The `ifs` parameter** (`:: [Slot]`) is the *input-field schema* the term may project from. It is
pinned by `TInpCtorField` (whose `Index` is into `ifs`) and left free by terms that read no input
field (`TLit`, `TOpaqueLit`, `TReg`). Threading `ifs` through the AST is what lets an `OutFields` — and hence an
`OPack` — guarantee *by construction* that every top-level input projection reads the same
constructor schema as the `OPack`'s `InCtor`, so `solveOutput` can recover a command field with no
`unsafeCoerce`. Terms that never appear in an invertible output position (`Update` right-hand sides,
`HsPred` operands) existentially hide `ifs`, so it never leaks into the `Edge` / `SymTransducer`
surface.
</Callout>

`NumOp` is the single arithmetic tag carried by `TArith`: `OpAdd` and `OpMul` are `+` and `*`.
`OpSub` is ordinary subtraction *except* for `Natural`, where it is **total monus**.

```haskell
data NumOp = OpAdd | OpSub | OpMul
    deriving stock (Eq, Show)
```

Unlike the opaque `TApp1`/`TApp2` escape hatches, `TArith` is read *for real* by the SBV translator,
so a guard over a computed value (a weighted sum, a derived cap) stays visible to the solver.

<Callout type="warn">
  **Breaking semantic fix in keiki 0.6.0.0 — `Natural` subtraction is total monus.**
  `tsub a b` on a `Natural` evaluates to `max 0 (a - b)`, so it is `0` when `b > a`. Concrete
  evaluation never calls the partial `Natural` `(-)` on an underflowing pair, so it cannot throw
  `Underflow`; the symbolic form is `ite (a >= b) (a - b) 0`. Both interpreters therefore agree.
  A model that relied on the old throwing behaviour to signal an invalid state must guard the
  ordering explicitly (`proj #balance .>= lit amount`) instead.
</Callout>

### Readable and opaque literals

*(keiki 0.8.0.0.)* `TLit` retains a `Show` dictionary as **presentation evidence**: renderers derive
a literal's text from the executable value itself, so a caller cannot attach a display label that
disagrees with what the machine computes. `TOpaqueLit` stores the same kind of value with no display
evidence and renders as `<lit>`.

The distinction is presentation only. Neither constructor changes what a term means:

- Concrete `evalTerm`, replay inversion, and the pure overlap validator return the stored value.
- Symbolic translation treats both identically.
- Structural rewrites in `Keiki.Composition` and `Keiki.Profunctor` preserve whichever evidence the
  term already had.
- A [field-projection](#field-projections) fold over a literal owner produces `TOpaqueLit`, because
  the `FieldProjection` interface cannot supply `Show` for the projected result. That is
  presentation loss, **not** symbolic opacity — the folded value is still exactly translated.

<Callout type="warn">
  **Readable rendering discloses `lit` values.** Because `toMermaid` now renders complete guards and
  updates by default, any secret, credential, personal datum, or deliberately redacted value must be
  built with `opaqueLit` — or the whole diagram rendered under
  [`topologyMermaidOptions`](/docs/keiki/reference/render-mermaid), which redacts all guard and
  update semantics. A partial, expensive, or stylised `Show` can change rendering but can never
  change execution or a proof result; `Show` text is not canonical serialization.
</Callout>

### Smart constructors

Author terms with these instead of the raw constructors.

```haskell
lit :: (Show r) => r -> Term rs ci ifs r
opaqueLit :: r -> Term rs ci ifs r
proj :: Index rs r -> Term rs ci ifs r
inpCtor :: InCtor ci ifs -> Index ifs r -> Term rs ci ifs r
```

`lit` is a readable constant; `opaqueLit` is the display-opaque constant for a value with no `Show`
instance or one that must stay redacted; `proj` reads a register; `inpCtor` reads field `ix` of the
input constructor described by `ic` (its result `Term`'s `ifs` is the constructor's field schema, so
an `OutFields` built from these is statically tied to the `OPack`'s `InCtor`).

The arithmetic smart constructors build a `TArith` over `+`/`-`/`*`. The operand type must be `Num`
and `Typeable`. For `Natural`, `tsub` is total monus as described above.

```haskell
tadd
    , tsub
    , tmul ::
        (Num r, Typeable r) =>
        Term rs ci ifs r -> Term rs ci ifs r -> Term rs ci ifs r
```

## Field projections

*(keiki 0.4.0.0.)* A field projection reads **one scalar field out of a consumer-owned value** —
a type keiki knows nothing about and that has no symbolic representation of its own. Only the
projected *result* needs to be in the symbolic registry; the owner does not. That is what lets a
guard be solver-visible over a value the application owns.

```haskell
class FieldProjection projection where
    type FieldName projection :: Symbol
    type FieldOwner projection :: Type
    type FieldResult projection :: Type
    fieldShapeId :: Proxy projection -> String
    projectFieldValue ::
        Proxy projection -> FieldOwner projection -> FieldResult projection
```

One **fresh tag type and one coherent instance per logical field**, reused at every occurrence of
that field. The tag's `Typeable` identity — not `FieldName`, not `fieldShapeId` — is what the
symbolic layer uses to decide variable sharing. Two different tags for the same logical field are
sound but *imprecise*: the solver treats them as independent values.

The contract on an instance:

- `projectFieldValue` must be **total** for every well-formed `FieldOwner`.
- `FieldName` and `fieldShapeId` must **truthfully describe that getter**.

Haskell's own instance coherence supplies one getter per tag, so a dishonest instance can misname a
field but *cannot* make one coherent tag mean two different getters. Keiki checks concrete term
behaviour and hands you `fieldWitnessAgrees`; a binding *generator* (keiro's structural bindings,
for instance) is responsible for proving a generated instance agrees with its schema and codec
provenance.

### The witness

```haskell
type role FieldWitness nominal
data FieldWitness projection   -- abstract; the constructor is not exported

fieldWitness ::
    ( FieldProjection projection,
      KnownSymbol (FieldName projection),
      Typeable projection,
      Typeable (FieldOwner projection),
      Typeable (FieldResult projection)
    ) =>
    FieldWitness projection
```

An abstract nominal token for a coherent instance **and its private symbolic-domain evidence**. The
nominal role stops you swapping the projection tag with `coerce`, and the tag's `TypeRep` supplies
symbolic cache identity independently of any caller-controlled diagnostic string. Since keiki
0.7.0.0 the witness also records whether the projection carries an exact domain — `fieldWitness`
records none, [`exactFieldWitness`](#exact-projections) records one — which is why the constructor
is not exported.

### The base

```haskell
data ProjBase (rs :: [Slot]) (ci :: Type) (ifs :: [Slot]) owner where
    PBReg :: Index rs owner -> ProjBase rs ci ifs owner
    PBInp :: InCtor ci ifs -> Index ifs owner -> ProjBase rs ci ifs owner
```

Where the projection may read its owner: a register slot, or one input-constructor field.
**Arbitrary computed bases are deliberately not representable** — restricting the base is what gives
the symbolic layer a stable, typed path identity.

### Smart constructors

```haskell
regProj ::
    (…) =>
    FieldWitness projection ->
    Index rs (FieldOwner projection) ->
    Term rs ci ifs (FieldResult projection)

inpProj ::
    (…) =>
    FieldWitness projection ->
    InCtor ci ifs ->
    Index ifs (FieldOwner projection) ->
    Term rs ci ifs (FieldResult projection)
```

`regProj` projects from a register slot; `inpProj` projects from the matched input constructor —
pair it with the corresponding `matchInCtor` guard exactly as you would `inpCtor`. Validation treats
a projected read as a read of the whole underlying input field.

<Callout type="warn">
  **Symbolic agreement is one-way, by design.** Repeated reads of the same typed path share one
  symbolic variable, so `regProj w #owner .== regProj w #owner` is *valid*, not merely satisfiable.
  But the symbolic value of a plain `fieldWitness` is an **over-approximation**: every concrete owner
  can be bound to a matching symbolic projection value, while an arbitrary symbolic model **need not
  correspond to a constructible owner**. `symSatExt` does not reconstruct consumer-owned values from
  free projection scalars. Treat a solver model over projections as evidence about the *scalars*, not
  about the owner.

  **Corrected in keiki 0.7.0.0.** Path identity and proof strength are separate concerns, and keiki
  used to conflate them: a one-way projection was treated as an *exact* translation whenever its
  result carrier happened to be solver-supported. It no longer is. A predicate containing a
  `TFieldProj` over a released `fieldWitness` is now reported as `UnverifiedOpaque` by
  [`verifyPredicate`](/docs/keiki/reference/symbolic). Path-stable repeated reads and the
  conservative `symIsBot` emptiness proof are unaffected — definite unsatisfiability over the larger
  free-scalar domain still proves the smaller concrete domain empty.
</Callout>

### Exact projections

*(keiki 0.7.0.0.)* An `ExactFieldProjection` instance opts one nominal projection tag into a
stronger contract: its declared domain is exactly the image of its getter, and it supplies a
canonical inverse. That is what lets the solver reach a *verified* answer over a consumer-owned
value rather than a conservative one.

```haskell
class (FieldProjection projection) => ExactFieldProjection projection where
    fieldProjectionDomain ::
        Proxy projection -> ProjectionDomain (FieldResult projection)
    reconstructFieldOwner ::
        Proxy projection ->
        FieldResult projection ->
        Maybe (FieldOwner projection)
```

Both directions are laws:

- every well-formed owner projects to a member of `fieldProjectionDomain`; and
- every domain member is accepted by `reconstructFieldOwner`, whose returned owner projects back to
  that same key.

Build the domain value with the combinators in
[`Keiki.ProjectionDomain`](/docs/keiki/reference/projection-domain).

Defining the instance changes nothing on its own — callers opt in **per use site** with
`exactFieldWitness` instead of `fieldWitness`:

```haskell
exactFieldWitness ::
    ( ExactFieldProjection projection,
      KnownSymbol (FieldName projection),
      Typeable projection,
      Typeable (FieldOwner projection),
      Typeable (FieldResult projection),
      Eq (FieldResult projection)
    ) =>
    FieldWitness projection
```

The two laws are executable, so a consumer or generated conformance suite can test them:

```haskell
data ProjectionLawFailure
    = ProjectionWitnessIsUnconstrained
    | ProjectedKeyOutsideDeclaredDomain
    | ProjectionInverseRejectedDomainKey
    | ProjectionInverseRoundTripMismatch
    deriving stock (Eq, Show)

checkFieldProjectionOwner ::
    (FieldProjection projection) =>
    FieldWitness projection ->
    FieldOwner projection ->
    Either ProjectionLawFailure ()

checkFieldProjectionKey ::
    (FieldProjection projection) =>
    FieldWitness projection ->
    FieldResult projection ->
    Either ProjectionLawFailure (FieldOwner projection)
```

`checkFieldProjectionOwner` runs the owner-to-domain direction plus the inverse round trip for one
owner value. `checkFieldProjectionKey` checks one declared key and returns its reconstructed owner
on success; call it for every member of a finite domain, and combine it with schema-derived
generators for a validated infinite text domain. Both return
`ProjectionWitnessIsUnconstrained` for a plain `fieldWitness`.

<Callout type="warn">
  **Exact-domain soundness is conditional on the owner-side law.** Keiki checks every
  solver-returned model for domain membership, inverse success, and getter round-trip, so it can
  catch an inverse that rejects an admitted key or returns a non-round-tripping owner. It **cannot**
  observe a domain that *omits* a key a real owner produces — that under-declaration manufactures a
  false UNSAT before any satisfying model exists. `VerifiedUnsatisfiable`, `symIsBot`, a determinism
  disjointness blessing, and a dead-edge proof over `exactFieldWitness` predicates are therefore
  sound only conditional on the declaration laws. Predicates using only the one-way `fieldWitness`
  keep the unconditional over-approximation guarantee. A generator that emits exact witnesses must
  also emit the owner-side conformance tests.
</Callout>

<Callout type="info">
  **Per-projection exactness is not predicate-global exactness.** One base path may use a single
  nominal exact tag repeatedly, but two distinct tags over one owner — or a direct owner read
  combined with any projection — stay conservative, because independent solver variables do not
  encode their joint owner relation. An *input* projection is exact only when the complete predicate
  logically implies its matching constructor guard. Projection arithmetic and ordering remain
  conservative; the exact surface is structural equality and its negation. `verifyPredicate` reports
  the difference, and `predicateTranslationReport` names the specific
  [`TranslationIssue`](/docs/keiki/reference/symbolic).
</Callout>

Three read-only queries expose the witness's private evidence without exposing its constructor, so
tooling can inspect a witness but cannot *claim* exactness:

```haskell
fieldWitnessHasExactDomain :: FieldWitness projection -> Bool
fieldWitnessDomain ::
    FieldWitness projection -> Maybe (ProjectionDomain (FieldResult projection))
fieldWitnessReconstruct ::
    FieldWitness projection -> FieldResult projection -> Maybe (FieldOwner projection)
```

`fieldWitnessHasExactDomain` returns `False` for every witness built by `fieldWitness`, and
`fieldWitnessDomain`/`fieldWitnessReconstruct` return `Nothing` for one.

<Callout type="info">
  **Projections are guards-only** in validated transducers. Raw evaluation stays total everywhere,
  but default validation rejects a projection in an update or an output —
  [`ProjectionOutsideGuard`](/docs/keiki/reference/validate). Equality additionally requires the
  result type to be in the curated symbolic registry, and ordering requires its ordering subset.
</Callout>

### Diagnostics and testing

```haskell
fieldProjectionPath ::
    (FieldProjection projection, KnownSymbol (FieldName projection)) =>
    FieldWitness projection ->
    ProjBase rs ci ifs (FieldOwner projection) ->
    String

fieldWitnessAgrees ::
    (FieldProjection projection, Eq (FieldResult projection)) =>
    FieldWitness projection ->
    (FieldOwner projection -> FieldResult projection) ->
    FieldOwner projection ->
    Bool
```

`fieldProjectionPath` renders the stable base and field name as a dotted path (`owner.field`, or
`Ctor.field.name` for an input base). It is **diagnostic only** — symbolic variable identity is
structural, not string-based.

`fieldWitnessAgrees witness reference owner` checks the instance's getter against a reference
getter on one owner value. QuickCheck it over your own owner generators, and mutation-test an
intentionally wrong instance to prove the property has teeth.

Two further helpers are exported as documented internals, for generators and for tooling that
reimplements path identity:

```haskell
fieldWitnessGet :: (FieldProjection projection) =>
    FieldWitness projection -> FieldOwner projection -> FieldResult projection
indexPosition :: Index xs a -> Int
```

`fieldWitnessGet` eliminates a witness through its coherent instance (this is what concrete
`evalTerm` applies). `indexPosition` is the zero-based position of an `Index` in its slot list;
projection identity includes the position as well as the name, so a manually constructed
duplicate-labelled schema cannot accidentally share a value.

See also [`constrainFieldProjection`](/docs/keiki/reference/symbolic) for binding a projection to a
concrete getter result in an agreement test, and
[`NonStructuralProjectionBoundary`](/docs/keiki/reference/composition) for what happens to a
projection across a composition boundary.

## Input constructors

An `InCtor` names one constructor of the input symbol type `ci` and pins the round-trip between that
constructor's payload and a typed register file `RegFile ifs`. The slot list `ifs` is the field
schema for the constructor; together with `Index` it lets call sites read fields via
`OverloadedLabels` (for example `inpStart #email`).

<Callout type="warn">
  **Breaking in keiki 0.9.0.0.** `InCtor` construction and record update are sealed behind a
  **read-only pattern**. The module exports `InCtor (InCtor, icName, icSchema, icMatch, icBuild)` —
  you can match and project, but you cannot build or record-update. See
  [Constructing a sealed `InCtor`](#constructing-a-sealed-inctor) below.
</Callout>

```haskell
pattern InCtor ::
  () =>
  (AssembleRegFile ifs, KnownSlotNames ifs) =>
  String ->
  InCtorSchema ci ifs ->
  (ci -> Maybe (RegFile ifs)) ->
  (RegFile ifs -> ci) ->
  InCtor ci ifs
```

<TypeTable
  type={{
    icName: { type: "String", description: "The named constructor's name (e.g. \"StartRegistration\") — diagnostic only; it never participates in structural comparison" },
    icSchema: { type: "InCtorSchema ci ifs", description: "Abstract Generic-derived constructor path and typed slot spine, or the unavailable marker" },
    icMatch: { type: "ci -> Maybe (RegFile ifs)", description: "Returns Just iff ci is the named constructor, decoding its payload into a typed register file" },
    icBuild: { type: "RegFile ifs -> ci", description: "Left inverse of icMatch: icMatch (icBuild rf) == Just rf for every well-formed rf" },
  }}
/>

The `AssembleRegFile` and `KnownSlotNames` constraints mean any code holding an
`InCtor` can mechanically rebuild a `RegFile` from a bag of `(Index, value)` pairs and recover the
slot names of `ifs` at run time. Both instances are automatic for any concrete slot list, so users
write no extra code.

### Constructing a sealed `InCtor`

Trusted construction requires a strict capability from a hidden library module. Public callers cannot
import that capability, and so get exactly three routes:

```haskell
-- Manual behavior, explicitly without structural evidence.
unavailableInCtor ::
  (AssembleRegFile ifs, KnownSlotNames ifs) =>
  String ->
  (ci -> Maybe (RegFile ifs)) ->
  (RegFile ifs -> ci) ->
  InCtor ci ifs

-- Change only the diagnostic name, preserving behavior and trusted evidence.
renameInCtor :: String -> InCtor ci ifs -> InCtor ci ifs
```

plus the trusted producers in [`Keiki.Generics`](/docs/keiki/reference/generics) —
`mkInCtorVia`, `mkInCtorRecordVia` — and TH derivation.

<Callout type="info">
  **Migration.** Replace an intentional manual `InCtor` record with
  `unavailableInCtor name match build`. Prefer `mkInCtorVia` for constructors wrapping record
  payloads and `mkInCtorRecordVia` for constructors whose fields are declared directly with record
  syntax. Use `renameInCtor` instead of record update when only the diagnostic name changes, and use
  a trusted producer on every boundary passed to `composeChecked` or relied on for symbolic
  constructor exclusion.
</Callout>

### Structural evidence and head classification

`InCtorSchema` is an abstract, `Generic`-derived structural schema: the constructor's path through
the representation, plus its ordered slot spine. Diagnostic names never participate.

```haskell
data InCtorSchemaAvailability = ...
inCtorSchemaUnavailable :: InCtorSchema ci ifs
inCtorSchemaAvailability :: InCtorSchema ci ifs -> InCtorSchemaAvailability

data InputHeadRelation
  = InputHeadsStructurallyEqual
  | InputHeadsStructurallyDifferent
  | InputHeadsUnwitnessed

classifyInputHeads :: InCtor ci left -> InCtor ci right -> InputHeadRelation
```

`classifyInputHeads` is proof-safe: `InputHeadsUnwitnessed` is returned whenever either side lacks
evidence, and callers must treat it conservatively rather than as "different".

The trust model roots in **lawful `Generic` instances**. A deliberately unlawful hand-written
instance is outside the threat model, exactly as `unsafeCoerce` is.

## The update language

`Update` is the copyless update language. The `w :: [Symbol]` index records the set of slot names the
update writes; the smart constructor `combine` demands `Disjoint w1 w2` to combine two updates, so
"each register is written at most once per edge update" becomes a type-level invariant rather than a
runtime check.

```haskell
data Update (rs :: [Slot]) (w :: [Symbol]) (ci :: Type) where
    UKeep :: Update rs '[] ci
    USet ::
        (KnownSymbol s) =>
        IndexN s rs r -> Term rs ci ifs r -> Update rs '[s] ci
    UCombine ::
        Update rs w1 ci ->
        Update rs w2 ci ->
        Update rs (Concat w1 w2) ci
```

`UKeep` writes nothing; `USet` writes one slot from a term's value; `UCombine` is the raw, *unchecked*
join (it is left unconstrained so internal pattern-matches in `Keiki.Composition` that reconstruct
`UCombine` values stay cheap).

Always introduce a join through `combine`, whose `Disjoint w1 w2` constraint statically rejects an
aggregate that writes the same slot twice (e.g. `USet #email t1 \`combine\` USet #email t2`) at
compile time with a `TypeError` naming the offending slot.

```haskell
combine ::
    (Disjoint w1 w2) =>
    Update rs w1 ci ->
    Update rs w2 ci ->
    Update rs (Concat w1 w2) ci
```

## Output assembly

A `WireCtor` is a wire-type tag for one constructor of the user's output sum `co`. Its functions let
`solveOutput` pattern-match an observed `co` and `evalOut` rebuild a `co` from its fields.

<Callout type="warn">
  **Breaking in keiki 0.9.0.0.** Like `InCtor`, `WireCtor` construction and record update are sealed
  behind a read-only pattern: `WireCtor (WireCtor, wcName, wcSchema, wcMatch, wcBuild)`.
</Callout>

```haskell
pattern WireCtor ::
  String ->
  WireSchema co fields ->
  (co -> Maybe fields) ->
  (fields -> co) ->
  WireCtor co fields
```

```haskell
classifyWireHeads :: WireCtor co left -> WireCtor co right -> WireHeadRelation
```

with `mkWireCtorVia`, `mkWireCtor0Via`, and `mkWireCtorRecordVia` as the trusted `Generic`
producers.

### Aligning an input constructor with a wire constructor

```haskell
data InputWireHeadRelation
  = InputWireHeadsAligned
  | InputWireHeadsStructurallyDifferent
  | InputWireHeadsUnwitnessed

classifyInputWireHeads :: InCtor mid ifs -> WireCtor mid fields -> InputWireHeadRelation
```

This compares an input constructor's evidence against an output wire constructor's evidence **at the
same carrier**. It is the observer form of the checked alignment that authorizes
sequential-composition substitution; the typed alignment witness itself stays internal. Diagnostic
names never participate — which is precisely what makes it sound where the old equal-names check was
not. See [Composition](/docs/keiki/reference/composition).

`OutFields` is an HList of `Term`s, one per field of the wire constructor; the field-tuple type is
built nested-pair style so `solveOutput` can walk it structurally. Its `ifs` parameter is the shared
input field schema of every `Term` in the list.

```haskell
data OutFields rs ci ifs fs where
    OFNil :: OutFields rs ci ifs ()
    OFCons ::
        Term rs ci ifs f ->
        OutFields rs ci ifs fs ->
        OutFields rs ci ifs (f, fs)
```

Build `OutFields` literals with `(*:)` (the right-associative synonym for `OFCons`, fixity
`infixr 5`) and `oNil` (the synonym for `OFNil`). They read top-to-bottom in the wire constructor's
field order:

```haskell
(*:) :: Term rs ci ifs f -> OutFields rs ci ifs fs -> OutFields rs ci ifs (f, fs)
oNil :: OutFields rs ci ifs ()

infixr 5 *:
```

```haskell
-- d.recipient *: d.subject *: d.at *: oNil
-- is identical to
-- OFCons t1 (OFCons t2 (OFCons t3 OFNil))
```

`OutTerm` is a pure expression yielding an output value `co`. Its only constructor, `OPack`, is the
structural pack: tagged by an input constructor (which the edge consumes) and an output wire
constructor (which the edge produces), with one `Term` per field of the wire constructor.

```haskell
data OutTerm (rs :: [Slot]) (ci :: Type) (co :: Type) where
    OPack ::
        InCtor ci ifs ->
        WireCtor co fields ->
        OutFields rs ci ifs fields ->
        OutTerm rs ci co
```

`solveOutput` walks the structural `OutFields`, gathers `(Index, value)` pairs against the named
`InCtor`, and reconstructs the input by calling `icBuild` on the assembled register file — no inverse
function supplied by the user, no coercion. Author `OutTerm`s with the `pack` smart constructor:

```haskell
pack ::
    InCtor ci ifs ->
    WireCtor co fields ->
    OutFields rs ci ifs fields ->
    OutTerm rs ci co
```

## The predicate language

`HsPred` is the v1 first-class predicate AST. It carries enough structure to evaluate guards
concretely and to translate to SMT through the SBV-backed `BoolAlg` instance in `Keiki.Symbolic`.

```haskell
data HsPred (rs :: [Slot]) (ci :: Type) where
    PTop :: HsPred rs ci
    PBot :: HsPred rs ci
    PAnd :: HsPred rs ci -> HsPred rs ci -> HsPred rs ci
    POr :: HsPred rs ci -> HsPred rs ci -> HsPred rs ci
    PNot :: HsPred rs ci -> HsPred rs ci
    PEq ::
        (Eq r, Typeable r) =>
        Term rs ci ifs1 r -> Term rs ci ifs2 r -> HsPred rs ci
    PInCtor :: InCtor ci ifs -> HsPred rs ci
    PCmp ::
        (Ord r, Typeable r) =>
        Cmp -> Term rs ci ifs1 r -> Term rs ci ifs2 r -> HsPred rs ci
```

`PInCtor` is the structural input-constructor guard (`True` iff the input symbol is the named
constructor). `PCmp` carries an ordering relation; unlike a threshold smuggled through `TApp`, it is
structural and the SBV translator emits a real symbolic comparison. Equality is left to `PEq` — `Cmp`
has no "equal" case.

`Cmp` is the single four-way ordering tag carried by `PCmp`: `CmpLt`/`CmpLe`/`CmpGt`/`CmpGe` are
`<`/`<=`/`>`/`>=`.

```haskell
data Cmp = CmpLt | CmpLe | CmpGt | CmpGe
    deriving stock (Eq, Show)
```

`Pred rs ci` is a readable synonym for `HsPred rs ci`.

### The guard-authoring operators

These are re-exported from `Keiki.Core` (and also live in `Keiki.Operators`). Each relational
operator is an alias for `PCmp`/`PEq` at a fixed relation; the logical and arithmetic operators
mirror their Prelude counterparts. Keep spaces around them (`lit a .* lit b`) — a dot touching an
identifier (`x.y`) is `OverloadedRecordDot` field access. If you import `Data.SBV` alongside this
module, import it qualified; SBV exports the same names.

```haskell
(.==) :: (Eq r, Typeable r) => Term rs ci ifs1 r -> Term rs ci ifs2 r -> HsPred rs ci
(./=) :: (Eq r, Typeable r) => Term rs ci ifs1 r -> Term rs ci ifs2 r -> HsPred rs ci
(.<)
    , (.<=)
    , (.>)
    , (.>=) ::
        (Ord r, Typeable r) => Term rs ci ifs1 r -> Term rs ci ifs2 r -> HsPred rs ci
(.&&), (.||) :: HsPred rs ci -> HsPred rs ci -> HsPred rs ci
pnot :: HsPred rs ci -> HsPred rs ci
(.+)
    , (.-)
    , (.*) ::
        (Num r, Typeable r) => Term rs ci ifs r -> Term rs ci ifs r -> Term rs ci ifs r
```

The fixities (verified against the source) are:

<TypeTable
  type={{
    ".==, ./=": { type: "infix 4", description: "Equality / inequality (PEq / PNot . PEq); do not chain" },
    ".<, .<=, .>, .>=": { type: "infix 4", description: "Ordering guards (PCmp at a fixed Cmp); do not chain" },
    ".&&": { type: "infixr 3", description: "Conjunction (PAnd)" },
    ".||": { type: "infixr 2", description: "Disjunction (POr)" },
    ".+, .-": { type: "infixl 6", description: "Term addition / subtraction (tadd / tsub)" },
    ".*": { type: "infixl 7", description: "Term multiplication (tmul)" },

/>

So `a .>= b` is `PCmp CmpGe a b`, `a ./= b` is `pnot (a .== b)`, and `p .&& q .|| r` parses as
`(p .&& q) .|| r`. The relational operators sit below the arithmetic operators and above the logical
ones. `pnot` is the direct AST alias for `PNot`.

`matchInCtor` is the named alias for the `PInCtor` guard: `evalPred (matchInCtor ic) regs ci`
equals `isJust (icMatch ic ci)`.

```haskell
matchInCtor :: InCtor ci ifs -> HsPred rs ci
```

*(keiki 0.7.0.0.)* `predicateImpliesInCtor` is the sound structural implication check behind that
guard: it answers whether **every** satisfying valuation of a predicate must match the named input
constructor.

```haskell
predicateImpliesInCtor :: String -> HsPred rs ci -> Bool
```

Conjunction needs either side to imply the constructor; disjunction needs both; negation and
non-constructor atoms establish nothing. Unlike the crash-safety walk behind
`guardImpliesInputReadWarnings`, it is deliberately **independent of conjunction operand order**, so
symbolic translation classifies `projection .&& matchInCtor ic` exactly as it classifies
`matchInCtor ic .&& projection`. (Concrete evaluation keeps its existing left-to-right partiality
warning.) This is the check that decides whether an input projection is exact — see
[exact projections](#exact-projections).

## The effective Boolean algebra

`BoolAlg` is the effective Boolean algebra over `a`-typed witnesses, used as the guard carrier of
edges. It abstracts the guard language so the same transducer machinery works over the concrete
`HsPred` carrier *and* the SBV-backed `SymPred` carrier.

```haskell
class BoolAlg phi a | phi -> a where
    top :: phi
    bot :: phi
    conj :: phi -> phi -> phi
    disj :: phi -> phi -> phi
    neg :: phi -> phi
    models :: phi -> a -> Bool
    isBot :: phi -> Bool
```

The v1 carrier's instance evaluates guards **concretely** — its `models` is `evalPred`, with **no
solver** involved:

```haskell
instance BoolAlg (HsPred rs ci) (RegFile rs, ci) where
    top = PTop
    bot = PBot
    conj p q = PAnd p q
    disj p q = POr p q
    neg p = PNot p
    models p (regs, ci) = evalPred p regs ci
    isBot PBot = True
    isBot _ = False
```

`Sat` is a stronger capability split out of `BoolAlg`: a `BoolAlg` whose witnesses can be *extracted*
from a satisfiable predicate. `sat phi` returns `Just` a value satisfying `phi`, or `Nothing` when it
is unsatisfiable.

```haskell
class (BoolAlg phi a) => Sat phi a where
    sat :: phi -> Maybe a
```

The v1 syntactic carrier has no solver, hence no extractable witness — its `sat` is always `Nothing`.
The precise witnesses come from the SBV-backed `Sat (SymPred …)` instance in `Keiki.Symbolic`.

```haskell
instance Sat (HsPred rs ci) (RegFile rs, ci) where
    sat _ = Nothing
```

## Edges and the transducer

An `Edge` is a single transition. `output` is a *list* of `OutTerm`s: `[]` is the ε-edge (no
observable emission), `[o]` is the letter edge (one event), `[o1, o2, ...]` is the multi-event edge
(one transition emits N events in declaration order).

```haskell
data Edge phi rs ci co s where
    Edge ::
        { guard :: phi
        , update :: Update rs w ci
        , output :: [OutTerm rs ci co]
        , target :: s
        , mode :: EdgeMode
        } ->
        Edge phi rs ci co s
```

<TypeTable
  type={{
    guard: { type: "phi", description: "The edge's guard in the chosen Boolean-algebra carrier" },
    update: { type: "Update rs w ci", description: "Register update; the write-set index w is existentially quantified at the record" },
    output: { type: "[OutTerm rs ci co]", description: "Emitted letters: [] (ε), [o] (letter), or [o1, o2, ...] (multi-event)" },
    target: { type: "s", description: "The destination vertex" },
    mode: { type: "EdgeMode", description: "Which execution paths the edge serves: Live or ReplayOnly" },

/>

The `w` index on `update` is existentially quantified at the `Edge` record so that the homogeneous
list `[Edge phi rs ci co s]` in `edgesOut` type-checks while the static disjointness check is still
enforced at every `Update`'s introduction point (via `combine`).

### Edge mode

*(keiki 0.3.0.0.)*

```haskell
data EdgeMode = Live | ReplayOnly
    deriving stock (Eq, Ord, Show, Bounded, Enum)
```

- A **`Live`** edge is an ordinary transition: forward stepping (`delta` / `step` / `stepEither`)
  may take it, and replay (`applyEvent` / `applyEventStreamingEither`) may invert against it.
- A **`ReplayOnly`** edge is *never* taken by forward stepping — no new command can fire it. It
  exists so events emitted under a retired rule keep an inverting edge. When a guard is tightened,
  the removed region (`old-guard ∧ ¬new-guard`) can be retained as a **replay-only twin** of the live
  edge, keeping every stored event replayable while the tightened rule governs all new traffic. Its
  `update` defines how those historical events fold *today*.

**Inversion is two-phase.** Candidates are sought among `Live` edges first; only when no live edge
matches are `ReplayOnly` edges tried. Ambiguity is judged *within the phase that produced
candidates*. An event attributable under the current rules therefore always attributes there — only
unattributable history falls through to the replay-only arms.

The `Semigroup`/`Monoid` instances define the mode of a composed edge — `Live` is the identity,
`ReplayOnly` absorbs, so a composite edge may fire forward only when every component may:

```haskell
instance Semigroup EdgeMode where
    Live <> m = m
    ReplayOnly <> _ = ReplayOnly

instance Monoid EdgeMode where
    mempty = Live
```

<Callout type="warn">
  **Breaking in keiki 0.3.0.0.** `Edge` gained the `mode` field. Existing hand-written construction
  sites should set `mode = Live` to keep their exact previous semantics. Composition (`compose`,
  `alternative`), the profunctor rewrites, and `withSymPred` all propagate the mode.

  Static checks are mode-aware: the determinism family (`checkTransitionDeterminism`,
  `checkTransitionDeterminismPure`, `determinismWarnings`, `isSingleValuedSym`) considers only
  `Live`/`Live` pairs, because only live edges compete in forward dispatch, and
  `inversionAmbiguityWarnings` flags only **same-mode** pairs — cross-mode pairs are resolved
  deterministically by the live-first phase order. Every other check applies to replay-only edges
  unchanged.
</Callout>

<Callout type="warn">
  **Deleting a deployed replay-only twin re-creates exactly the break it fixed** — stored events in
  the removed region lose their inverting edge. Delete a twin only once every stream containing the
  region's events is terminal or truncated. Build one with
  [`replayOnly`](/docs/keiki/reference/builder); see [evolve a schema
  safely](/docs/keiki/cookbook/evolve-a-schema-safely).
</Callout>

edges' update terms.


## The concrete evaluators

These run the ASTs above against an actual register file and input symbol. **No solver** — they
compute Haskell values directly.

```haskell
evalTerm :: Term rs ci ifs r -> RegFile rs -> ci -> r
evalOut :: OutTerm rs ci co -> RegFile rs -> ci -> co
evalPred :: HsPred rs ci -> RegFile rs -> ci -> Bool
runUpdate :: Update rs w ci -> RegFile rs -> ci -> RegFile rs
```

`evalTerm` evaluates a term; `evalOut` rebuilds an output value (the `InCtor` on `OPack` is consulted
only by the inverse direction, `solveOutput`); `evalPred` evaluates a guard to a `Bool`; `runUpdate`
applies an update, forcing each written slot to WHNF so a long-running embedder accumulates no thunk
tower.

`delta` is the unique-matching-edge transition. It returns `Just (s', regs')` iff **exactly one**
outgoing edge has a satisfied guard, and `Nothing` when zero or more than one match.

```haskell
delta ::
    (BoolAlg phi (RegFile rs, ci)) =>
    SymTransducer phi rs s ci co ->
    s ->
    RegFile rs ->
    ci ->
    Maybe (s, RegFile rs)
```

`omega` returns the list of events emitted by the unique active edge: `[]` for an ε-edge, `[o]` for a
letter edge, `[o1, o2, ...]` for a multi-event edge. It also returns `[]` if no edge (or more than
one edge) is active — so the caller cannot distinguish "no active edge" from "active ε-edge" from
this function alone; use `step` or `delta` when that distinction matters.

```haskell
omega ::
    (BoolAlg phi (RegFile rs, ci)) =>
    SymTransducer phi rs s ci co ->
    s ->
    RegFile rs ->
    ci ->
    [co]
```

## Pure-layer run entry points

`step` is one full step, combining `delta` and `omega`. It returns `Nothing` if no edge from the
current vertex has a satisfied guard; on success it returns the bare triple — next vertex, updated
registers, and emitted letters (the inner `[co]` is `[]` for an ε-edge).

```haskell
step ::
    (BoolAlg phi (RegFile rs, ci)) =>
    SymTransducer phi rs s ci co ->
    (s, RegFile rs) ->
    ci ->
    Maybe (s, RegFile rs, [co])
```

`stepEither` is like `step` but returns a precise `StepFailure` on the `Left` instead of collapsing
every failure into `Nothing`. On the `Right` it returns **exactly** the triple `step` returns.

```haskell
stepEither ::
    (BoolAlg phi (RegFile rs, ci)) =>
    SymTransducer phi rs s ci co ->
    (s, RegFile rs) ->
    ci ->
    Either (StepFailure s) (s, RegFile rs, [co])
```

### Replay

Replay inverts persisted events through the same edges that handle commands. New code should use the
structured `Either` functions: they distinguish corrupt or incompatible history from an ordinary
command rejection and identify exactly where hydration stopped. The older `Maybe` functions remain
compatibility wrappers and deliberately discard this evidence.

`InFlight` is the streaming carrier. `Settled s` is a stable vertex. `InFlight s pending` means the
edge update has already run and replay must still match the evaluated tail of that edge's multi-event
output; consuming a tail event must not apply the update again.

```haskell
data InFlight s co
    = Settled !s
    | InFlight !s ![co]
    deriving (Eq, Show)
```

A one-event failure is one of three replay-specific cases:

```haskell
data ReplayStepFailure s co
    = ReplayNoInvertingEdge s [RejectedEdgeSummary s]
    | ReplayAmbiguousInversions s [MatchedEdgeSummary s]
    | ReplayQueueMismatch s co [co]
    deriving stock (Eq, Show)
```

`ReplayNoInvertingEdge` means no outgoing edge could recover a guard-satisfying command from the
observed event. `ReplayAmbiguousInversions` means multiple edges recovered one, which is a durable
soundness defect rather than ordinary rejection. `ReplayQueueMismatch` records the stable target,
the observed event, and the pending queue when a multi-event tail arrived out of order.

List-level failures add the zero-based event index and the wrapper state immediately before failure.
Strict replay also reports a log that ends with pending tail events:

```haskell
data ReplayFailureReason s co
    = ReplayEventFailed (ReplayStepFailure s co)
    | ReplayLogTruncated [co]
    deriving stock (Eq, Show)

data ReplayFailure s co = ReplayFailure
    { replayFailedIndex  :: Int
    , replayFailedState  :: InFlight s co
    , replayFailureReason :: ReplayFailureReason s co
    }
    deriving stock (Eq, Show)
```

`applyEventStreamingEither` consumes one observed event. From `Settled`, it selects the unique
inverting edge, applies its update once, and records any evaluated tail. From `InFlight`, it only
matches and pops the queue head.

```haskell
applyEventStreamingEither ::
    (BoolAlg phi (RegFile rs, ci), Eq co) =>
    SymTransducer phi rs s ci co ->
    InFlight s co ->
    RegFile rs ->
    co ->
    Either (ReplayStepFailure s co) (InFlight s co, RegFile rs)
```

`replayEvents` starts from any streaming seed and intentionally permits a page to end `InFlight`, so
a paginated event-store reader can carry that wrapper into the next page.

```haskell
replayEvents ::
    (BoolAlg phi (RegFile rs, ci), Eq co) =>
    SymTransducer phi rs s ci co ->
    (InFlight s co, RegFile rs) ->
    [co] ->
    Either (ReplayFailure s co) (InFlight s co, RegFile rs)
```

`applyEventsEither` is strict chunk replay from a caller-supplied settled state. `reconstituteEither`
is the same strict behavior from the transducer's initial state. Both reject a truncated chain with
`ReplayLogTruncated`; its failure index is the input length, where the missing tail event belonged.

```haskell
applyEventsEither ::
    (BoolAlg phi (RegFile rs, ci), Eq co) =>
    SymTransducer phi rs s ci co ->
    (s, RegFile rs) ->
    [co] ->
    Either (ReplayFailure s co) (s, RegFile rs)

reconstituteEither ::
    (BoolAlg phi (RegFile rs, ci), Eq co) =>
    SymTransducer phi rs s ci co ->
    [co] ->
    Either (ReplayFailure s co) (s, RegFile rs)
```

The compatibility names are implemented by erasing the `Left`: `applyEventStreaming`, `applyEvents`,
and `reconstitute` return `Maybe`; `applyEvent` is additionally letter-only. Prefer them only when a
bare accepted/rejected answer is truly sufficient.

These are the detailed counterparts of `applyEventsEither` and `reconstituteEither`, with identical
failures. Three properties of the trace are worth knowing:

- A multi-event edge completes **one** attribution covering its whole tail, not one per event.
- An **epsilon-output edge is unobservable in replay** and so never appears in the trace — there is
  no event to attribute to it.
- The live-first phase is reported exactly, so a `ReplayOnly` entry marks history that no current
  live edge could explain.

<Callout type="info">
  Attribution is **opt-in and costs nothing when unused.** All replay paths share one evaluation
  kernel; the existing functions retain a nullary no-trace policy with O(1) auxiliary trace state,
  so adding these entry points did not slow ordinary replay down.
</Callout>

## Step diagnostics

`stepEither` reports failure through `StepFailure`. There are three cases:

```haskell
data StepFailure s
    = NoOutgoingEdges s
    | NoMatchingEdge s [RejectedEdgeSummary s]
    | AmbiguousEdges s [MatchedEdgeSummary s]
    deriving stock (Eq, Show)
```

- `NoOutgoingEdges` — the source vertex has no outgoing edges at all.
- `NoMatchingEdge` — there are outgoing edges, but none matched the command; carries one
  `RejectedEdgeSummary` per edge, in declaration order.
- `AmbiguousEdges` — two or more guards matched the same command (a runtime witness of a
  single-valuedness violation); carries one `MatchedEdgeSummary` per matched edge.

`EdgeRef` is the canonical edge locator: the vertex an edge leaves from and its zero-based position
in `edgesOut t source`.

```haskell
data EdgeRef s = EdgeRef
    { edgeSource :: s
    , edgeIndex :: Int
    }
    deriving stock (Eq, Show)
```

<Callout type="warn">
  **An `EdgeRef` is construction-local, not a stable application identifier.** `edgeIndex` is the
  zero-based position in `edgesOut t edgeSource` for *this concrete transducer construction*, so it
  changes whenever outgoing declaration order changes. It is the shared local edge-identity
  vocabulary for build-time diagnostics, [`StepSuccess`](#detailed-forward-success), and
  [`ReplayAttribution`](#replay-attribution) — do not persist it.
</Callout>

The summaries deliberately carry **no** register values — diagnostics summarize, they do not dump
state.

```haskell
data RejectedEdgeSummary s = RejectedEdgeSummary
    { rejectedEdge :: EdgeRef s
    , rejectedTarget :: s
    , rejectedGuard :: Bool
    }
    deriving stock (Eq, Show)

data MatchedEdgeSummary s = MatchedEdgeSummary
    { matchedEdge :: EdgeRef s
    , matchedTarget :: s
    }
    deriving stock (Eq, Show)
```

<Callout type="info">
`stepEither` and `StepFailure` are introduced here for completeness, but the per-failure
interpretation — how to read each case and what to do about it — is documented by the diagnostics
capability. See the diagnostics how-to under `/docs/keiki/how-to` (or the explanation page at
`/docs/keiki/explanation/...`); the [reference section landing](/docs/keiki/reference) lists the
related pages.
</Callout>

## A minimal example

The smallest machine that exercises `delta`, `omega`, `evalOut`, and a real edge: two vertices over a
`Bool` input and `String` output, with no registers.

```haskell
inCtorTrue :: InCtor Bool '[]
inCtorTrue = InCtor
  { icName  = "True"
  , icMatch = \case True -> Just RNil; False -> Nothing
  , icBuild = \RNil -> True
  }

wcStringTrue :: WireCtor String ()
wcStringTrue = WireCtor
  { wcName  = "True"
  , wcMatch = \s -> if s == "true" then Just () else Nothing
  , wcBuild = \() -> "true"
  }

synthetic :: SymTransducer (HsPred '[] Bool) '[] Bool Bool String
synthetic = SymTransducer
  { edgesOut = \case
      False -> [ Edge { guard  = matchInCtor inCtorTrue
                      , update = UKeep
                      , output = [ pack inCtorTrue wcStringTrue oNil ]
                      , target = True
                      , mode   = Live
                      }
               ]
      True  -> []
  , initial     = False
  , initialRegs = RNil
  , isFinal     = id
  }

-- step synthetic (False, RNil) True == Just (True, RNil, ["true"])
-- omega synthetic False RNil True  == ["true"]
-- delta synthetic True  RNil True  == Nothing   -- sink vertex
```

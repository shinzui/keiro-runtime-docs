`Keiki.Symbolic` is the build-time symbolic upgrade of keiki's predicate algebra. It
**re-exports all of [`Keiki.Core`](/docs/keiki/reference/core)** and, since keiki 0.7.0.0, all of
[`Keiki.ProjectionDomain`](/docs/keiki/reference/projection-domain) — one import gives you the
pure transducer surface, the exact-domain vocabulary, and the symbolic machinery — and adds an
`sbv`/z3-backed `BoolAlg`
instance that decides "are these two edge guards mutually exclusive?" precisely rather than
syntactically. For the why, see [Why SMT](/docs/keiki/explanation/why-smt) and
[The symbolic transducer](/docs/keiki/explanation/the-symtransducer).

<Callout type="warn">
z3 (via `sbv`) is a **build/CI-time dependency only** — it is never on the per-event runtime hot
path. The everyday step functions (`delta`/`omega`/`step`/`stepEither`/`reconstitute`) decide
guards by **concrete evaluation**: `models (guard e) (regs, ci)` reduces to `evalPred`, never a
solver call. Only `isBot`, `symIsBot`, `symSatExt`, `verifyPredicate`, `verifyPredicateDetailed`,
`checkTransitionDeterminismSym`, and `checkDeadEdgesSym` (with their `…Detailed` variants) invoke
z3, and they are meant for tests and the symbolic CI gate (see
[The symbolic CI gate](/docs/keiki/explanation)).
</Callout>

## The `Sym` typeclass

A type has a `Sym` instance when it has a curated representation in the SBV symbolic universe.
The associated type `SymRep a` pins the SBV-friendly carrier; `toSym`/`fromSym` round-trip a
concrete Haskell value through the solver; `symDefault` supplies a fallback for unconstrained
slots during witness extraction; `constrainSymDomain` restricts the symbolic representation to
values that actually denote an `a`.

```haskell
class (SBV.SymVal (SymRep a), Typeable a) => Sym a where
    type SymRep a :: Type
    toSym :: a -> SymRep a
    fromSym :: SymRep a -> a
    symDefault :: a
    constrainSymDomain :: SBV.SBV (SymRep a) -> SBV.Symbolic ()
    constrainSymDomain _ = pure ()
```

The `SBV.SymVal (SymRep a)` superclass gives `SBV.literal`, `SBV.free`, and `SBV.unliteral`
for free. `symDefault` is consumed by `symSatExt`: when the solver model binds no value for a
slot the predicate never referenced, the witness extractor falls back to it — sound, because an
unreferenced slot is unconstrained and any value satisfies the predicate.

<Callout type="info">
  **`constrainSymDomain` — new in keiki 0.5.0.0 (PVP major, but source-compatible).** Most carriers
  use their whole SBV domain and inherit the `pure ()` default, so existing hand-written instances
  keep compiling unchanged. A **refined** carrier states its validity invariant here: `Natural` is
  represented as an unbounded `Integer` and constrains it `.>= 0`. Keiki applies the constraint
  everywhere it allocates a symbolic variable — `symFree`, structural register and input reads,
  field projections, and opaque term fallbacks — so no solver path can produce a value outside the
  carrier.
</Callout>

### Whole-carrier exactness

*(keiki 0.7.0.0.)* Having a `Sym` instance is **not** the same as being exactly representable.

```haskell
symbolicWholeCarrierExact :: forall r. (Typeable r) => Bool
```

`symbolicWholeCarrierExact` answers whether the curated representation covers the complete concrete
carrier **bijectively**. It is the gate for
[`wholeProjectionDomain`](/docs/keiki/reference/projection-domain): supporting symbolic equality
alone is not sufficient. It holds for `Bool`, `Integer`, `Natural`, and the curated fixed-width
integer types; it does **not** hold for `UTCTime` (leap-second clamping) or `Text` (SMT-LIB strings
stop at U+2FFFF).

## The runtime registry: `SymDict` and `discoverSym`

`Sym` evidence is reified so the translator can dispatch on `Typeable` at runtime.

```haskell
data SymDict r where
    SymDict :: (Sym r) => SymDict r

discoverSym :: forall r. (Typeable r) => Maybe (SymDict r)
```

`discoverSym` returns `Just SymDict` for any curated supported type and `Nothing` otherwise. The
translator uses it to route `PEq` over an arbitrary operand type: a `Sym` hit translates to
`(.==)` on SBV terms; a miss falls back to a fresh `SBool` (sound, loses precision). Two
companion dictionaries carry the extra evidence the ordering and arithmetic translators need:

```haskell
data SymOrdDict r where
    SymOrdDict :: (Sym r, SBV.OrdSymbolic (SBV.SBV (SymRep r))) => SymOrdDict r

discoverSymOrd :: forall r. (Typeable r) => Maybe (SymOrdDict r)

data SymNumDict r where
    SymNumDict :: (Sym r, Num (SBV.SBV (SymRep r))) => SymNumDict r

discoverSymNum :: forall r. (Typeable r) => Maybe (SymNumDict r)
```

`discoverSymOrd` reifies `SBV.OrdSymbolic` evidence (what `PCmp` needs to emit a real
`.<`/`.<=`/`.>`/`.>=`); it covers the numeric and time types (`Int`, `Integer`, `Natural`, the
fixed-width integers, and `UTCTime`) but **deliberately omits `Bool` and `Text`** — ordering a
`Bool` guard is not meaningful and `SString` ordering is out of scope. `discoverSymNum` reifies
`Num` evidence (what `TArith` needs to emit a real `+`/`-`/`*`); it covers the numeric integers
**including `Natural` since keiki 0.6.0.0**, and omits `Bool`, `Text`, and `UTCTime`. A `Nothing`
from either makes the relevant translator fall back to a fresh opaque variable — sound, just
imprecise.

<Callout type="info">
  **`Natural` arithmetic is special-cased in the translator.** `OpAdd` and `OpMul` emit the ordinary
  SBV operations, but `OpSub` emits `ite (a .>= b) (a - b) 0` so the symbolic form matches the total
  monus concrete evaluation uses. Plain SMT integer subtraction would return a negative value that
  no `Natural` denotes. In keiki 0.5.0.0 `Natural` was deliberately kept *out* of the arithmetic
  registry for exactly this reason; 0.6.0.0 admitted it once the monus encoding existed.
</Callout>

### Literals and free variables

```haskell
symLit  :: forall a. (Sym a) => a -> SBV.SBV (SymRep a)
symFree :: forall a. (Sym a) => String -> SBV.Symbolic (SBV.SBV (SymRep a))
```

`symLit` lifts a concrete value to an SBV literal of its `SymRep`; `symFree` allocates a fresh
symbolic variable of the carrier's `SymRep`.

## Translation: `SymEnv`, `translateTermSym`, `translatePred`

A single predicate's walk threads a shared context so that distinct `PInCtor` atoms agree they
cannot both hold and so that repeated reads of one register share one solver variable.

```haskell
data SymEnv = SymEnv
    { seInputCtor                 :: SBV.SBV String
    , seInputArm                  :: SBV.SBool
    , seVarCache                  :: IORef (Map SymVarKey SomeSBV)
    , seVarLabels                 :: IORef (Map SymVarKey String)
    , seProjectionKeyOrder        :: IORef [SymVarKey]
    , seConstrainedProjectionKeys :: IORef (Set SymVarKey)
    , seProjectionBindings        :: IORef (Map SymVarKey SomeProjectionBinding)
    , seProjectionOrdinal         :: IORef Int
    }

mkSymEnv :: SBV.Symbolic SymEnv
```

/>

The memo cache (`seVarCache`) is the key correctness mechanism, keyed by a **structural** variable
key rather than a rendered string:

```haskell
data SymVarKey
    = RegVar String
    | InpVar String String
    | ProjectionVar
        ProjectionBaseKey
        SomeTypeRep    -- the projection tag
        SomeTypeRep    -- FieldOwner
        SomeTypeRep    -- FieldResult
    deriving stock (Eq, Ord, Show)

data ProjectionBaseKey
    = ProjectionReg String Int
    | ProjectionInp String String Int
    deriving stock (Eq, Ord, Show)
```

`TReg` keys on `RegVar <slot>`; `TInpCtorField` keys on `InpVar <ctor> <field>`; `TFieldProj` keys on
`ProjectionVar` over its base path (slot name **and** `indexPosition`) plus the three `TypeRep`s. The
**first** read of a key allocates one `SBV.free` variable and caches it; **every later read of the
same key returns the cached variable**. So the solver sees two reads of `#x` as the *same* value, and
`proj #x .== proj #x` is **valid**, not merely satisfiable — and likewise for two reads of the same
typed projection path. The cache is scoped to one `translatePred` walk (one `mkSymEnv`), so variables
are shared *within* a query but never leak across independent queries.

<Callout type="info">
  Projection identity is deliberately **structural, not string-keyed**: the tag's `TypeRep` decides
  sharing, so caller-controlled diagnostic strings (`FieldName`, `fieldShapeId`,
  `fieldProjectionPath`) never determine solver identity. The SBV *label* a projection variable gets
  is a generated `"proj/<ordinal>"` from `seProjectionOrdinal`, keeping arbitrary schema names out of
  SBV's restricted label namespace.
</Callout>

### `constrainFieldProjection`

*(keiki 0.4.0.0.)*

```haskell
constrainFieldProjection ::
    forall projection rs ci ifs.
    ( Typeable projection
    , Typeable (FieldOwner projection)
    , Sym (FieldResult projection)
    ) =>
    SymEnv ->
    FieldWitness projection ->
    ProjBase rs ci ifs (FieldOwner projection) ->
    FieldResult projection ->
    SBV.Symbolic ()
```

Binds the memoized projection variable for a typed path to a **concrete** getter result, for
concrete-to-symbolic agreement tests. It resolves the same `ProjectionVar` key the translator would,
then `constrain`s it equal to the literal.

<Callout type="warn">
  For a plain `fieldWitness` the supported agreement is **one-way**. Every concrete owner can bind a
  matching symbolic projection value, but an arbitrary symbolic projection model need not correspond
  to a constructible owner — `symSatExt` does **not** reconstruct consumer-owned values from free
  projection scalars. See [field projections](/docs/keiki/reference/core#field-projections).

  An [`exactFieldWitness`](/docs/keiki/reference/core#exact-projections) is the two-way case: its
  declared [`ProjectionDomain`](/docs/keiki/reference/projection-domain) is constrained **once per
  structured symbolic key**, and a satisfying model key is checked for domain membership, inverse
  success, and getter round trip before it is exposed. A finite domain is accepted only when every
  literal round-trips through its symbolic representation and satisfies backend bounds such as
  `Text`'s U+2FFFF ceiling; an unsupported domain emits **no partial constraint** and leaves the
  translation conservative.
</Callout>

### `translateTermSym`

```haskell
translateTermSym ::
    forall rs ci ifs r.
    (Sym r) =>
    SymEnv ->
    Term rs ci ifs r ->
    SBV.Symbolic (SBV.SBV (SymRep r))
```

The translation is structural for `TLit`, `TOpaqueLit`, `TReg`, `TInpCtorField`, `TArith`, and
`TFieldProj`. The two literal constructors translate **identically** — display evidence never
reaches the solver. `TFieldProj` is `memoFree env (projectionVarKey witness base)`, a free variable
for the typed path, plus the exact-domain constraint when the witness carries one. A `TArith` over
a type whose `SymRep` is SBV-numeric (a `discoverSymNum` hit) emits a real `+`/`-`/`*` over the
translated operands, so a guard over a *computed* value is visible to the solver. `TApp1` and
`TApp2` wrap opaque Haskell functions and translate to **fresh** `SBV.free "app1"`/`"app2"`
variables of the result type — **sound but under-verifying**: two occurrences of the same opaque
application do not share a variable (opaque functions have no `Eq`), and their values are not part
of the extracted witness.

### `translatePred`

```haskell
translatePred ::
    forall rs ci. SymEnv -> HsPred rs ci -> SBV.Symbolic SBV.SBool
```

`translatePred` walks an `HsPred` structurally into an SBV `SBool`:

- `PTop` / `PBot` map to `sTrue` / `sFalse`.
- `PAnd` / `POr` / `PNot` map to `.&&` / `.||` / `sNot` on the recursive translations.
- `PEq a b` tries `discoverSym` on the operand type; a hit emits `(.==)` between the two
  translated terms, a miss emits a fresh `SBool` (the equality is opaque).
- `PInCtor ic` emits `seInputCtor .== literal (icName ic)`; the shared `seInputCtor` makes
  constructor mutual-exclusion decidable.
- `PCmp op a b` tries `discoverSymOrd`; a hit emits the matching SBV comparison, a miss emits a
  fresh `SBool`.

## The symbolic predicate wrapper: `SymPred`

```haskell
newtype SymPred (rs :: [Slot]) (ci :: Type) = SymPred {unSymPred :: HsPred rs ci}

type SymGuarded rs s ci co = SymTransducer (SymPred rs ci) rs s ci co
```

`SymPred` is a newtype over `HsPred` that **selects the v2 SBV-backed `BoolAlg` instance** instead
of the pure syntactic one in `Keiki.Core`. The v1 `BoolAlg HsPred` instance stays unchanged for
back-compat; consumers that want symbolic answers wrap with `SymPred`. `SymGuarded` is the
SBV-backed analogue of `Keiki.Core`'s `Guarded`.

### The `BoolAlg` instance

```haskell
instance BoolAlg (SymPred rs ci) (RegFile rs, ci) where
    top  = SymPred PTop
    bot  = SymPred PBot
    conj (SymPred p) (SymPred q) = SymPred (PAnd p q)
    disj (SymPred p) (SymPred q) = SymPred (POr p q)
    neg  (SymPred p)             = SymPred (PNot p)
    models (SymPred p) (regs, ci) = evalPred p regs ci
    isBot  (SymPred p)            = symIsBot p
```

The five structural methods just compose `HsPred` constructors. `models` delegates to
`Keiki.Core`'s `evalPred` — **concrete evaluation, no solver call** — which is exactly why the
runtime hot path never touches z3. `isBot` routes through `symIsBot`, which asks z3. Witness
extraction lives in a separate `Sat` instance so the witness-free analyses keep type-checking on
register-file-existential carriers:

```haskell
instance
    (ExtractRegFile rs, KnownInCtors ci) =>
    Sat (SymPred rs ci) (RegFile rs, ci)
    where
    sat (SymPred p) = symSatExt p
```

## Solver-backed primitives

```haskell
{-# NOINLINE symIsBot #-}
symIsBot :: HsPred rs ci -> Bool

satResultIsProvablyUnsat :: SBV.SatResult -> Bool

{-# NOINLINE symSatExt #-}
symSatExt ::
    forall rs ci.
    (ExtractRegFile rs, KnownInCtors ci) =>
    HsPred rs ci -> Maybe (RegFile rs, ci)
```

Both are pure-API wrappers around an SBV solver call via `unsafePerformIO`, marked `NOINLINE`.
This is justified because every SBV query is deterministic for a given predicate and
side-effect-free outside the solver process.

`symIsBot` translates the predicate and asks z3 whether any model exists.
`satResultIsProvablyUnsat` returns `True` only for SBV's definitive `Unsatisfiable` result. It returns
`False` for `Satisfiable`, `DeltaSat`, `Unknown`, `ProofError`, and every other solver failure or
uncertainty. `symIsBot` uses that helper, so an undecided query is treated as "possibly non-empty",
never as proof that two guards are disjoint. A warm query runs in roughly ~10ms.

`symSatExt` is full **witness extraction**: on a satisfiable predicate it returns
`Just (regs, cmd)` where both are concrete values reconstructed from the SBV model. The model's
input-constructor tag is confined to the known constructor domain (`KnownInCtors ci`), so a
predicate without a `PInCtor` atom still reconstructs a real command. Since EP-44, `symSatExt`
*is* the implementation of `Keiki.Core`'s `sat` method on `SymPred`.

<Callout type="warn">
  **Strengthened in keiki 0.7.0.0 — every `Just` now satisfies `models`.** `symSatExt` concretely
  rechecks each reconstructed candidate before returning it, restoring the unconditional guarantee
  that `models p (regs, cmd) == True` for the returned pair. Previously an unrealizable free
  projection assignment, an opaque `TApp1`/`TApp2` assignment, or a non-`Sym` equality fallback
  could yield a pair that failed concrete evaluation; those cases — and a constructor-guard
  violation found during the recheck — now return `Nothing` instead.

  `Nothing` therefore means **"no concrete witness recovered"**, which is *not* proof of
  unsatisfiability. Use `symIsBot` when you need emptiness. `symSatExt` may install a relation-safe
  reconstructed owner at the matching structural path for an
  [exact projection](/docs/keiki/reference/core#exact-projections), but the final concrete recheck
  remains authoritative.
</Callout>

## Verification: was the answer actually proved?

*(`verifyPredicate` and `predicateTranslationExact`: keiki 0.6.0.0. The detailed surface:
keiki 0.7.0.0.)*

A solver call has two independent ways to fall short of a proof: the **translation** may be a sound
over-approximation rather than an exact encoding, and the **solver** may return an inconclusive
status. This surface reports both instead of collapsing them into a `Bool`.

### Translation strength

```haskell
data TranslationStrength
    = ExactTranslation
    | ConservativeOverApproximation (NonEmpty TranslationIssue)
    deriving stock (Eq, Show)

predicateTranslationReport :: HsPred rs ci -> TranslationStrength
predicateTranslationExact :: HsPred rs ci -> Bool
```

`predicateTranslationReport` combines per-node support with a **predicate-wide owner-path
analysis**, so individually exact projections are not promoted when the solver lacks their joint
relation. `predicateTranslationExact` is the `Bool` projection of it. Neither calls the solver.

Every loss of exactness gets a named, deterministic reason:

```haskell
data TranslationIssue
    = OpaqueApplication
    | UnsupportedEquality SomeTypeRep
    | UnsupportedOrdering SomeTypeRep
    | UnsupportedArithmetic SomeTypeRep
    | UnconstrainedProjection ProjectionDescriptor
    | UnsupportedProjectionDomain ProjectionDescriptor String
    | ProjectionUsedOutsideEquality ProjectionDescriptor
    | ConflictingProjectionViews ProjectionBaseDescriptor
    | DirectAndProjectedOwnerRead ProjectionBaseDescriptor
    | UnguardedProjectionInputRead ProjectionDescriptor
    deriving stock (Eq, Show)
```

    UnsupportedOrdering: { type: "SomeTypeRep", description: "PCmp over a type absent from the ordering subset." },

### The verdicts

```haskell
data PredicateVerification
    = VerifiedSatisfiable
    | VerifiedUnsatisfiable
    | UnverifiedOpaque
    | UnverifiedSolverUnknown String
    | UnverifiedSolverFailure String
    deriving stock (Eq, Show)

verifyPredicate :: HsPred rs ci -> IO PredicateVerification
```

`verifyPredicate` reports `VerifiedSatisfiable` or `VerifiedUnsatisfiable` **only** for a
predicate-globally exact translation *and* a definite solver answer. An opaque application, an
unsupported carrier, a solver timeout or `Unknown`, and a solver failure each get their own
explicitly unverified constructor.

<Callout type="warn">
  **Behaviour change in keiki 0.7.0.0.** A predicate containing a `TFieldProj` over a released
  one-way `fieldWitness` now returns `UnverifiedOpaque`. Before 0.7.0.0 such a projection was
  wrongly treated as exact whenever its *result* carrier happened to be solver-supported. Nothing
  about soundness regressed — `symIsBot` still proves such predicates empty, because definite
  unsatisfiability over the larger free-scalar domain also proves the smaller concrete domain
  empty — but `verifyPredicate` no longer overstates what was proved. Only definite UNSAT counts as
  proof, and `symIsBot`, the determinism family, and the dead-edge paths all use the same
  failure-aware solving kernel.
</Callout>

### The detailed result

```haskell
data PredicateVerificationDetail
    = PredicateSatisfiable TranslationStrength [ProjectionModel]
    | PredicateUnsatisfiable TranslationStrength
    | PredicateSolverUnknown TranslationStrength String
    | PredicateSolverFailure TranslationStrength String
    | PredicateProjectionContractViolation
        TranslationStrength
        ProjectionDescriptor
        String
    deriving stock (Show)

verifyPredicateDetailed :: HsPred rs ci -> IO PredicateVerificationDetail
```

`verifyPredicateDetailed` solves **once** and preserves the full solver status, the translation
strength, and any checked projection models. It can therefore report a definite result for a
conservative translation — something `verifyPredicate`, which is its compatibility projection,
deliberately refuses to promote.

`PredicateProjectionContractViolation` is the case worth wiring an alert to: an admitted model key
was rejected by the declared inverse or failed its getter round trip, meaning an
`ExactFieldProjection` instance does not satisfy its own laws.

```haskell
data ProjectionModel = ProjectionModel
    { projectionModelDescriptor :: ProjectionDescriptor
    , projectionModelKey :: Dynamic
    , projectionModelOwner :: Dynamic
    }
    deriving stock (Show)

projectionModelKeyAs :: (Typeable a) => ProjectionModel -> Maybe a
projectionModelOwnerAs :: (Typeable a) => ProjectionModel -> Maybe a
```

Values stay `Dynamic` because one predicate can mention unrelated projection carriers; cast with the
typed eliminators, **never** by matching on a display name. A model is decoded only after domain
membership, inverse success, and getter round-trip all pass.

<Callout type="warn">
  A `ProjectionModel` is **path-local**: a checked key/owner pair for one structural path, not a
  complete `(RegFile, ci)` witness. Ask `symSatExt` for that.
</Callout>

## Witness-extraction evidence

```haskell
class ExtractRegFile (rs :: [Slot]) where
    extractRegFile :: (forall r. (Sym r) => String -> r) -> RegFile rs

data SomeInCtor (ci :: Type) where
    SomeInCtor :: (ExtractRegFile ifs) => InCtor ci ifs -> SomeInCtor ci

class KnownInCtors ci where
    allInCtors :: [SomeInCtor ci]
```

`ExtractRegFile` materializes a `RegFile` from a name-keyed reader (the reader's input is a slot
name, the same string `translateTermSym` allocates under `"reg/" <> slotName`). Its two instances
walk the slot list — `'[]` returns `RNil`; `'(s, t) ': rs` reads the head slot's name and recurses
— so the instance is automatic for any concrete slot list whose value types are in the curated
`Sym` registry. `SomeInCtor` is an existential wrapper hiding an `InCtor`'s field-list shape while
carrying the `ExtractRegFile` evidence to rebuild it; `KnownInCtors` is the statically-known bag of
a `ci`'s constructors (`()` has a built-in singleton instance). For a User Registration aggregate,
`KnownInCtors` is a five-line list pairing the existing `inCtor*` declarations.

## Single-valuedness

```haskell
isSingleValuedSym ::
    forall phi rs s ci co.
    (BoolAlg phi (RegFile rs, ci), Bounded s, Enum s) =>
    SymTransducer phi rs s ci co ->
    Bool

withSymPred ::
    SymTransducer (HsPred rs ci) rs s ci co ->
    SymTransducer (SymPred rs ci) rs s ci co
```

A transducer is **single-valued** when, at every reachable vertex, at most one outgoing edge's
guard is satisfied for any given input. `isSingleValuedSym` checks, for every vertex and every
distinct pair of outgoing edges, that `isBot (guard e1 `conj` guard e2)`. It is
`BoolAlg`-polymorphic, so precision depends on the chosen `isBot`: wrap with `withSymPred` first to
get the exact SBV-backed answer. `withSymPred` re-tags every edge guard from the v1 `HsPred`
carrier to the v2 `SymPred` carrier, leaving the control graph and the update/output terms
unchanged. See [Single-valuedness and soundness](/docs/keiki/explanation).

## Solver-backed validation diagnostics

```haskell
checkTransitionDeterminismSym ::
    (Bounded s, Enum s, Show s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    [DeterminismWarning s]

checkDeadEdgesSym ::
    (Bounded s, Enum s, Show s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    [DeadEdgeWarning s]
```

These are the z3-backed escalations of the pure checks in
[`Keiki.Core`](/docs/keiki/reference/validate) (they require z3 on `PATH`).
`checkTransitionDeterminismSym` lifts the transducer with `withSymPred` and runs the
`BoolAlg`-polymorphic `checkTransitionDeterminism` at the `SymPred` carrier, whose `isBot` accepts
only a definitive z3 unsatisfiable result. It catches register-value-dependent overlaps the pure
path cannot prove syntactically and conservatively reports possible overlap on solver uncertainty.
`checkDeadEdgesSym` flags edges whose guard is unsatisfiable **in isolation** (via
`symIsBot`), which the structural `checkDeadEdges` misses unless the guard is literally `PBot`. It
does **not** compute the register configurations reachable at each vertex, so it still cannot catch
a guard satisfiable in isolation but never under the registers reachable there; that needs a full
reachable-state fixpoint and is left as future work.

### The detailed variants

*(keiki 0.7.0.0.)* Both analyses have a variant that keeps the full solver status and edge
attribution instead of collapsing to a warning list.

```haskell
data DeterminismAnalysisDetail s = DeterminismAnalysisDetail
    { determinismDetailEdgeA :: EdgeRef s
    , determinismDetailEdgeB :: EdgeRef s
    , determinismDetailVerification :: PredicateVerificationDetail
    }

checkTransitionDeterminismSymDetailed ::
    (Bounded s, Enum s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    IO [DeterminismAnalysisDetail s]

data DeadEdgeAnalysisDetail s = DeadEdgeAnalysisDetail
    { deadEdgeDetailEdge :: EdgeRef s
    , deadEdgeDetailVerification :: PredicateVerificationDetail
    }

checkDeadEdgesSymDetailed ::
    (Bounded s, Enum s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    IO [DeadEdgeAnalysisDetail s]
```

`checkTransitionDeterminismSymDetailed` solves `guard a .&& guard b` once for every **`Live`/`Live`**
outgoing pair (`firstIndex < secondIndex`), matching the mode scoping of the compatibility check.
`checkDeadEdgesSymDetailed` solves every edge guard once, across all modes. Note the weaker
constraints — neither needs `Show s`, because they report `EdgeRef`s rather than rendered names —
and that both live in `IO` rather than behind `unsafePerformIO`. The compatibility warnings are
projections of exactly these results, using the same single solver call and the same attribution.

## Replay-inversion ambiguity analysis

*(keiki 0.9.0.0.)* An **opt-in** SBV analysis of the two replay candidates behind an
`inversionAmbiguityWarnings` pair, against shared registers and a structurally aligned observed
head. It is never called by default validation or by runtime replay.

```haskell
checkInversionAmbiguitySymDetailed ::
    forall s rs ci co.
    (Bounded s, Enum s, Show s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    IO [InversionAnalysisDetail s]

checkInversionAmbiguitySym ::
    (Bounded s, Enum s, Show s) =>
    SymTransducer (HsPred rs ci) rs s ci co ->
    IO [TransducerValidationWarning s]
```

```haskell
data InversionAnalysisDetail s = InversionAnalysisDetail
    { iadSource :: s
    , iadLeftEdge :: EdgeRef s
    , iadRightEdge :: EdgeRef s
    , iadLeftSchemaAvailability :: WireSchemaAvailability
    , iadRightSchemaAvailability :: WireSchemaAvailability
    , iadHeadRelation :: WireHeadRelation
    , iadVerdict :: InversionProofVerdict
    , iadSolverStatus :: InversionSolverStatus
    , iadTranslationIssues :: [InversionTranslationIssue]
    }

data InversionProofVerdict
    = InversionProvedDisjoint
    | InversionNotProvedDisjoint

data InversionSolverStatus
    = InversionSolverNotRun
    | InversionSolverSatisfiable
    | InversionSolverUnsatisfiable
    | InversionSolverUnknown String
    | InversionSolverTimedOut
    | InversionSolverFailure String
```

<Callout type="warn">
  **Only a definite `InversionSolverUnsatisfiable` removes a warning.** `checkInversionAmbiguitySym`
  is a compatibility projection of the detailed form: it returns the exact existing warning values,
  dropping a pair only after a definite UNSAT for that exact source-and-edges key. It joins verdicts
  to warnings by **source vertex and both edge indices**, and **fails closed** — a missing,
  duplicate, or reordered detail retains the warning.
</Callout>

`InversionTranslationIssue` is a deterministic explanation for a relationship deliberately omitted
from the replay-pair formula. **Every omission widens the formula**, so the issue list is how you
tell "proved disjoint" from "could not model it precisely enough to try":

```haskell
data InversionTranslationIssue
    = InversionWireSchemasUnwitnessed
    | InversionUnsupportedObservedFieldCarrier Int SomeTypeRep
    | InversionOpaqueDerivedOutput InversionCandidate Int
    | InversionUnsupportedDerivedArithmetic InversionCandidate Int SomeTypeRep
    | InversionUnsupportedDerivedProjection
        InversionCandidate Int ProjectionDescriptor String
    | InversionInputConstructorIdentityUnwitnessed InversionCandidate String
    | InversionGuardTranslationIssue InversionCandidate TranslationIssue

data InversionCandidate = InversionCandidateA | InversionCandidateB
```

### What changed in the default check

The **default** `inversionAmbiguityWarnings` did not become solver-backed — it stays pure. But in
0.9.0.0 it now uses structural head classification, and suppresses a same-mode warning when exact
integral register-versus-literal conjuncts prove the two replay candidates disjoint.

<Callout type="warn">
  **This changes results on recompilation.** Unsupported and opaque guards remain conservative
  warnings, and their `tvwDetail` now identifies the construct that blocked the cheap proof. Runtime
  replay and the opt-in symbolic checker are unchanged, but a program that asserted on an exact
  warning set — or on `tvwDetail` text — may see a different one. Tests asserting that `tvwDetail`
  names `TApp` specifically are the known breakage, because the opaque-guard audit widened to cover
  a `TArith` whose carrier is outside the numeric registry.
</Callout>

### Constructor identity in translation

`PInCtor` translation now uses shared structural constructor-path decisions rather than diagnostic
names. Same-named **trusted** constructors remain distinct; unwitnessed equal names share a
conservative fallback atom, while unequal names remain independent and therefore **cannot
manufacture mutual exclusion**. Witness reconstruction uses a separate stable `KnownInCtors` ordinal,
so predicate identity is encoded independently from the trusted structural paths. Diagnostic
constructor names never become SBV identifiers.

---
title: "Recover an inspection feed"
description: "Rebuild client state after dropped updates or a disconnected socket."
---

Connect the owner's WebSocket endpoint after applying its HTTP and origin policy. Keep an HTTP poll available for recovery; a notification is not durable delivery.

## Subscribe

Send this JSON frame:

```json
{"type":"subscribe","feed":"workflows","limit":100}
```

Replace client state from the returned `snapshot`. Apply changed/removed keys from updates in sequence. A removed key only left the first-page view.

## Recover

On `queue_overflow` or a sequence gap, discard assumptions about intervening updates and re-subscribe or re-read HTTP. After connection closure, reconnect with backoff and establish a fresh snapshot before applying deltas. If capacity refuses admission, increase backoff rather than opening parallel retry sockets.

Verify recovery against the corresponding HTTP view. Matching rows establish the current observation, not a shared transaction snapshot. Tune refresh cadence using worker latency/throughput measurements. Read the [HTTP limits](/docs/keiro/reference/ops-http).

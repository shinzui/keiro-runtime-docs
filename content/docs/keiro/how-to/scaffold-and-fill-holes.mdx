---
title: "Scaffold and fill holes"
description: "Plan and emit generated modules safely, preserve create-once behavior, resolve protected and stale paths, fill typed seams, and verify the combined service with harnesses."
---

`scaffold` turns a checked spec into an overwritable deterministic layer and create-once hand-owned
behavior seams. It plans and verifies the complete output before its first write.

Keiro DSL 0.15 requires explicit adoption for existing pre-v2 generated ledgers. Before
regenerating an older service, follow [Adopt generated Haskell v2](/docs/keiro/how-to/adopt-generated-haskell-v2).
The tool preserves hand-owned Hole files; compile them against the new concise field API.

## Scaffold into the consuming source tree

```bash
keiro-dsl scaffold service.keiro --out src
```

Before writing, the command checks validation, exact/case-folded path collisions, faithful lowering,
the symbolic-operator firewall, and every existing generated target's `-- @generated` banner. A
refusal exits 1 and writes nothing.

<Callout type="warn">
If a generated path already contains hand-owned code, move or rename that file. Use
`--force-generated-overwrite` only after reviewing that exact path and intentionally adopting it as
generated output. The switch bypasses only missing-banner protection.
</Callout>

## Read the ownership report

The report distinguishes generated and hole dispositions:

```text
generated  Generated.TransferRouting.Hospital.Domain       (overwritten)
hole       TransferRouting.Hospital.Holes                  (created)
hole       TransferRouting.Hospital_load.ReadModelHoles    (skipped: already present)
firewall: OK (N generated modules scanned, 0 forbidden operators)
fragment: src/keiro-dsl-cabal-fragment.context.transfer-routing.txt
```

Generated families include aggregate `Domain`/`Codec`/`EventStream`/`Projection`/`Harness`,
read-model `ReadModelTable`/`ReadModel`/harness, process/router facts/runtime, contract/inbox/publisher,
queue/policy, and workflow facts/runtime. Exact output depends on nodes; the Cabal fragment is authoritative.

Create-once files include `Holes`, `ProcessHoles`, `RouterHoles`, and `ReadModelHoles`. Workflow
behavior remains in a separately hand-authored body module and has no generated hole stub.

## Reconcile the Cabal fragment and stale ledger

Paste the Cabal fragment's `other-modules:` and `build-depends:` blocks into the Cabal component that owns
the output. Re-run this step whenever the node inventory changes.

The per-context scaffold record powers later `stale:` output. Scaffold never deletes a stale path:

- inspect then delete a stale `generated` entry if nothing imports it;
- inspect/migrate a stale `hole` entry as hand-owned code; and
- separate output directories if a previous-spec-path note reveals two specs sharing one context.

## Fill only hand-owned seams

<Callout type="warn">
  **Aggregate transition behaviour changed owner in Keiro 0.6.0.0 (language 2, ADR-17).** Guard and
  write expressions used to be rendered as *comments* in a create-once `Holes` module, with consumer
  code owning the transducer that actually ran — so a checked expression could be quietly ignored or
  reimplemented with different semantics while Keiro's diff, replay, snapshot, and symbolic surfaces
  kept describing the source expression.

  Every version-2 aggregate transition now has **exactly one** behaviour owner: **generated
  ownership** (the default) or **explicit `implementation hole`**. Ownership is part of the checked
  semantic graph, the canonical rendering, the diff surface, the scaffold record, and the fold
  fingerprint.

  Under generated ownership the declared guard and *ordered* register writes are type-checked,
  lowered into structural Keiki terms, and **necessarily executed** by the generated transducer. A
  hand-owned module may still construct declared event and output values, but it cannot replace the
  transition predicate, reorder or override its writes, or supply an alternative transducer.

  The escape hatch is deliberately preserved rather than removed: a closed expression language cannot
  anticipate every domain predicate, so `implementation hole` remains permanently available and
  honest. What is no longer possible is a hole *silently* replacing behaviour the DSL claims to own.
  Version-1 generated output remains frozen.
</Callout>

Read each typed signature and `-- HOLE …` annotation, then use generated names/constants:

- aggregate: upcasters, explicit event fields, and any transition explicitly declared
  `implementation hole` — a generated-owned transition's guard and writes are **not** yours to fill;
- read model: qualified-table SQL, apply, and query;
- process/router: resolver/handler, stream/category, projections, and runtime assembly;
- integration: decode/handler/bridge behavior;
- queue: fan-out, raw-SQL dedupe, and job handler; and
- workflow: ordered body using generated facts.

Never put Keiki symbolic operators in generated modules. A wrong generated file means the spec or
scaffolder is wrong.

<Callout type="info">
  *(Keiro 0.7.0.0.)* Version-2 `fields(Command)` event values are now generated **directly** from a
  checked total identity mapping. Direct, aliased-wire, optional, nominal, `Time`, `Natural`, and
  structural fields no longer pass through a create-once identity-copy output hook. Explicit event
  fields stay hand-owned. If you still have an obsolete generated-identity function from an earlier
  scaffold it is *reported* and cannot affect runtime execution — but delete it.
</Callout>

For hand-written duplicate dispatch, call `confirmBenignDuplicate` with the target stream and
attempted event ID. Do not acknowledge a bare global `DuplicateEvent`.

## Run the matching harness

```bash
cabal test keiro-dsl-conformance-newsurface
```

Choose the component matching the surface (`snapshot`, `process-runtime`, `router-full`,
`readmodel-runtime`, `intake-full`, `queue-runtime`, `dispatch-full`, `workflow-full`, and so on).
Harnesses prove the generated facts and hand-owned behavior agree; scaffold alone cannot.

After every spec change: check, scaffold, reconcile stale/fragment output, compile, and rerun the
harness.

## Holes from mapped consumer types

A spec with [mapped structural types](/docs/keiro/reference/keiro-dsl-mapped-types) adds a distinct
family of hand-owned holes — a `StructuralBinding`, a `FixtureCases`, and a register `initial` per
declaration — scaffolded as **create-once** skeletons grouped by their declared owner modules.
Re-scaffolding never overwrites one; it reports granular *newly required* holes instead.

Ask what you owe rather than reading the tree:

```bash
keiro-dsl check service.keiro --explain-bindings
```

It prints each required symbol with its package, module, signature, and use sites. Both binding laws
(`bindingDomainRoundTrip`, `bindingShapeRoundTrip`) and the finite fixture cases are exercised by the
generated harness, so an unfilled or wrong binding fails the same gate as any other hole.

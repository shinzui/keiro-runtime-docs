---
title: "Check a service spec"
description: "Run the current keiro-dsl parser and semantic gate, interpret located errors and warnings, and fix topology, policy, identity, or persistence defects before scaffolding."
---

Run `check` before generating Haskell. It parses the whole `.keiro` file, validates every top-level
node and cross-node reference, prints located diagnostics, and exits nonzero when any diagnostic is
an error.

## Run and normalize

```bash
keiro-dsl check service.keiro
# OK

keiro-dsl check service.keiro --emit
# canonical accepted spec
```

Warnings print but exit 0. Errors use this form and exit nonzero:

```text
service.keiro:<line>: error[Code]: <message>
```

`--emit` combines parse, validation, and canonical pretty-printing. Scaffold runs the same gate and
writes nothing for an invalid spec.

## Fix the owning family

| Family | Representative diagnostics | Corrective move |
|---|---|---|
| names and syntax | `IdentUnsafeNormalization`, `GeneratedOccurrenceCollision`, `GeneratedOccurrenceReserved`, `VertexCtorCollision`, `FieldWireKeyCollision`, `FieldWireKeyInvalid`, duplicate-name codes | Rename to an ASCII, Haskell-safe, collision-free identifier; remove shadowed singleton/row declarations |
| aggregate/evolution | `RegisterInitialOutOfScope`, `WriteTargetNotRegister`, `StatusMapNotTotal`, `EvtVersionMissingUpcaster`, `UpcasterChainGap`, `ClockSampled` | Align declared types/references, complete or explicitly partialize the map, add contiguous upcasters with one owner per source version, inject time |
| event retirement / replay-only | `EventRetirementInProgress`, `DeprecatedEventStillEmitted`, `ReplayOnlyEmitsNothing` | Keep a live emitter while `retiring`; take the event off the *live* write path before marking it `deprecated`; give every `replay-only` transition an `emit` |
| read model | `RmShapeHashDrift`, `RmStrongInlineOnly`, `RmScopeWithoutStrong`, `RmInlineFeedUnreferenced` | Capture the printed shape, bump version for a real shape change, align consistency/feed/scope/projection ownership |
| process/router | `SagaCategoryIllegal`, `ProcessFieldBindingUnresolved`, `RouterBindingUnscoped`, `RouterReadModelUnverified`, `PolicyContradiction`, `AmbiguousMarkedBenign`, `ProcessBenignInversion`, `RouterBenignInversion` | Use a valid category, resolve typed bindings, align node/dispatch policy, route ambiguity to retry/dead-letter evidence |

<Callout type="warn">
  **`RouterReadModelUnverified` used to be unreachable.** It existed as a declared but never-emitted
  `DiagnosticCode` constructor; as of 0.11.0.0 it carries real semantics and fires when a router's
  resolved read model cannot be verified. A consumer that matched the constructor as dead code — or
  a `--deny` list that named it expecting a no-op — now sees live diagnostics.
</Callout>
| inbox/outbox | `DispositionIncomplete`, disposition inversion codes, `TopicAffinityMismatch`, `EmitSkipMissing` | Complete unique outcomes, preserve retry/poison semantics, align contract topic, add `_ => skip` |
| workqueue/dispatch | queue divergence/group/provision codes, `WqDispositionIncomplete`, dispatch reference codes | Copy the derived queue trio, align FIFO/group/provision, complete policy, resolve read-model columns and queue fields |
| workflow/operation | duplicate label/patch codes, `WorkflowContinueAsNewNotTerminal`, `AwaitSignalMismatch`, `OperationUnresolvedRef` | Stabilize labels/patch IDs, put continuation last/top-level, align signal value and target references |

See [domain/read-side notation](/docs/keiro/reference/keiro-dsl-domain-nodes) and
[runtime/integration notation](/docs/keiro/reference/keiro-dsl-runtime-nodes) for exact closed values
and defaults.

## What language 4 additionally rejects

*(Keiro 0.9.0.0.)* `check` closed a set of surfaces that were previously **accepted but unenforced** —
values a spec could declare that could not actually lower to working generated code, or that would
have produced a runtime collision nothing checked for.

The split matters when you are deciding whether to move a spec to language 4:

- **Under every language version**, a value that cannot lower to working generated code is now
  rejected. This can turn a previously-passing older spec red — that is intended; it was never going
  to generate.
- **Only under language 4**, `check` additionally enforces numeric floors, duplicate and shadowing
  rules, stable runtime identity uniqueness, Kafka and PostgreSQL naming rules, intake envelope and
  schema coupling, contract topic aliases, and the aggregate wire convention.

`DiagnosticCode` gained append-only constructors for each of these families, plus contract TypeID
admission. Exhaustive matches over it must be extended.

<Callout type="info">
  A spec that checks clean under language 3 may report new errors when its preamble moves to 4. Read
  each one as a latent defect the earlier contract could not see, not as a regression — and note that
  languages 1 through 3 keep their released acceptance behaviour exactly, so nothing forces the move.
  See [language versions](/docs/keiro/reference/keiro-dsl-language-versions).
</Callout>

## Treat warnings as review items

Warnings do not block the CLI, but they describe an acknowledged risk or forward policy:

- `ProcessBenignInversion`: duplicate/rejected delivery is being treated as success under a
  target-scoped runtime check;
- `PolicyDeadLetterUnused` / `AmbiguousFollowsRejectedPolicy`: node-level rejection behavior needs
  explicit operator understanding;
- `WqUnloggedDurability`: a database crash can empty the queue;
- `RmProjectionWithoutNode`: legacy projection wiring lacks registered read-model identity/helpers;
- `DeprecatedEventReplayHazard`: a deprecated event has **no** replay-only emitter, so stored history
  containing it is no longer replayable — restore an equivalent `replay-only` transition, or
  terminalize/truncate every affected stream before deployment
  ([retire an event type](/docs/keiro/how-to/retire-an-event-type));
- `EventRetirementInProgress`: the safe retained shape is in place; keep the eventual cleanup visible;
  and
- `ReplayOnlyCommandStillLive`: a `replay-only` transition has no live sibling for its
  `(source, command)` pair — the command is fully retired at that state, and the fuller procedure is
  event retirement.

Do not suppress these by changing generated code. Decide whether the spec policy is intentional.

<Callout type="warn">
`check` sees one spec. It cannot know whether live streams still contain a deprecated event or still
exercise a retired guard region — that is operational history, answered by the
[replay audit](/docs/keiro/how-to/audit-real-logs-before-a-deploy). That is why those two are warnings
rather than errors.
</Callout>

## Gate CI

```bash
keiro-dsl check service.keiro
```

The exit code is sufficient for a pass/fail gate — but warnings exit 0, so this alone does not gate
them. Add a warning policy explicitly:

```bash
# Pin the language floor and fail on every warning.
keiro-dsl check service.keiro --min-language 4 --deny-warnings

# Or fail on selected codes only (repeatable and comma-separated).
keiro-dsl check service.keiro --deny RouterBenignInversion,ProcessBenignInversion
```

<Callout type="warn">
  **If you already had a `--deny-warnings` job, re-read it against keiro-dsl 0.11.0.0.** Two changes
  bite:

  - An invocation that also passed `--coverage-report` used to print coverage warnings and **exit
    0**. Coverage findings are now part of the warning policy, so the same command may start failing
    — correctly.
  - `--deny CODE` now **refuses a code `check` cannot emit** rather than silently accepting it. A
    list naming a `diff`-only code (`EvtFieldWireKeyChanged`, `WorkflowShapeChanged`), a coverage
    code without `--coverage-report`, or `CoverageOpaqueGateExceeded` at all, now fails loudly. It
    was never gating on those.

  Also add `--deny RouterBenignInversion` if you relied on `--deny ProcessBenignInversion` catching
  router duplicate-disposition notices; they are a separate code now.
</Callout>

<Callout type="info">
  **Which skeletons pass `--deny-warnings` as generated?** Only `keiro-dsl new intake`, which stopped
  spelling the unenforced `required cross-check body` flags on its bind row (it used to warn
  `IntakeBindFlagUnenforced` out of the box). The router and process skeletons keep their idiomatic
  benign-inversion spellings, so they gate CI with a selective `--deny` list rather than
  `--deny-warnings`.
</Callout>

Use `/dev/stdin` for pipelines, for example:

```bash
keiro-dsl new router | keiro-dsl check /dev/stdin
```

Continue with [Scaffold and fill holes](/docs/keiro/how-to/scaffold-and-fill-holes) only after the
spec is green.

## Checking a whole service, and what you still owe

Two `check` surfaces are worth adding to the loop once a spec grows:

```bash
# Validate several .keiro files as one service contract.
keiro-dsl check service.keiro-workspace

# List every consumer-owned binding, fixture, and register-initial symbol
# that mapped structural types require you to write by hand.
keiro-dsl check service.keiro --explain-bindings

# Record structural/opaque coverage; add --fail-on-opaque to gate it.
keiro-dsl check service.keiro --coverage-report coverage.json
```

A `.keiro-workspace` manifest composes its members into one merged graph *before* validation, so every
rule applies to the whole service rather than file by file — see [service
workspaces](/docs/keiro/reference/keiro-dsl-workspaces). `--explain-bindings` is the direct answer to
"the scaffold left me holes; what exactly do I owe and where is each used?" — see [mapped consumer
types](/docs/keiro/reference/keiro-dsl-mapped-types).

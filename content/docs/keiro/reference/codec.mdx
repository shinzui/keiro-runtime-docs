The types and functions on this page live in `Keiro.Codec` (re-exported from `Keiro`). For the
narrative — value-not-typeclass, the schema-version stamp, the upcaster chain — see
[Codec and schema evolution](/docs/keiro/explanation/codec-and-schema-evolution).

## `Codec`

Everything a stream needs to serialize, deserialize, and migrate its events. It is a **record value**,
not a typeclass.

## `Upcaster`

One rung of an upcaster chain: the source version it upgrades **from**, and a pure migration.

```haskell
type Upcaster = (Int, EventType -> Value -> Either Text Value)
```

A rung receives the **stored** `EventType` alongside the payload, so one codec can own several event
kinds without guessing the kind from payload fields. That is how `keiro-dsl` lowers several
same-version event bumps into one rung: the generated dispatcher selects the event-specific upcaster
by tag and passes every other kind through byte-for-byte.

<Callout type="warn">
Upcasters are **permanent compatibility code**. A rung lives while any stored payload at its source
version persists — which, for an append-only log without truncation, means forever. Keiro has no
mechanism for declaring an old stored version unsupported.
</Callout>

<Callout type="warn">
Use `mkCodec` for production codecs. It validates `schemaVersion >= 1`, duplicate event tags,
duplicate upcaster sources, out-of-range upcaster sources, and missing rungs before runtime. The raw
record constructor remains exported for low-level tests and escape hatches.

You get this check whether or not you call `mkCodec` yourself: `validateEventStreamWith` runs it at
the stream boundary, so `mkEventStream`, `mkEventStreamWith`, and `mkEventStreamOrThrow` all fail
construction on a misconfigured codec. Only `mkEventStreamUnchecked` bypasses it.
</Callout>

```haskell
mkCodec :: Codec e -> Either CodecConfigError (Codec e)

data CodecConfigError
  = CodecSchemaVersionInvalid !Int
  | CodecDuplicateEventTypes ![EventType]
  | CodecDuplicateUpcasterSources ![Int]
  | CodecUpcasterSourceOutOfRange !Int !Int
  | CodecUpcasterChainIncomplete ![Int] !Int
  deriving stock (Generic, Eq, Show)
```

`CodecUpcasterChainIncomplete missing target` means the codec says its current `schemaVersion` is
`target`, but one or more source-version rungs in `[1 .. target - 1]` are absent. That turns
"we will find out during hydration" into an explicit construction failure.

## `CodecError`

```haskell
data CodecError
  = UnknownEventType !EventType ![EventType]
  | InvalidSchemaVersion !Int
  | UnknownVersion !Int
  | VersionAhead !Int !Int
  | UpcasterError !Int !Text
  | DecodeFailed !Text
  | GapInUpcasterChain !Int !Int
  | IncompleteUpcasterChain !Int !Int
  | MalformedSchemaVersionStamp !Value
  | NonObjectCallerMetadata !Value
  deriving stock (Generic, Eq, Show)
```

<Callout type="warn">
An unknown `eventType` on read is **fatal** (`UnknownEventType`), carrying the offending tag and the
allowed set. There is no "skip unknown events" mode.
</Callout>

## Functions

```haskell
encodeForAppend             :: Codec e -> e -> Either CodecError EventData
encodeForAppendWithMetadata :: Codec e -> Maybe Value -> e -> Either CodecError EventData
decodeRecorded              :: Codec e -> RecordedEvent -> Either CodecError e
decodeRaw                   :: Codec e -> EventType -> Int -> Value -> Either CodecError e
migrateToCurrent            :: Codec e -> EventType -> Int -> Value -> Either CodecError Value
extractSchemaVersion        :: RecordedEvent -> Either CodecError Int
metadataFor                 :: Int -> Maybe Value -> Either CodecError Value
```

Behavior to know:

- `encodeForAppendWithMetadata` stamps `schemaVersion` into fresh or supplied metadata via
  `metadataFor`, and the **schema-version key always wins** over any clashing caller key, so the
  version on disk is authoritative. Caller metadata must be a JSON object; non-object metadata is
  rejected with `NonObjectCallerMetadata`.
- `decodeRecorded` reads the stamped version (`extractSchemaVersion`, defaulting to `1` only when
  metadata is absent or lacks the key), runs `migrateToCurrent` (replay upcasters `n, n+1, …` up to
  `schemaVersion`), then the current event-type-aware `decode`. A present malformed stamp is
  `MalformedSchemaVersionStamp`, not a silent default.
- A stored payload with a source version greater than the codec's current `schemaVersion` fails with
  `VersionAhead`; a chain that simply ends before the target fails with `IncompleteUpcasterChain`.

The worked example is the `jitsurei` order codec (`orderCodec`, `schemaVersion = 2`,
`upcasters = [(1, const upcastOrderPlacedV1)]` — the `const` discards the `EventType` because that
codec migrates a single kind at this rung); see
[Evolve an event schema](/docs/keiro/how-to/evolve-an-event-schema).

<Callout type="warn">
`schemaVersion` is **aggregate-global**, not per event kind. When a second event kind changes, assign
it `aggregate-max + 1`, not that event's private previous version plus one. That keeps every payload
stamp aligned with the one aggregate-wide chain.
</Callout>

A decode golden proves an old payload still *decodes*. It never proves that the decoded event still
has an inverting edge or folds to the same state — that is a separate question answered by
[the replay audit](/docs/keiro/reference/replay-audit). See
[Evolution and replayability](/docs/keiro/explanation/evolution-and-replayability) for how the two
gates divide the work, and
[Deploy ordering](/docs/keiro/reference/deploy-ordering) for why a codec bump cannot ride an ordinary
rolling deploy.

## Nominal bindings

`Keiro.Codec.Nominal` is re-exported from `Keiro`.

This is the published contract between a **consumer-owned** nominal domain type and the Keiro-owned
wire representation sitting immediately inside the JSON boundary. `keiro-dsl` generates code against
it, and the generated conformance harness checks a consumer's binding with it.

```haskell
data NominalBinding domain representation = NominalBinding
    { nominalToRepresentation :: !(domain -> representation)
    , nominalFromRepresentation :: !(representation -> domain)
    }
```

<Callout type="warn">
  **Both directions must be total, and the pair must be an isomorphism.** A consumer type whose
  constructor *rejects*, *normalizes*, or *identifies* values of the representation is **refined**,
  not nominal, and must not use this API — a smart constructor that lowercases, trims, or validates
  breaks the round trip in a way the fixture corpus may not reveal. The generated codec remains the
  only authority for JSON parsing and rendering; a binding never sees JSON.
</Callout>

The two laws are executable:

```haskell
nominalDomainRoundTrip ::
    (Eq domain) => NominalBinding domain representation -> domain -> Bool
nominalRepresentationRoundTrip ::
    (Eq representation) => NominalBinding domain representation -> representation -> Bool
```

A generated harness drives them from a labelled fixture corpus:

```haskell
data NominalFixture domain = NominalFixture
    { nominalFixtureLabel :: !Text
    , nominalFixtureWire :: !Value
    , nominalFixtureDomain :: !domain
    }
    deriving stock (Eq, Show)

newtype NominalFixtureCases domain = NominalFixtureCases
    { nominalFixtureCases :: NonEmpty (NominalFixture domain)
    }
    deriving stock (Eq, Show)
```

<Callout type="info">
  The corpus is **evidence, not proof**. It exercises the binding contract over the cases you
  declare and says nothing about values outside them. It is non-empty by construction, so a binding
  cannot be admitted with no evidence at all.
</Callout>

Stability: types and record field names are stable within a major version. Additions are permitted;
a rename or a semantic change requires a major bump and a coordinated `keiro-dsl` release.

## The enforced identifier domain

`Keiro.Codec.IdDomain` is re-exported from `Keiro`. This is the **frozen**
runtime contract for canonical prefix-bearing TypeID-v7 identifiers — the domain that `keiro-dsl`
[Language 6](/docs/keiro/reference/keiro-dsl-language-versions) enforces on every generated
prefix-bearing ID.

```haskell
enforcedIdDomainVersion :: Text
enforcedIdDomainVersion = "keiro-dsl/id-domain/typeid-v7/1"
```

The contract is a record, built for a prefix by `typeIdV7Domain`:

```haskell
data IdNormalization = CanonicalLowercase
    deriving stock (Eq, Ord, Show)

data IdDomainContract = IdDomainContract
    { idDomainVersion :: !Text
    , idDomainPrefix :: !Text
    , idDomainSeparator :: !Char
    , idDomainSuffixLength :: !Int
    , idDomainMaxLength :: !Int
    , idDomainNormalization :: !IdNormalization
    , idDomainJsonRepresentation :: !Text
    }
    deriving stock (Eq, Ord, Show)

typeIdV7Domain :: Text -> IdDomainContract
```

<TypeTable
  type={{
    idDomainVersion: { type: "Text", description: "Always the frozen \"keiro-dsl/id-domain/typeid-v7/1\"." },
    idDomainPrefix: { type: "Text", description: "The declared prefix, e.g. \"inc\"." },
    idDomainSeparator: { type: "Char", description: "'_' — exactly one underscore between prefix and suffix." },
    idDomainSuffixLength: { type: "Int", description: "26 — the Crockford base32 suffix length." },
    idDomainMaxLength: { type: "Int", description: "26 for an empty prefix, otherwise prefix length + 27." },
    idDomainNormalization: { type: "IdNormalization", description: "CanonicalLowercase — the only admitted normalization." },
    idDomainJsonRepresentation: { type: "Text", description: "\"canonical-json-text\"." },
  }}
/>

Admission is deliberately narrow. A value is accepted only when it is **canonical lowercase TypeID
text**, carries the **declared prefix and exactly one underscore**, has a **26-character Crockford
suffix**, and its UUID satisfies the **v7 version and variant bits**. Each rejection is named:

```haskell
data IdDomainFailure
    = IdDomainNonCanonical
    | IdDomainWrongPrefix !Text !Text     -- expected, actual
    | IdDomainMalformed !Text
    | IdDomainNotUuidV7 !Text
    deriving stock (Eq, Ord, Show)

idDomainAcceptsText :: IdDomainContract -> Text -> Bool
validateIdDomainText :: IdDomainContract -> Text -> Either IdDomainFailure ()
```

<Callout type="info">
  `IdDomainNonCanonical` and `IdDomainMalformed` are genuinely different answers. Text that parses
  only *after* lowercasing — and then round-trips — is reported as non-canonical rather than
  malformed, so an operator can tell "your producer is upper-casing" apart from "this is not a
  TypeID at all". The underlying dependency separates canonical parsing from the UUID version check,
  and both steps are part of this frozen contract.
</Callout>

Two parsers construct a **prefix-indexed** `KindID` — and only after Keiro's
admission policy has already succeeded, so a generated consumer cannot accidentally widen the domain
by reaching for the dependency's own parser:

```haskell
parseKindIdV7Text ::
    forall prefix. (ValidPrefix prefix) => Text -> Either IdDomainFailure (KindID prefix)
parseKindIdV7Value ::
    forall prefix. (ValidPrefix prefix) => Value -> Parser (KindID prefix)
```

`parseKindIdV7Value` is the one generated integration-contract fields use. Paired with Aeson's
`explicitParseField`, it attaches the **owning JSON field path** to the stable failure, so a rejected
identifier says which field it came from.

Two helpers close the loop with the rest of the stack:

```haskell
idDomainTextPattern :: IdDomainContract -> Either DomainConstructionError TextPattern
idDomainSampleText :: IdDomainContract -> Text
```

`idDomainTextPattern` yields the matching **exact Keiki projection domain**
([`TextPattern`](/docs/keiki/reference/projection-domain)) — that is what lets a generated aggregate
guard comparing two same-declaration IDs reach a *verified* symbolic result rather than a
conservative one. `idDomainSampleText` renders a valid sample for scaffolded fixtures.

## Frozen checked value codecs

Keiro 0.18 exposes three frozen wire policies from `keiro-core`; their modules are also
re-exported by the `keiro` package for generated consumers. The declaration-owned codecs run
before the total consumer binding. Their policy identities participate in mapped wire fingerprints.

### `Keiro.Codec.CalendarDay`

`keiro-core/calendar-day/1` covers the complete `Day` carrier without timezone conversion.
The reader accepts a signed year with at least four ASCII digits, redundant leading zeroes and
an optional plus sign, with exactly two month/day digits. Invalid Gregorian dates fail. The
writer removes redundant signs/zeroes while padding short years to four digits; years are unbounded.
`parseCanonicalCalendarDayText` additionally requires exact writer spelling.

```haskell
calendarDayCodecPolicyIdentity :: Text
renderCalendarDay :: Day -> Text
encodeCalendarDay :: Day -> Value
parseCalendarDayText :: Text -> Either Text Day
parseCanonicalCalendarDayText :: Text -> Either Text Day
parseCalendarDay :: Value -> Parser Day
```

### `Keiro.Codec.TextSet`

`keiro-core/text-set/1` accepts JSON string arrays in any order, including duplicates, and
constructs the set before binding or replay. The writer emits unique strings in ascending Unicode
code-point order. It performs no Unicode normalization or case folding; invalid elements retain
Aeson's located diagnostics.

```haskell
textSetCodecPolicyIdentity :: Text
encodeTextSet :: Set Text -> Value
parseTextSet :: Value -> Parser (Set Text)
```

### `Keiro.Codec.Base16Bytes`

`keiro-core/base16-bytes/1` admits empty and even-length upper/lowercase hexadecimal text.
The writer is lowercase and preserves all bytes, including leading zeroes. Odd lengths, prefixes,
whitespace, invalid digits and non-string JSON are rejected. `Keiro.Codec.Refined` in
`keiro-core` is a facade over this same API, not a consumer validation callback.

```haskell
base16BytesCodecPolicyIdentity :: Text
decodeBase16BytesText :: Text -> Either Base16BytesError ByteString
encodeBase16Bytes :: ByteString -> Value
parseBase16Bytes :: Value -> Parser ByteString
renderBase16Bytes :: ByteString -> Text
```

```haskell
data Base16BytesError
  = Base16BytesOddLength !Int
  | Base16BytesInvalidDigit !Int !Char
  deriving stock (Eq, Show)
```

## Explicit ID admission

Keiro 0.18 adds a closed admission selector to `Keiro.Codec.IdDomain`. It controls accepted
existing TypeID values, not identifier generation. Use the smart contract constructors rather than
manually filling the record.

```haskell
data IdAdmission
  = TypeIdV7
  | TypeIdV5OrV7
  deriving stock (Eq, Ord, Show)

data IdNormalization = CanonicalLowercase
  deriving stock (Eq, Ord, Show)

data IdDomainContract = IdDomainContract
  { idDomainAdmission :: !IdAdmission,
    idDomainVersion :: !Text,
    idDomainPrefix :: !Text,
    idDomainSeparator :: !Char,
    idDomainSuffixLength :: !Int,
    idDomainMaxLength :: !Int,
    idDomainNormalization :: !IdNormalization,
    idDomainJsonRepresentation :: !Text
  }
  deriving stock (Eq, Ord, Show)

data IdDomainFailure
  = IdDomainNonCanonical
  | IdDomainWrongPrefix !Text !Text
  | IdDomainMalformed !Text
  | IdDomainNotUuidV7 !Text
  | IdDomainVersionNotAdmitted !Char
  | IdDomainVariantNotRfc4122 !Char
  deriving stock (Eq, Ord, Show)
```

```haskell
typeIdV7Domain :: Text -> IdDomainContract
typeIdV5OrV7Domain :: Text -> IdDomainContract
validateIdDomainText :: IdDomainContract -> Text -> Either IdDomainFailure ()
parseKindIdText :: forall prefix. (ValidPrefix prefix) => IdDomainContract -> Text -> Either IdDomainFailure (KindID prefix)
parseKindIdValue :: forall prefix. (ValidPrefix prefix) => IdDomainContract -> Value -> Parser (KindID prefix)
```

`enforcedIdDomainVersion` remains `keiro-dsl/id-domain/typeid-v7/1`; `v5OrV7IdDomainVersion` is
`keiro-dsl/id-domain/typeid-v5-or-v7/1`. Both enforce prefix, canonical lowercase Crockford text,
length and RFC variant. `parseKindIdV7Text` and `parseKindIdV7Value` preserve the v7 convenience API.
The runtime validator and `idDomainTextPattern` derive from the same closed admission table.

Under Language 6:

```keiro-dsl
id LegacyId prefix=legacy domain=typeid-v5-or-v7
```

Omitting `domain` preserves v7 and released identity bytes; explicit `domain=typeid-v7` selects
the same domain. The selected domain follows direct/nested fields, keyed maps, workqueues,
query types, router identity and declared contract IDs. Anonymous `typeid "prefix"` fields retain v7.

`IdDecl.admission`, `NominalRepresentation.IdRepresentation` and `NominalLeafKind.NominalIdLeaf`
carry `IdAdmission`; direct construction and exhaustive matches need updating.
`EnforcedTypeIdV7TextDomain` is renamed to `EnforcedTypeIdTextDomain`; the default v7 serialized
equality identity remains unchanged. The new
`IdDomainContract.idDomainAdmission` field and error constructors are breaking source changes.
Widening to v5-or-v7 preserves retained reads but new v5 writes can break old readers; narrowing
can reject retained v5 history. Both raise `IdDomainContractChanged`, with direction-specific
rollout guidance, and participate in fold/replay identity. Keep old readers reachable until the
retained-history and rolling-reader evidence permits retirement.

See [checked mappings](/docs/keiro/reference/keiro-dsl-mapped-types) and
[replay compatibility evidence](/docs/keiro/reference/replay-compatibility).

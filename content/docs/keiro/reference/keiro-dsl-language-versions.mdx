title: "keiro-dsl language selection"
description: "Select Language 6 and inspect its syntax and runtime profiles."

Language 6 is the only supported DSL language in these release docs.
Every complete source file must declare it before `context`:

```keiro-dsl
language keiro-dsl 6
context service
```

Comments and blank lines may precede the declaration.
Do not omit the declaration. Use the same declaration in every workspace member.

## Validation

```bash
keiro-dsl check service.keiro --min-language 6 --deny-warnings
keiro-dsl inspect service.keiro --format=json
```

`check` rejects a source below the specified minimum.
`inspect` reports the declared language, effective language, and selected profiles.
Require declared and effective version `6` in release sources.

The checked toolchain still reports Language 6 support as `candidate`.
This report value describes the upstream registry. It does not change the documentation support policy.

## Selected profiles

| Profile | Language 6 value | Purpose |
| --- | --- | --- |
| Syntax | `keiro-dsl/syntax-profile/5` | Selects the accepted grammar. |
| Runtime semantics | `keiro-dsl/runtime-semantics/5` | Selects checked runtime capabilities. |

A profile number is an internal identifier. It is not a source language version.
For example, syntax profile 5 belongs to source Language 6.

Use `languageSupportsFeature` to query a syntax capability.
Use `runtimeProfileHasCapability` to query a runtime capability.
The profile constructors are private.

The [Language 6 capability matrix](/docs/keiro/reference/keiro-dsl-language-6) describes each supported feature.
The [coverage map](/docs/keiro/reference/keiro-dsl-coverage-map) lists the checked modules and registries.

## Runtime capability profiles

Language 6 includes generated ID domains, nominal equality, contract ID domains, and strict specification validation.
It also includes projection catalogs, typed command outcomes, and separate delivery and query policies.
The additional capabilities cover delegated inboxes and structural mappings.

Some runtime capabilities contribute a segment to the aggregate fold fingerprint.
`ProjectionCatalogRuntime` contributes `semantic-contract:keiro-dsl/projection-catalog/1`.
The seven additional Language 6 runtime capabilities contribute no profile fold segment.

Declaration-specific identities still affect persisted contracts.
For example, a wire shape, ID domain, or reaction change can require replay or deployment coordination.
Run `diff` and the conformance harnesses after such a change.

## Field aliases

An aggregate field may declare a Haskell selector and a wire key:

```keiro-dsl
aggregate Order
  regs
  states Open
  command Place { orderId haskell orderId as "order_id" }
  event Placed = fields(Place)
  Open -- Place -->
    emit Placed
    goto Open
```

The alias changes the indicated source or wire surface.
Review the corresponding compatibility findings before deployment.

## Starter files

The checked `new` command uses `currentStableLanguageVersion`.
That selector still emits an older preamble.
After `new`, set the first declaration to `language keiro-dsl 6` and run `check --min-language 6`.
`currentAuthoringLanguageVersion` returns 6 for library authoring tools.

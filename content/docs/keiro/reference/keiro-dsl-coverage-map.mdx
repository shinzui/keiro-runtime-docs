This page is the completeness index for the developer-visible `keiro-dsl` surface at Keiro
0.17.0.0. It maps the closed registries and every public library module to the reference that
explains its behavior. Detailed notation and signatures stay on the focused owning pages.

The language-feature registry has 16 constructors: four introduced by Language 2, one by Language
4, six by Language 5, and five by Candidate Language 6. The runtime-capability registry has nine:
two introduced by runtime semantics 2, two by 3, three by 4, and two by Candidate runtime semantics
5. Profile membership is monotone; a feature's version is a minimum, not an upper bound.

## Diagnostics are a closed registry

`DiagnosticCode` derives `Enum` and `Bounded`; `diagnosticCodeText`, `parseDiagnosticCode`, and
`diagnosticOrigin` make every spelling and emitting pipeline machine-checkable. `check --deny`
rejects diff-only or otherwise unreachable codes, and `diff --deny` rejects non-diff codes. This
prevents a CI policy from silently naming a diagnostic its command cannot emit.

The focused reference pages list codes beside the feature or evolution rule they explain. The enum
itself remains the exhaustive spelling registry; duplicating hundreds of constructors here would
create a second, drift-prone authority without explaining their semantics.

## Coverage maintenance contract

When `Node`, `LanguageFeature`, `RuntimeCapability`, CLI `Command`, `skeletonKinds`, or the Cabal
`exposed-modules` list grows, this page and the linked owning reference must grow in the same docs
sync. A feature is not considered covered merely because its name appears here: the owning page must
state its syntax or type, validation, generated/runtime behavior, persistence or identity effects,
and evolution/rollout behavior where applicable.

`Keiro.Dsl.GeneratedHaskellLanguage` is intentionally absent from the 60-module list: it belongs to
a separate private Cabal library used by the generated-Haskell migration machinery and is not an
installed public module.

This page owns every non-aggregate runtime node. References to aggregates, projections, read models,
contracts, commands, queues, workflows, and fields are resolved by `check`.

Stable Languages 1–5 and Candidate Language 6 share this page. Candidate-only clauses are labelled
where they occur and summarized in the [complete Language 6 matrix](/docs/keiro/reference/keiro-dsl-language-6).

<Callout type="warn">

  generated code previously handed you a stringly-typed value now hand you a closed, generated type.
  The hand-written `Keiro.*` runtime APIs are unchanged; this is a **regeneration** break, so
  re-scaffold and fix the resulting type errors.

  - **Workqueue:** `jobOutcomeFor` takes a **queue-named closed outcome sum** rather than `Text`.
  - **Inbox:** generation exposes closed **outcome** and **detailed disposition** sums.
  - **Aggregate stream categories:** fixed to their generated event-stream phantom. `PMCommand` and
    router consumers use the new `<aggregate>CommandCategory` instead of a `Text` category.
  - **Workflow:** `workflowFacts` becomes the generated `WorkflowFacts` **record**.

  Generated contract **topic constants** are now exported too, so a consumer no longer retypes a
  topic string. And generated decoders report the **rejected value**, the **complete expected set**,
  and the **Aeson field path** on failure — a decode error now says which field, what it saw, and

</Callout>

## Process and timer

Language 1–5 keep the legacy process body and positional `emitIndex` dispatch identity shown below.
Candidate Language 6 adds a separate `reactions version <n>` body that lowers to
`Keiro.ProcessManager.Reaction`:

```keiro-dsl
process IncidentReaction
  name "incident-reaction"
  reactions version 1
  input IncidentReported { incidentId:IncidentId severity:Severity }
  correlate input.incidentId via idText
  saga IncidentSaga category "incidentSaga"
  target Incident
  projections [ ]
  on IncidentReported
    when input.severity == Severity.Sev1
      advance RecordCritical { incidentId }
      dispatch Incident@input.incidentId EscalateIncident { incidentId }
        on-appended AckOk ; on-duplicate AckOk ; on-failed Retry
    otherwise
      no-action
  dispatch-id strategy=uuidv5 from=(name, correlationId, sourceEventId, targetStreamName, occurrence)
  rejected => halt
  poison => halt
```

### Reaction validation

The checked `Keiro.Dsl.ProcessReaction` phase makes the following invalid before scaffolding:

- a duplicate input declaration, `on` block, or timer name;
- an `on` block for an unknown input, or a declared input with no `on` block;
- a non-Boolean guard, a guarded chain without a final `otherwise`, or an `otherwise` before the
  final arm;
- unknown saga/target aggregates, commands, fields, or structurally invalid mappings;
- an incomplete timer payload, a schedule/cancel naming an unknown timer, a timer without the
  process-level retry policy, or a retry policy with no timers; and
- reuse of any timer-ID or fired-event-ID prefix within the process.

An arm is `no-action` or an ordered `advance` plus follow-ups. Follow-ups are `dispatch`, `schedule`,
insert-only `schedule … once`, or `cancel`. An `advance … accepted { … }` continuation is generated
only when the saga transition is generated-owned; a hole-owned transition leaves an explicit
accepted-event proof obligation and marks reaction verification `custom-unverified`.

```keiro-dsl
  on IncidentReported
    advance RecordIncident { incidentId }
    schedule escalation fireAt input.raisedAt + 5m { incidentId detail }
    schedule reminder once fireAt input.raisedAt + 60m { incidentId }

  on ResponderAcked
    cancel reminder

  timers max-attempts 5 dead-letter "incident timer exceeded ceiling"

  timer escalation
    id uuidv5 "incident-escalation-timer:" <> correlationId
    payload { kind="escalation" incidentId:IncidentId detail:Text }
    fire dispatch Incident@correlationId EscalateIncident { incidentId }
      fired-event-id uuidv5 "incident-escalation-fired:" <> correlationId
      on-ok Fired ; on-reject Fired ; on-ambiguous Retry ; on-error Retry ; not-mine Retry
    decode unknown-status => Cancelled
```

Accepted scheduling and cancellation share the saga append transaction. Rearming `schedule`
updates the due request; `schedule … once` is insert-only; `cancel` addresses the same deterministic
timer identity. `max-attempts` is positive and the dead-letter text is operator guidance. Unknown
timer status decodes to the declared posture.

### Frozen reaction fingerprint

`processReactionFingerprintFrom` is the lowercase SHA-256 hex digest of
`canonicalReactionSurface`. The canonical surface starts with `reaction-v1` and length-frames every
field by its UTF-8 byte length, so adjacent text and non-ASCII values cannot alias. It includes the
reaction version, input names/types, ordered reactions, guard expressions, arm bodies, ordered
follow-ups, the target-keyed source-event-occurrence identity-model tag, and timer identities,
payloads, fire commands, and dispositions. Source locations and formatting are absent.

The operator-only `timers max-attempts … dead-letter …` policy is deliberately outside this
fingerprint. Its evolution has the separate `ProcessTimerCeilingChanged` advisory and does not claim
to change reaction replay identity.

### Timer and fired-event UUIDs

Timer IDs and fired event IDs do **not** hash the reaction fingerprint. Generated code derives each
one independently as:

```text
UUIDv5(namespaceURL,
       utf8(byteLength(prefix) + ":" + prefix
          + byteLength(correlationId) + ":" + correlationId))
```

The byte lengths are decimal UTF-8 lengths, not character counts. The concatenated text is passed
through Keiro's frozen `identitySeedBytes` encoder. A timer uses its `id uuidv5 "<prefix>" <>
correlationId` prefix; its fired command uses the separate `fired-event-id` prefix. This framing
makes pairs such as (`"ab"`, `"c"`) and (`"a"`, `"bc"`) distinct, while UUIDv5 makes retries
reproduce the same IDs. Prefix reuse is rejected because it would collapse two declared identity
domains.

### Generated runtime contract

Scaffolding generates the closed input ADT, pure reaction function, typed
`ReactiveProcessManager`, runtime worker, reaction version/fingerprint constants, timer request and
payload codecs, deterministic timer fire functions, and a process harness. The only create-once
reaction hole decodes `RecordedEvent` into the closed input type. Dispatch identity is fixed to
`(name, correlationId, sourceEventId, targetStreamName, occurrence)`; follow-up order supplies the
occurrence component.

### Reaction evolution and rollout

Moving an existing manager name from the legacy body to reactions changes the dispatch identity
model and is breaking. A lower reaction version, a semantic fingerprint change without a version
bump, removal of a scheduled timer, or a timer/fired-event prefix change is also breaking.

With the required version bump, a fingerprint change is advisory. Removing a reaction, changing a
guard, reordering arms, or changing arm count/fan-out is advisory too. Those five advisory codes
carry the `drain-required` rollout constraint because redelivery through old and new binaries can
choose or emit different work. Timer payload drift instead carries `producer-last`; a timer retry
ceiling or window change is advisory without an invented drain constraint. See the exact code table
in [`diff`](/docs/keiro/reference/keiro-dsl-cli#non-breaking-advisories).

### Legacy process body

```keiro-dsl
process HospitalSurge
  name "hospital-surge"
  input SurgeInput { hospitalId availableIcuBeds:Int observedAt:Time }
  correlate input.hospitalId via idText
  saga Surge category "hospitalSurge"
  target Hospital
  projections [ hospitalReadiness ]
  on SurgeInput
    advance NoteSurgeThreshold { hospitalId timerId=timer.id }
    dispatch Hospital@input.hospitalId ActivateSurge { hospitalId }
      on-appended AckOk ; on-duplicate AckOk ; on-failed Retry
    schedule surgeFollowUp
  dispatch-id strategy=uuidv5 from=(name, correlationId, sourceEventId, emitIndex)
  rejected => halt
  poison => halt
  timer surgeFollowUp
    id uuidv5 "hospital-surge-timer:" <> correlationId
    fireAt input.observedAt + 5m
    payload { kind="hospital-surge-follow-up" hospitalId }
    fire dispatch Surge@correlationId MarkSurgeTimerFired { hospitalId timerId }
      fired-event-id uuidv5 "hospital-surge-fired:" <> correlationId
      on-ok Fired ; on-reject Fired ; on-ambiguous Retry ; on-error Retry ; not-mine Retry
    decode unknown-status => Cancelled
    max-attempts 5 dead-letter "surge timer exceeded ceiling"
```

Durations are decimal digits plus `s`, `m`, or `h`. The fire time must use a declared `:Time` input;
dispatch IDs are runtime-owned. Saga categories are non-empty camelCase without `-`, `:`, whitespace,
control characters, or `$all`; generated category constants are used with `entityStream`.

<Callout type="warn">
  **keiro-dsl 0.11.0.0 refuses four spellings the grammar accepted but no runtime implements.** Each
  warns on released languages below 4 and **errors from language 4 on**. The spelling that matches
  the runtime stays accepted and silent in every case.

  | Code | Refused spelling | Why |
  | --- | --- | --- |
  | `DispatchOnAppendedUnsupported` | `on-appended` anything other than `AckOk`, on both process and router dispatch rows | a successful append is always acked |
  | `TimerNotMineUnsupported` | `not-mine Fired` | the timer worker marks a timer `Fired` only when the fire action returns an appended event id |
  | `DecodeBodyPostureUnsupported` | `intake … body lenient` | generated codecs decode a body strictly |
  | `IntakeBindHeaderUnknown` | `bind … from header "x"` naming a header outside keiro's canonical envelope set | the Kafka inbox reads a fixed header set and cannot be remapped |

  `DiagnosticCode` gains all four; exhaustive matches must be extended.
</Callout>

<Callout type="warn">
  **A process `dispatch-id` line is now checked as strictly as a router's.** It must read exactly:

  ```text
  dispatch-id strategy=uuidv5 from=(name, correlationId, sourceEventId, emitIndex)
  ```

  — the tuple `Keiro.ProcessManager` actually derives from. Previously *any* strategy identifier and
  *any* tuple parsed and were then discarded, so a spec could claim a derivation it did not get.
  Routers keep their own `(name, key, sourceEventId, targetStreamName, occurrence)`. A process spec
  that wrote anything else is now a **parse error**.
</Callout>

Dispatch outcomes are `AckOk`, `Retry`, or `deadLetter "reason"`. Node-level `rejected` and `poison`
are each `halt`, `deadLetter`, or `skip`; rejection-class failures include `CommandAmbiguous` for an
ordinary dispatch. Timer outcomes are `Fired` or `Retry`, but `on-ambiguous Fired` is invalid.
`max-attempts` must be at least 1.

Generated: `Process`, `ProcessHarness`, and aggregate modules. Hand-owned: `ProcessHoles` for handle,
deadline/fire behavior, SQL, and runtime assembly. Pass generated worker options to
`runProcessManagerWorkerWith`. A manual duplicate path must call `confirmBenignDuplicate` against
the target stream.

## Router

```keiro-dsl
router PagingRouter
  name "jitsurei-paging"
  input IncidentRaised { incidentId service }
  key input.incidentId via idText
  resolve stable via read-model service_oncall row { responderId }
  target Page
  projections [ ]
  dispatch-each SendPage { incidentId=input.incidentId responderId=resolved.responderId }
    on-appended AckOk ; on-duplicate AckOk ; on-failed Retry
  dispatch-id strategy=uuidv5 from=(name, key, sourceEventId, targetStreamName, occurrence)
  rejected => deadLetter
  poison => halt
```

The resolver source is `read-model <name>` or `hole`. `stable` is mandatory: retries dedupe repeated
targets but a drifting resolver accumulates the union of attempt outputs. Bindings read declared
`input.*`, `resolved.*`, or quoted literals. Name, key, target, and target-based dispatch identity
are replay-sensitive.

Generated: `Router`, `RouterHarness`. Hand-owned: `RouterHoles` plus the effectful resolver and
assembled runtime value. Pass generated options to `runRouterWorkerWith`. Target/command/projection,
key/row/binding, read-model, and policy consistency are checked.

## Contract, intake, emit, and publisher

### Contract

```keiro-dsl
contract emergency {
  schemaVersion 1
  discriminator messageType
  topic incidentEvents "emergency.incident.events"
  event IncidentTransferNeedDeclared on incidentEvents {
    incidentId: typeid "inc"
    region: text
    redCount: int
  }
}
```

Contract field types are `typeid "prefix"`, `text`, or `int`. Candidate Language 6 also lets a field
name a declared `id`:

```keiro-dsl
id TemplateId prefix=template

contract templates {
  schemaVersion 1
  discriminator messageType
  topic templateEvents "templates.events"
  event TemplateClaimed on templateEvents {
    templateId: TemplateId
    legacyTemplateId: typeid "template"
  }
}
```

The declared form reuses the ID's TypeID prefix and nominal Haskell type instead of repeating an
anonymous prefix. It must resolve to an `id`; an enum, nominal scalar, mapped declaration, or unknown
name is `ContractIdUnknown`. Changing the declared ID's prefix or its selected ID-domain contract is
a public contract evolution finding. Topic aliases map to actual Kafka topics; events declare their topic affinity.
Generated `Contract` modules own payload ADTs/codecs.

### Intake

```keiro-dsl
intake incidentInbox {
  contract emergency
  topic incidentEvents
  accept IncidentTransferNeedDeclared
  bind messageId from header "keiro-message-id" required cross-check body
  bind key from kafka-key
  dedupe key messageId policy PreferIntegrationMessageId
  persist = dedupe-only
  decode { envelope strict-required lenient-optional ; body strict schemaVersion == 1 }
  disposition {
    processed => ackOk
    duplicate => ackOk
    inProgress => retry 5s
    previouslyFailed => deadLetter "prior failure"
    decodeFailed => deadLetter
    dedupeFailed => deadLetter
    storeFailed => retry 5s
  }
}
```

Binding sources are `header "name"`, `body`, `kafka-key`, or `kafka-cursor`; `required` and
`cross-check body` are optional modifiers. `persist` is `full-envelope` (default) or `dedupe-only`.
The latter drops successful payload bytes but failed rows always retain the full envelope.

Candidate Language 6 accepts `idempotence delegated` in place of inbox-table ownership. Its
generated runner uses the no-`Store` delegated APIs and requires the downstream atomic state
transition to provide the durable receipt. It is not appropriate for silent commands, non-atomic
side effects, or multi-command reactions, and it provides no inbox backlog or failed-row inspection.
`persist = dedupe-only` is invalid with delegated idempotence because there is no Keiro inbox row to
retain or trim (`DelegatedInboxDedupeOnlyPersistence`); omit `persist`. The generated module exports
`inboxIdempotence = IdempotenceDelegated` and a typed `runInboxIntake` wrapper over
`runInboxDelegated`.

The directly scaffoldable dedupe policies are `PreferIntegrationMessageId`,
`PreferSourceEventIdentity`, and `KafkaDeliveryIdentity`. A custom runtime key remains hand-owned.

All seven disposition rows are mandatory and unique. `duplicate` acknowledges, prior failure and
decode poison dead-letter, and transient store failure retries. The generated `inboxPersistence`
value is passed to `runInboxTransactionWith`. Consumer group/sharding settings remain deployment
configuration, outside the notation.

### Emit and publisher

```keiro-dsl
emit reservationResponse {
  contract emergency ; topic hospitalEvents ; source "hospital-capacity" ; key incidentId
  map status { "confirmed" => TransferReservationAccepted _ => skip }
  messageId derive "msg" hole ; idempotencyKey derive hole
}

publisher hospitalPublisher {
  emit reservationResponse ; ordering PerKeyHeadOfLine ; maxAttempts 10
  backoff exponential 2s max=60s multiplier=2.0
  outboxId stable from messageId
}
```

The emit map requires `_ => skip`; all mapped events must belong to the chosen contract topic.
Publisher backoff is `constant <duration>` or
`exponential <initial> max=<duration> multiplier=<decimal>`. Exponential form requires both options.
Ordering is one of `PerKeyHeadOfLine`, `PerSourceStream`, `StopTheLine`, or `BestEffort`. The
publisher references an emit and captures the stable outbox identity field. Mapping, derivation,
ordering, and stable identity are evolution surfaces.

## Workqueue and dispatch

```keiro-dsl
workqueue reservation_work {
  queue logical = "hospital_capacity.reservation_work"
  derive physical = "hospital_capacity_reservation_work"
         dlq = "hospital_capacity_reservation_work_dlq"
         table = "pgmq.q_hospital_capacity_reservation_work"
  ordering fifo-heads
  group key from reservationId via raw
  provision standard
  payload ReservationWorkItem { reservationId -> "reservation_id" text required }
  retry maxRetries = 3 delay = 5s dlq = on
  disposition {
    storeFailure -> retry 5s
    decodeFailure -> deadLetter
    commandRejected -> deadLetter
    onCodecReject -> deadLetter
  }
}
```

Ordering is `unordered` (default), `fifo-throughput`, or `fifo-roundrobin`; Candidate Language 6
adds `fifo-heads`. FIFO
requires exactly one group key; unordered forbids it. `fifo-heads` lowers to the strict grouped-head
reader as generated `FifoHeads` policy and safely supports batches; the legacy FIFO strategies
require batch size 1 at runtime. Declaring `fifo-heads` under Languages 1–5 is rejected at the
language-feature boundary.
`via raw` requires a `text` payload field. An opaque `via <name>` requires
`fixture "input => output"`.

Provisioning is `standard` (default), `unlogged`, or
`partitioned(interval="daily", retention="7 days")`. Unlogged queues can be truncated to empty after
a database crash and produce `WqUnloggedDurability`. Partition settings are non-empty, require
`pg_partman`, and apply only when creating a queue; reconciliation does not migrate an existing
queue. FIFO adds its GIN index. A DLQ remains standard.

Payload field types include the queue codec surface (`text`, `int`, `bool`) with explicit wire name.
The captured physical/DLQ/table trio is re-derived from the logical name.
All four disposition rows are mandatory; store failure retries, decode failure dead-letters, and
`dlq = on` requires a positive retry ceiling.

<Callout type="warn">
  **Breaking in keiro-dsl 0.11.0.0: every workqueue payload field is required.** The `required`
  marker is still *accepted* but selects nothing, and `WqField` loses its `wqfRequired` field. The
  removed `WqFieldOptionalUnsupported` diagnostic went with the model it described: generated
  decoders read every field with `o .:`, so an "optional" payload field never existed.

  The consequence for evolution is the important part — **adding a payload field is now classified
  breaking however it is spelled.** A job already queued under the old shape does not contain the
  new field, which the previous "a new optional field is additive" classification denied. See
  [Version a job payload](/docs/keiro/how-to/version-a-job-payload).
</Callout>

<Callout type="info">
  **Three previously descriptive-only surfaces are now checked against the references they name**
  *(0.11.0.0)*:

  - a timer's `decode unknown-status` must be a status the timer table stores — `Scheduled`,
    `Firing`, `Fired`, `Cancelled`, or `Dead` (`TimerDecodeStatusUnknown`);
  - a timer's `dead-letter` reason must not be blank, since it is the text an operator-written
    worker passes to `Keiro.Timer.deadLetterTimer` (`TimerDeadLetterTextInvalid`);
  - a pgmq `dedup key` must be a generated selector of its source read model, reported with the
    existing `DispatchReadModelFieldUnknown`, and a pgmq `fanout body` must be spellable as a
    Haskell value identifier (`PgmqFanoutFunctionInvalid`).

  Emit `source`, `key`, and map discriminant names remain the **one** documented descriptive-only
  surface, because no typed source namespace exists to resolve them against.
</Callout>

```keiro-dsl
dispatch reservation_work_dispatch {
  source readModel = accepted_transfer_needs key = reservationId
  fanout body = resolveTransferCandidates
  dedup key = reservationId
        seenIn readModel = transfer_decisions field = reservation_id
        seenIn queue = reservation_work field = reservation_id
  enqueue to = reservation_work
}
```

Source/dedupe read models, the declared read-model column, queue, queue wire field, and enqueue target
must resolve. Fan-out and raw-SQL queue dedupe are hand-owned. Generated queue output is `Queue`,
`QueuePolicy`, and a `QueueCodec` module; headers, batch/visibility/poll/concurrency tuning, metrics,
and handler behavior stay in runtime configuration.

### The generated `QueueCodec`

Scaffolded workqueues ship a `QueueCodec` module holding a **versioned** `keiroJobCodec` envelope
(`{v,t,data}`) starting at schema version 1, rather than a bare `aesonJobCodec` payload. New queues
therefore begin inside an envelope that makes rolling-deploy skew self-describing: an old worker
reading a future envelope returns `JobPayloadFromFuture` and the job is retried.

Payload-evolution *syntax* in the DSL remains future work — `diff` still classifies workqueue payload
changes with its normal rules — but the runtime envelope is in place from day one.

<Callout type="warn">
A **fresh** queue needs no migration. An **existing** queue carrying bare-payload messages must be
drained before you swap its codec, or use a transitional decoder that accepts both shapes; otherwise
in-flight bodies fail as `JobPayloadMalformed` and dead-letter. See
[deploy-ordering rule 3](/docs/keiro/reference/deploy-ordering#3-upgrade-versioned-job-workers-before-producers).
</Callout>

## Workflow and operation

```keiro-dsl
workflow HospitalTransferReservation
  name "hospital-transfer-reservation"
  in ReservationWorkflowInput { reservationId:Id hospitalId:Id coolingOffDelay:Duration }
  out ReservationWorkflowSummary
  id from input.reservationId via idText
  body
    step create-transfer-hold -> ReservationHold
    patch fraud-check-v2 {
      step fraud-check -> FraudCheckResult
    }
    await reservation-confirmation -> ReservationConfirmation
    sleep cooling-off after coolingOffDelay
    child ship-order id input via shipChildId -> Text
    continueAsNew RolloverSeed
```

Body item forms are `step`, `await`, injected-delay `sleep`, child workflow, nested `patch`, and
top-level terminal `continueAsNew`. Labels are unique and replay matches labels. Patch IDs are
opaque, globally unique within the workflow, colon-free, and never reused. Use a patch for a
cross-cutting change to several journaled steps; rename one changed step instead of patching it.

`continueAsNew <Seed>` must be the final top-level item and cannot appear in a patch. The hand-owned
body calls `restoreSeed` at the beginning and `continueAsNew` at the tail. Generated output is
`WorkflowFacts` and `WorkflowRuntime`; behavior stays in a hand-written body module.

The four operation shapes are:

```keiro-dsl
operation ConfirmReservation
  command on Reservation
    stream from reservationId via reservationStream
    project [ transferDecision ]

operation QueryTransferDecision
  query transferDecision
    input TransferReservationId
    result Maybe TransferDecision
    consistency Strong

operation SignalReservationConfirmation
  signal reservation-confirmation of HospitalTransferReservation
    key from reservationId via reservationWorkflowId
    value ReservationConfirmation

operation RunReservationWorkflow
  run HospitalTransferReservation
    input ReservationWorkflowInput
    outcome -> ReservationWorkflowRun
```

Aggregate/read-model/workflow references resolve. A signal label and value type must match an
`await`; workflow ID/sleep fields must exist. Operations validate entry points but own no separate
persisted decode or identity surface in `diff`.

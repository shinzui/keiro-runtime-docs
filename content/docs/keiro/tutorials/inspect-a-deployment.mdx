---
title: "Inspect a deployment over HTTP"
description: "Start a read-only operations server and verify its schema boundary."
---

Use `keiro-ops-http` 0.22.0.0 with a database prepared through the [installation guide](/docs/getting-started/installation). For the 0.22 cohort apply Kiroku migration 0016 with affected workers stopped; its composed framework plan has 48 entries.

## Start and verify

Install the published executable with your Haskell package workflow, then start it against the migrated database:

```bash
keiro-ops-http --database-url "$DATABASE_URL" --port 9092
```

In another terminal:

```bash
curl -fsS http://127.0.0.1:9092/health
curl -fsS http://127.0.0.1:9092/wf/list
```

Health reports `status:"ok"`, an empty `schema_drift` list and `mutations_enabled:false`. An empty workflow list is valid on a new database. Schema mismatch refuses inspection; use the matching release's migration plan before retrying.

The standalone server has no application catalogs. Embed the application with your `AppHooks` when aggregate/process-manager state is required. Leave mutations disabled until adopting the [confirmation procedure](/docs/keiro/how-to/confirm-http-operations). Read the [limits](/docs/keiro/reference/ops-http) before exposing the service through a proxy.

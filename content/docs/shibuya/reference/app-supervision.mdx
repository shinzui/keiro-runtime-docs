## Supervision strategy

```haskell
data SupervisionStrategy
  = IgnoreFailures
  | StopAllOnFailure
```

`IgnoreFailures` keeps other processors running if one child exits. `StopAllOnFailure` maps to an
NQE strategy that stops all processors when one fails. Graceful exits, including finite streams
completing and handlers returning `AckHalt`, do not stop sibling processors.

## Application config

```haskell
data AppConfig = AppConfig
  { strategy :: SupervisionStrategy
  , inboxSize :: Int
  }

defaultAppConfig :: AppConfig
```

`defaultAppConfig` is `IgnoreFailures` with an inbox of `100`. `runApp` validates that `inboxSize`
is at least `1` before starting any processor.

## Shutdown configuration

```haskell
data ShutdownConfig = ShutdownConfig
  { drainTimeout :: !NominalDiffTime
  , totalShutdownTimeout :: !NominalDiffTime
  }

defaultShutdownConfig :: ShutdownConfig
```

The default drain timeout is 30 seconds. The total graceful-phase timeout is 60 seconds.
The total timeout includes adapter shutdown and draining. Master cleanup follows that phase;
this option does not promise that the entire stop call returns within the deadline.

## App handle operations

```haskell
getAppMetrics :: (IOE :> es) => AppHandle es -> Eff es MetricsMap

stopApp :: (IOE :> es) => AppHandle es -> Eff es ()

stopAppGracefully ::
  (IOE :> es) =>
  ShutdownConfig ->
  AppHandle es ->
  Eff es Bool

waitApp :: (IOE :> es) => AppHandle es -> Eff es ()
```

`stopApp` uses `defaultShutdownConfig`. `stopAppGracefully` marks the application as draining,
tries each adapter's `shutdown`, waits for processors to finish, and always attempts master cleanup.
A synchronous shutdown exception does not skip later adapters, but the total timeout or external
cancellation can interrupt the graceful phase. Repeated and concurrent stop calls share the first
call's result. The first call also selects the shutdown configuration.

A clean drain returns `True`. A drain or total timeout returns `False` after cleanup.
Adapter or cleanup exceptions can propagate instead of returning a `Bool`.

## Structured errors

```haskell
data AppError
  = AppPolicyError PolicyError
  | AppHandlerError HandlerError
  | AppRuntimeError RuntimeError
  | AppBatchConfigError BatchConfigError
  | AppConfigInvalid ConfigError
```

Policy, batch config, and app config errors are produced before processors start. Runtime errors
cover supervisor failures. Handler exceptions are represented as `HandlerException Text`; on the
single-message path, thrown handlers are finalized as `AckRetry (RetryDelay 0)`.

## Validation and failure ownership

```haskell
data ConfigError
  = InvalidInboxSize !Int
  | DuplicateProcessorId !ProcessorId

data PolicyError
  = InvalidPolicyCombo !Text
  | InvalidConcurrency !Int
  | ConcurrencyCapacityOverflow !Int

data ProcessorFailure = ProcessorFailure !Text !(Maybe MessageId)
```

`runApp` rejects duplicate processor IDs, nonpositive `Ahead`/`Async` concurrency, and derived
buffer-capacity overflow before acquiring adapters. Startup tracks acquired resources so a later
acquisition failure triggers cleanup of earlier resources without replacing the primary exception.

Import `ProcessorFailure` from `Shibuya`. A permanent framework finalization failure is an
infrastructure failure, distinct from an intentional `AckHalt`. It wakes idle intake and retains
failed lifecycle evidence after live metrics are removed. `IgnoreFailures` keeps siblings running
but does not make the failed application ready. `StopAllOnFailure` stops siblings and delivers the
processor failure to the caller once. The NQE supervisor is not linked to the `runApp` caller.

## Forced-stop limitation

The published 0.10.0.0 release has a reported case where asynchronous handlers remain active after
`stopAppGracefully` returns `False` and can finalize after their gate opens. A returned stop result
therefore does not prove that all handler side effects have ended. Keep handlers idempotent and
fence the old worker before starting a replacement or releasing its resources. If the application
requires a strict stop boundary, enforce it at the process boundary.
The report is `mori://shinzui/shibuya/okf/bug-reports/concepts/BUG-1`.

Read [Configure graceful shutdown](/docs/shibuya/how-to/configure-graceful-shutdown) for timeout
selection and replacement-worker checks.

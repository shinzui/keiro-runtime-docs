---
title: "03 — Handler, ack, and tracing"
description: "The processOne path: call the handler, finalize the decision, record metrics, and stop on halt."
---

`processOne` in `Shibuya.Internal.Runner.Supervised` receives the metrics handle, processor
identity, concurrency, terminal-exit publisher, handler, and ingested delivery.
It extracts the parent trace context, opens a consumer span, and merges framework attributes with
adapter attributes. Adapter attributes win on duplicate keys.

The handler and finalizer have separate failure boundaries. A synchronous handler exception records
the exception and selects `AckRetry (RetryDelay 0)`. The runner then calls `finalizeWithRetry`
for that decision. A finalizer failure does not invoke the handler again.

```haskell
finalizeResult <- finalizeWithRetry traceSpan ingested decision
```

A successful `AckOk` or `AckRetry` increments processed. `AckDeadLetter` and handler exceptions
increment failed. Those counters do not count successful business effects exclusively.
Finalization failure records failure metrics and trace evidence.

The terminal request uses an exit publisher that wakes blocked intake:

```haskell
case finalizeResult of
  Left _ ->
    liftIO $ requestProcessorExit exitPublisher
      (ProcessorFailed (finalizationFailureText msgIdText) (Just messageId))
  Right () -> case result of
    Right (AckHalt reason) ->
      liftIO $ requestProcessorExit exitPublisher (ProcessorHalted reason)
    _ -> pure ()
```

Infrastructure failure takes precedence if concurrent work requests both failure and graceful halt.
The surrounding loop exits with `ProcessorFailure` for failed finalization; deliberate halt uses
`ProcessorHalt`. Supervision retains failure lifecycle after removing the live metrics entry.

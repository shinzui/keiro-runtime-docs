---
title: "04 — Supervision and shutdown"
description: "How runApp starts processors, the Master tracks metrics, and graceful shutdown drains work."
---

`runApp` from the top-level `Shibuya` module is the application entry point:

```haskell
runApp ::
  (IOE :> es, Tracing :> es) =>
  AppConfig ->
  [(ProcessorId, QueueProcessor es)] ->
  Eff es (Either AppError (AppHandle es))
```

It validates `AppConfig`, every `QueueProcessor` policy, and every batch config first. If validation
passes, it starts a `Master`, spawns each processor with the internal supervised runner, and returns
an `AppHandle`.

The `Master` in `Shibuya.Internal.Runner.Master` owns the NQE supervisor and the processor metrics
registry. Public modules keep `Master` opaque; use `getAppMaster`, `getAppMetrics`, and the metrics
server helpers instead of record fields.

The internal supervised runner creates metrics and done state, registers with the master, then adds
the processor body as a supervised child. It catches `ProcessorHalt` so a handler's intentional halt
is not treated as an unexpected exception by that child.

Graceful shutdown is in `stopAppGracefully`:

```text
1. call every adapter.shutdown
2. wait for in-flight processors to drain, up to drainTimeout
3. stop the master, cancelling remaining children
4. return whether the drain completed before timeout
```

`waitApp` is different. It blocks until every processor's `done` TVar is true. Use `waitApp` for
finite streams or top-level programs that should run until external shutdown code calls `stopApp`.

## Released liveness fixes

Shibuya 0.9.0.2 removes the unused linked master mailbox actor. The master retains the actual
NQE supervisor and metrics registry. Version 0.9.0.3 starts that supervisor without linking it to
the `runApp` caller. This prevents a finished application's unreachable supervisor from killing
the caller during major garbage collection, and prevents duplicate failure delivery under
`StopAllOnFailure`. Processor links still propagate failures and stop siblings under that policy.
`stopMaster` cancels the supervisor and its children; public application signatures are unchanged.

The 0.10 lifecycle API at the reviewed upstream head is an unpublished candidate. Its total
shutdown deadline, new error constructors, retained lifecycle, health and WebSocket changes are
not part of the released 0.9 API documented here.

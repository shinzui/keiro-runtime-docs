Use this matrix to select the documented packages. It records reviewed source versions.
It does not establish compatibility with later releases.

## Supported DSL

Language 6 is the only supported Keiro DSL language in this documentation.
Put this declaration before `context` in every `.keiro` file:

```keiro-dsl
language keiro-dsl 6
```

Require it during validation:

```bash
keiro-dsl check service.keiro --min-language 6 --deny-warnings
```

For workspaces, declare Language 6 in every member.
Read the [Language 6 reference](/docs/keiro/reference/keiro-dsl-language-6) for capabilities and current tool behavior.

## Keiro dependency set

Use the current packages together. Keiro 0.19 requires:

- `kiroku-store >=0.9.0.1 && <0.10`.
- `kiroku-store-migrations ^>=0.6.0.0`.
- `shibuya-core ^>=0.10.0.0`.
- `shibuya-pgmq-adapter ^>=0.16.1.0` for `keiro-pgmq`.
- pg-migrate `^>=1.2.0.0` for migration and fixture packages.
- `pgmq-migration >=0.6.1.1 && <0.7` for the PGMQ test component.

The fixture requires `ephemeral-pg >=0.3.1 && <0.4`.
`pg-migrate-test-support 1.2` accepts that line. Remove the former
`allow-newer: pg-migrate-test-support:ephemeral-pg` workaround.

The Shibuya/Kiroku adapter cohort accepts effectful-core `>=2.6.1 && <2.7` or
`>=2.7.1.1 && <2.8`. Its package bounds exclude `2.7.0.0` through `2.7.1.0`.
Do not relax those exclusions to complete a solve.

## Database preparation

Use the [installation guide](/docs/getting-started/installation) for a new database.
Compose the store, framework, queue, and application migration components in one plan.
Apply and verify the plan before runtime pools and workers start.

The framework-only plan has
forty-four entries: twelve Kiroku and thirty-two Keiro. Kiroku `0012` adds the category index.
For an existing database, stop old appenders before applying it; start current appenders afterward.
Read [category-index preparation](/docs/kiroku/reference/schema-migrations#category-index-preparation).

For later schema changes, read the [migration reference](/docs/keiro/reference/migrations-and-schema).
It identifies required SQL, rebuild constraints, and verification commands.
Complete or abandon active catalog rebuilds before migration `0024`.
Stop timer writers before migration `0032`; deploy the new writers before guarded timer resume starts.

## Service validation

1. Declare Language 6 in each source file.
2. Run `check` with `--min-language 6`.
3. Generate the service and compile its application code.
4. Run the generated conformance harnesses and application tests.
5. Compare persisted contracts with `keiro-dsl diff` before later changes.
6. Apply and verify the database plan before deployment.

Read [replay compatibility](/docs/keiro/reference/replay-compatibility) before a change to retained event history.

## Unreleased PGMQ source

The reviewed PGMQ head includes inspection reads, five new `Pgmq` effect constructors, and
`isAmbiguousReply`. These changes landed after the published 0.6.1.1 tag. The source package
version has not yet changed; that number alone does not prove the new API is published.
The installation set above uses the published packages.
Read the explicit unreleased sections in the
[Hasql reference](/docs/pgmq/reference/hasql-api#unreleased-inspection-reads) and
[Effectful reference](/docs/pgmq/reference/effectful-api#unreleased-disconnect-classification).

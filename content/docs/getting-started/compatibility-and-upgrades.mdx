Use this matrix to select the documented packages. It records reviewed source versions.
It does not establish compatibility with later releases.
Read the [changelog](/docs/changelog) for more recent published releases and their package-specific changes.
Release-history coverage does not advance this API review boundary.

## Supported DSL

Language 6 is the only supported Keiro DSL language in this documentation.
Put this declaration before `context` in every `.keiro` file:

```keiro-dsl
language keiro-dsl 6
```

Require it during validation:

```bash
keiro-dsl check service.keiro --min-language 6 --deny-warnings
```

For workspaces, declare Language 6 in every member.
Read the [Language 6 reference](/docs/keiro/reference/keiro-dsl-language-6) for capabilities and current tool behavior.

## Keiro dependency set

Use the current packages together. Keiro 0.21 requires:

- `kiroku-store ^>=0.11.0.0`.
- `kiroku-store-migrations ^>=0.7.1.0`.
- `shibuya-core ^>=0.10.0.1`.
- `shibuya-pgmq-adapter ^>=0.16.1.0` for `keiro-pgmq`.
- pg-migrate `^>=1.2.0.0` for migration and fixture packages.
- `pgmq-migration >=0.6.1.1 && <0.7` for the PGMQ test component.

The fixture requires `ephemeral-pg >=0.3.1 && <0.4`.
`pg-migrate-test-support 1.2` accepts that line. Remove the former
`allow-newer: pg-migrate-test-support:ephemeral-pg` workaround.

The Shibuya/Kiroku adapter cohort accepts effectful-core `>=2.6.1 && <2.7` or
`>=2.7.1.1 && <2.8`. Its package bounds exclude `2.7.0.0` through `2.7.1.0`.
Do not relax those exclusions to complete a solve.

## Database preparation

Use the [installation guide](/docs/getting-started/installation) for a new database.
Compose the store, framework, queue, and application migration components in one plan.
Apply and verify the plan before runtime pools and workers start.

The framework-only plan has
forty-seven entries: fifteen Kiroku and thirty-two Keiro. Kiroku `0012` adds the category index.
For an existing database, stop old appenders before applying it; start current appenders afterward.
Read [category-index preparation](/docs/kiroku/reference/schema-migrations#category-index-preparation).

For later schema changes, read the [migration reference](/docs/keiro/reference/migrations-and-schema).
It identifies required SQL, rebuild constraints, and verification commands.
Complete or abandon active catalog rebuilds before migration `0024`.
Stop timer writers before migration `0032`; deploy the new writers before guarded timer resume starts.

## Service validation

1. Declare Language 6 in each source file.
2. Run `check` with `--min-language 6`.
3. Generate the service and compile its application code.
4. Run the generated conformance harnesses and application tests.
5. Compare persisted contracts with `keiro-dsl diff` before later changes.
6. Apply and verify the database plan before deployment.

Read [replay compatibility](/docs/keiro/reference/replay-compatibility) before a change to retained event history.

## Keiki source-only boundary

Keiki's descriptive SCXML exporter remains outside published 0.9.1.0. See [SCXML](/docs/keiki/reference/render-scxml). PGMQ and Shibuya's formerly source-only additions are now published; the 0.22 adoption section below records their newer constraints.

## Upgrade subscriptions and generated clients

Stop subscriptions before Kiroku 0013/0014 and budget a write pause for the transactional 0015
index build. Validate group sizes/members, fetch batches, and stream buffers through smart
constructors. Update typed decode hooks, exhaustive Store interpreters, and full records. See
[the migration cutover](/docs/kiroku/reference/schema-migrations#subscription-and-inspection-cutover).
For Keiro 0.21, also [regenerate and adapt DSL clients](/docs/keiro/reference/keiro-dsl-cli#keiro-dsl-021-adoption).

## Published 0.22 adoption set — checked 2026-10-27

Keiro 0.22 publishes these dependency constraints: Store `^>=0.12.0.0`, store migrations `^>=0.7.2.0`, Shibuya core `^>=0.12.0.0`, PGMQ adapter `^>=0.18.0.0`, PGMQ packages `>=0.7.0.0 && <0.8`, and pg-migrate `^>=1.2.0.0`. Kiroku's adapter is `^>=0.7.0.0`; optional Kiroku metrics is `^>=0.4.0.0`. These are verified published bounds, not a downstream application certification. The earlier table retains the last completed whole-tree API boundary.

Stop affected workers for Kiroku migration 0016 and restart new binaries before namespace binding. Apply PGMQ migration 0007 before traffic and retain partition polling. The framework plan now has 48 entries, plus seven for PGMQ. Update direct `Ingested` records with `deliveryStatus`, complete command/hook records with their inspection fields, exhaustive target/error matches and conflicting orphan JSON instances.

`keiro-ops-http 0.22.0.0` and `pgmq-inspect 0.7.0.0` are published. Shibuya browser/control/detail APIs and PGMQ inspection/disconnect APIs previously labeled unreleased now ship in 0.11/0.7 respectively. Keiki SCXML remains source-only. See [HTTP operations](/docs/keiro/reference/ops-http), [queue inspection](/docs/pgmq/reference/inspection-server), and [release history](/docs/changelog).

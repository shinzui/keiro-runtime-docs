This matrix records the exact committed releases reviewed by this documentation
pass. It is an evidence boundary, not a promise that arbitrary newer versions
are compatible. Pin package versions, read upstream release notes, and rerun your
own build, migration, and integration tests before upgrading.

<Callout type="info">
  **`keiro-dsl` language 5 is the sole stable authoring contract** as of Keiro 0.12.0.0, and it is the

  aggregate fold identity — plan it as a replay concern, not just a grammar upgrade.
</Callout>

## Breaking source upgrades

Treat every pre-1.0 minor line as potentially breaking.

- **keiki 0.2:** the `Keiki.Decider` facade is removed; builders require
  explicit output intent; replay failures are structured; pinned shape names
  intentionally cause one cache miss and full replay for non-empty 0.1
  snapshots. See [persist a register
  snapshot](/docs/keiki/how-to/persist-a-register-snapshot#upgrading-from-keiki-01).
- **keiki 0.3:** `Edge` gains `mode :: EdgeMode`; hand-written edges must set
  `mode = Live`. Tightening a guard now has a sanctioned remedy — see [tighten a
  guard without breaking
  replay](/docs/keiki/how-to/tighten-a-guard-without-breaking-replay).
- **keiki 0.4:** `Term` gains `TFieldProj`, and
  `TransducerValidationWarning` / `ComposeAlignmentWarning` gain projection
  constructors, so exhaustive matches must be extended;
  `checkComposeAlignment` now requires `WeakenR rs1`. See [field
  projections](/docs/keiki/reference/core#field-projections).
- **keiki 0.5:** the `Sym` class gains `constrainSymDomain` (defaulted, so hand-written instances
  still compile); `Natural` becomes a curated symbolic carrier with a non-negative domain and a
  pinned `CanonicalTypeName`; the opt-in opaque-guard audit widens to unsupported `TArith` carriers
  and its message text changes, so tests asserting on it need updating. `keiki-codec-json` gains
  `Natural` wire support, rejecting negative and fractional numbers.
- **keiki 0.6 (semantic):** structural `Natural` subtraction is **total monus** —
  `a - b = max 0 (a - b)` — in both concrete and symbolic evaluation, so a model that relied on
  `Underflow` to signal an invalid state must guard the ordering explicitly. See [the term
  language](/docs/keiki/reference/core#the-term-language).
- **keiki 0.7 (semantic):** `verifyPredicate` no longer treats a one-way `fieldWitness` projection as
  an exact translation — such predicates now report `UnverifiedOpaque`. `symSatExt` concretely
  rechecks every candidate, so it returns `Nothing` where it previously could return a pair that
  failed `models`. Neither change weakens `symIsBot`. New: `Keiki.ProjectionDomain`,
  `exactFieldWitness`, and the detailed step/replay attribution APIs.
- **keiki 0.8:** `TLit` and `lit` require `Show` and `Term` gains `TOpaqueLit`, so exhaustive matches
  must be extended and literals without `Show` move to `opaqueLit`. `toMermaid` and every no-options
  shape renderer now default to **readable** guards and complete updates — every diagram golden
  changes; use `toTopologyMermaid` for the old bytes. `MermaidOptions` **removes**
  `showWrittenSlots` and `showGuardSummary` in favour of `updateMode` and `guardMode`. Readable
  rendering discloses `lit` values: secrets must use `opaqueLit`. See [readable and opaque
  literals](/docs/keiki/reference/core#readable-and-opaque-literals).
- **keiki 0.9:** `InCtor` and `WireCtor` construction **and record update** are sealed behind
  read-only patterns — replace manual records with `unavailableInCtor` / `unavailableWireCtor`, a
  `Via` producer, or TH. `mkInCtor`, `mkInCtor0`, `mkWireCtor`, `mkWireCtor0` are deprecated;
  `renameInCtor` / `renameWireCtor` replace record update for relabelling. Sequential composition
  substitutes only through typed input-to-wire alignment, so `ComposeAlignmentWarning` gains
  `StructurallyDifferentInputWire` and `UnwitnessedInputWireAlignment`. Nullary TH wires match via
  `Generic co` instead of `Eq co`. Default `inversionAmbiguityWarnings` classifies heads
  structurally and can prove some candidates disjoint, so **a recompile may report a different
  warning set** and `tvwDetail` text changed. The JSON wire format is unchanged. See [what replay
  proves](/docs/keiki/explanation/what-replay-proves).
- **Keiro 0.5:** `keiro-dsl` **service workspaces** ship. `DiagnosticCode` gains nine append-only
  workspace constructors, `ScaffoldRun.Refusal` gains `GoldenRootDivergence`,
  `ScaffoldRun.WriteDisposition` gains `Unchanged`, and `DiffReport.Remedy` gains
  `RemedyRescaffoldWorkspace`; exhaustive matches must be extended. No existing behaviour changed,
  and a single `.keiro` file behaves as a one-member workspace. See [service
  workspaces](/docs/keiro/reference/keiro-dsl-workspaces).
- **Keiro 0.6:** requires keiki `>=0.6 && <0.7`. Adds the `language keiro-dsl N` preamble and
  language 2 (nominal consumer bindings, `Keiro.Codec.Nominal`, typed aggregate expressions,
  direct `Time`/`Natural` aggregate fields). The public expression AST gains located arithmetic,
  scalar literals, explicit roots/paths, and transition implementation ownership; aggregate fields
  use `AggregateField` and register types use `TypeExpr` instead of a raw `Name`. `DiagnosticCode`
  gains the aggregate-type, source-language, nominal, and scalar-expression codes. See [language
  versions](/docs/keiro/reference/keiro-dsl-language-versions).
- **Keiro 0.7:** requires keiki `>=0.7 && <0.8` — Keiki now classifies a predicate crossing a
  one-way generated projection conservatively, so symbolic verification may return
  `UnverifiedOpaque` where an earlier release reported a verified result. **Runtime command
  execution and replay are unchanged**; only proof strength moves. Adds language 3 and the enforced
  `Keiro.Codec.IdDomain` TypeID-v7 contract: generated prefix-bearing IDs become **abstract**
  (`parseX`/`mkX`/`xText` from `Generated.<Context>.Nominals`) and service-level IDs and enums move
  out of per-aggregate `Domain` modules into one context-level `Nominals` module, so hand-owned
  imports must be updated. New diagnostics: `IdDomainContractChanged`, `EventOutputCommandMismatch`,
  `AggregateEventlessStateChange`.
- **Keiro 0.8:** `keiro-dsl` only. `LanguageDefinition` gains `definitionSyntaxProfile` and
  `definitionRuntimeSemantics` and is exported as `LanguageDefinition (..)`, so positional
  construction and non-wildcard record patterns no longer compile. Generated bytes, the 0.7
  acceptance matrix, and rendered diagnostics are unchanged.
- **Keiro 0.9:** requires keiki `>=0.8 && <0.9`. Language 4 becomes the sole stable contract.
  **Aggregate fold fingerprints widen from 16-hex FNV-1a-64 to 32-hex FNV-1a-128, intentionally
  invalidating existing snapshots** — generated transducers must be refreshed. Read-model,
  mapped-wire, and behavior-key 64-bit identities do not move. Fold, diff, replay-impact, and
  workspace-diff APIs now return `Either FoldSurfaceError`, and the `Spec`-only legacy wrappers are
  **removed** in favour of passing a `CheckedService`. Generated runtime surfaces close over `Text`
  (closed outcome sums, `<aggregate>CommandCategory`, a generated `WorkflowFacts` record), structural
  projection witnesses are renamed to deterministic owner-and-JSON-pointer names, and the unreachable
  grammar types `Derivation`, `DerivStrategy`, `Disposition`, `DispAction`, `EnvelopeBinding`, and
  `EnvelopeLayer` are removed. `DiagnosticCode` and `RolloutConstraint` gain append-only
  constructors.
- **Keiro 0.10:** no user-facing changes. `keiro-core` and `keiro-migrations` report "no changes";
  `keiro`, `keiro-pgmq` move only their lockstep bounds. Released with the package set for the
  `keiro-dsl` 0.10.0.0 work.
- **Keiro 0.11:** requires keiki `>=0.9 && <0.10` and `keiki-codec-json 0.9`. Generated aggregates
  already use the trusted TH path, so keiki 0.9's seal needs no source change — but validation
  results may differ where 0.9 distinguishes structural heads. **JSON event and snapshot formats are
  unchanged.** `Keiro.Timer.Schema.TimerStatus` additionally derives `Enum` and `Bounded`; stored
  representations are unchanged.

  `keiro-dsl` carries the rest, and it is a substantial adopter upgrade:

  - **Scaffold sidecars are renamed** and an old-name tree **refuses without writing**. Review the
    reported moves and rerun `scaffold --apply-name-migrations`. The conformance ledger also changes
    to the versioned `keiro-dsl conformance ledger v1` format, converted only by that explicit path.
  - **Generated Haskell uses one checked naming edition** — `service_oncall` now generates
    `ServiceOncall`, not `Service_oncall`. Apply the reported source migration and recompile.
  - **`check --deny-warnings` is an honest gate at last.** With `--coverage-report` it previously
    printed coverage warnings and exited 0. `--deny CODE` now refuses codes `check` cannot emit, so a
    CI file naming one fails loudly. Router notices moved to `RouterBenignInversion` — add it to any
    `--deny ProcessBenignInversion` list.
  - **Four accepted-but-unimplemented spellings are now refused** (`body lenient`, non-`AckOk`
    `on-appended`, `not-mine Fired`, unknown intake headers), and a process `dispatch-id` line is
    checked as strictly as a router's.
  - **Every workqueue payload field is required**; `WqField` loses `wqfRequired`, and adding a
    payload field is now classified breaking however spelled.
  - `keiro-dsl/coverage-report/1` spells warning severity `"warning"`, not `"advisory"`.
  - Language 4 gains **field aliases** (`haskell <selector>`, `as "<wire-key>"`) and moves to
    `syntax-profile/3`.

  See the [keiro-dsl CLI](/docs/keiro/reference/keiro-dsl-cli) and [language
  versions](/docs/keiro/reference/keiro-dsl-language-versions).
- **Keiro 0.12:** the largest runtime release since the 0.3 line. Requires
  `kiroku-store >=0.4 && <0.5`.

  **Migrations `0021`, `0022`, and `0023` all apply.** `0021` is the only one that rewrites live
  state: it returns every pre-existing `suspended` workflow instance to `running` once, costing one
  extra replay each. Budget a single elevated resume pass at the cutover. See
  [migrations and schema](/docs/keiro/reference/migrations-and-schema#0021-exact-discovery-is-not-additive).

  - **Workflow discovery is exact.** A `suspended` instance with no due `wake_after` is now invisible
    to the resume worker, so idle cost no longer scales with parked workflows. The cost: a
    **third-party wake source must write the owning instance row on every lifecycle transition**, or
    it strands its workflow. See [write a custom wake
    source](/docs/keiro/how-to/write-a-custom-wake-source).
  - **A terminally failed workflow now stops at the next step boundary**, as a cancelled one already
    did. Runs that relied on continuing past a concurrent `WorkflowFailed` marker now return `Failed`.
  - **Breaking signatures:** `JournalAppendOutcome` gains `JournalRefusedTerminal`;
    `markInstanceSuspended` is replaced by `markInstanceSuspendedAwaiting`; `recordCrashTx` returns
    `Maybe Int32`; `cancelAwakeableTx` returns `Maybe (Text, Text)`; `gcWorkflowsOnce` and
    `runWorkflowGcWorker` gain `Error StoreError :> es`; `ResumeLogEvent` gains
    `ResumeCrashRecordSkipped`; `WorkflowResumeOptions` gains `maxConcurrentAdvances` (default 1);
    `KeiroMetrics` gains eight instrument fields.
  - **Deterministic ids hash UTF-8 seed bytes.** *For ASCII seeds every id is byte-identical* — no
    migration, no operator action. Only non-ASCII seeds move, and they move off a collision that
    could wedge a workflow journal. The derivation is now frozen. See [deterministic
    ids](/docs/keiro/reference/durable-workflows#deterministic-ids-hash-utf-8-seed-bytes).
  - **New: the typed [projection catalog](/docs/keiro/reference/projection-catalog)** —
    `Keiro.Projection.Catalog` and `.Operations`, durable rebuild groups, and a resumable history
    runner with promotion gated on source exhaustion, adapter participation, and verification.
  - **New package: [`keiro-ops`](/docs/keiro/reference/keiro-ops-cli)** — an operational console and
    embeddable command library, with a two-phase preview/`--force` contract on every destructive
    command.
  - **`keiro.projection.lag` is deprecated** in favour of
    `keiro.projection.global_position_distance`; its unit changed from `{event}` to `{position}`
    because it never counted events. Dashboards should rename. Seven `keiro.projection.rebuild.*`
    instruments are new.
  - **`keiro-dsl` language 5 is the new stable contract** — see the callout above; its
    `ProjectionCatalogRuntime` capability changes aggregate fold identity, and every mapped service
    needs one regeneration to pick up the `StructuralConformance` and `BehaviorSourceMap` modules.
- **Keiro 0.3 line:** command, replay, worker, read-model, and workflow outcomes
  are typed more precisely; framework tables live in `keiro`; public event
  streams require replay validation. For `.keiro` specs, follow [migrate a spec
  to 0.2](/docs/keiro/how-to/migrate-a-keiro-spec-to-0-2).
- **Keiro 0.4:** `scheduleTimerOnceTx` returns `Bool`; `ChildRow` gains
  `failureReason` and `markChildFailedTx` takes the terminal reason as its third
  argument; snapshot hydration requires a third
  control-state/fold discriminator, so snapshots written without it are
  invalidated and rebuilt once (migration
  `0019-keiro-snapshots-state-shape-hash.sql`); validated event-stream assembly
  rejects invalid codec schema versions, event tags, and upcaster chains, with
  `mkEventStreamUnchecked` as the explicit emergency-forensics bypass. Requires
  keiki 0.4. See [Snapshots](/docs/keiro/reference/snapshot).
- **Kiroku 0.3:** update cursor, validation, store-error, subscription-source,
  CLI, and adapter handling using the [0.3 upgrade
  matrix](/docs/kiroku/how-to/upgrade-to-0-3).
- **Shibuya 0.8:** handlers receive `Message`, application runners take
  `AppConfig`, batching is first-class, and adapter finalizers must be
  idempotent. Start with the [Shibuya landing page](/docs/shibuya).
- **pgmq-hs 0.4:** `pgmq-migration` exports a component instead of its removed
  standalone runner. Compose it through pg-migrate and use the explicit
  predecessor-history path for existing databases.

## Database upgrade order

For an existing PostgreSQL deployment, do not deploy the new runtime first and
hope startup repairs history:

1. Build the complete application migration plan and inspect `plan`, `status`,
   and `verify` output against a backup or rehearsal database.
2. Quiesce old migration writers and back up the production database.
3. If upgrading Keiro 0.1, follow the [framework-table relocation
   procedure](/docs/keiro/how-to/upgrade-a-0-1-database).
4. Import verified Kiroku/Keiro Codd history and PGMQ
   `public.schema_migrations` history where those predecessor ledgers exist.
   Imports adopt evidence without replaying schema DDL.
5. Run the complete native Kiroku → Keiro → PGMQ → application plan, then run
   strict verification.
6. Deploy runtime processes, reconcile additive queue topology, and monitor the
   typed failure and durable-worker outcomes described by each package.

Fresh databases skip the predecessor imports. Use the [runtime composition
recipe](/docs/pg-migrate/cookbook/compose-runtime-components) and [deployment
runbook](/docs/pg-migrate/how-to/deploy-a-migration-plan) for the executable and
operator gates.

## Stability and pending work

- Keiki, Keiro, Kiroku, Shibuya, PGMQ client packages, and adapters are pre-1.0.
  This documentation does not promise API stability beyond each package's
  release notes and bounds.
- pg-migrate is reviewed at 1.1.0.0, but its compatibility page remains the
  authority for compiler, PostgreSQL, Hasql, and ledger-version support.
- The Message DB adapter is not on the Shibuya 0.8 compatibility line, as noted
  above.
- `keiro-runtime-jitsurei` and `content/docs/example-app/` remain pending
  modernization, and the gap has **widened**: the application has since been
  re-architected onto the validated runtime and the `keiro-dsl` toolchain, and
  24 of the 30 source files that tour quotes have changed. It is an older
  architecture tour, not proof of the current package matrix — see the warning on
  [the example-app landing page](/docs/example-app).

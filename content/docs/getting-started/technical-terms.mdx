Use these definitions for Keiro concepts. The source is `mori://shinzui/keiro/okf/terminology`.
The site uses a checked snapshot of that bundle.

Use **stream** for stored event history and **event stream** for the aggregate contract.
Use **idempotency** for duplicate-effect protection. Preserve the literal DSL clause `idempotence delegated`.
Preserve API names, identifiers, and protocol values exactly.

These entries are project technical nouns. They do not constitute the official ASD-STE100 dictionary.
Full vocabulary and grammar review against Issue 9 remains pending.
See [Contributing](/docs/getting-started/contributing) for the writing rules.

## Current terms

| Term | Definition | Canonical source |
| --- | --- | --- |
| stream | A stream is an ordered, append-only history of events for one aggregate instance or other entity. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-1` |
| event stream | An event stream is Keiro's aggregate contract for command handling, event production, and state reconstruction. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-2` |
| codec | A codec defines event type identifiers, payload encoding, payload decoding, and schema versions. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-3` |
| command cycle | A command cycle reconstructs aggregate state, evaluates a command, and appends resulting events with a concurrency check. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-4` |
| snapshot | A snapshot is aggregate state saved at a known stream version to reduce the events needed for reconstruction. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-5` |
| read model | A read model is a view of event-sourced data organized for application queries. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-6` |
| projection | A projection is logic that updates a read model from recorded events. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-7` |
| inline projection | An inline projection updates its read model within the transaction that appends a command's events. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-8` |
| asynchronous projection | An asynchronous projection processes committed events independently of command handling. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-9` |
| process manager | A process manager is an event-sourced coordinator that reacts to events with commands or timers. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-10` |
| router | A router is a stateless dispatcher that looks up command recipients in response to an event. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-11` |
| timer | A timer is a durable scheduled wakeup for a process or workflow. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-12` |
| durable workflow | A durable workflow is sequential code whose saved progress lets steps and waits resume after interruptions. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-13` |
| journal | A journal is the durable execution history that recovers workflow progress and supplies saved step results. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-14` |
| awakeable | An awakeable is a durable workflow wait for an external result or cancellation. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-15` |
| domain event | A domain event is a recorded business fact owned by a bounded context's internal model. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-16` |
| integration event | An integration event is a published business fact that forms a contract for consumers outside its owning bounded context. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-17` |
| transactional outbox | A transactional outbox is durable message storage whose enqueue commits atomically with its associated database changes. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-18` |
| inbox | An inbox tracks received messages so duplicate delivery does not repeat committed handler effects. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-19` |
| dead letter | A dead letter is a retained delivery failure that requires investigation before explicit replay. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-20` |
| sidecar | A sidecar is a supporting file that keiro-dsl generates alongside Haskell code. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-21` |
| scaffold ledger | A scaffold ledger is tool-maintained generation history that tracks service files and their ownership. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-22` |
| conformance ledger | A conformance ledger is tool-maintained generation history for a service's conformance test package. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-24` |
| Cabal fragment | A Cabal fragment is generated Haskell build configuration for inclusion in a package's Cabal file. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-26` |
| workspace manifest | A workspace manifest is authored configuration that groups keiro-dsl specifications into one service and declares generation settings. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-27` |
| replay safety | Replay safety is the property that recorded events can reconstruct the durable state produced by command handling. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-28` |
| symbolic transducer | A symbolic transducer is a state-machine model for command conditions, state updates, emitted events, and replay. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-29` |
| lifecycle state | A lifecycle state is the named stage of an aggregate that determines which transitions are available. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-30` |
| register | A register is a named, typed value that an aggregate retains alongside its lifecycle state. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-31` |
| transition | A transition is an aggregate rule that defines conditions, updates, emitted events, and the next lifecycle state for a command. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-32` |
| guard | A guard is a condition that must hold before a transition can handle a command. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-33` |
| subscription | A subscription is a consumer that follows selected event history and processes available events. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-34` |
| checkpoint | A checkpoint is a durable record of subscription progress through an event source. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-35` |
| stream category | A stream category is a named family of streams for event consumption. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-36` |
| stream version | A stream version is an event position within one stream that identifies the history seen by a command. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-37` |
| global position | A global position is a store-wide event cursor for ordering events across streams and tracking consumer progress. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-38` |
| query freshness | Query freshness is the policy that determines required projection progress before a read-model query runs. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-39` |
| projection catalog | A projection catalog declares projections, read models, event sources, target ownership, and rebuild boundaries. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-40` |
| physical target | A physical target is an application-owned database table that a projection maintains. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-41` |
| rebuild group | A rebuild group is a set of projection targets that must be rebuilt and returned to service together. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-42` |
| projection rebuild | A projection rebuild reconstructs or reconciles derived data from retained event history and verifies it before service. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-43` |
| replay adapter | A replay adapter is projection logic that safely processes historical events during a rebuild. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-44` |
| work queue | A work queue is a durable queue of jobs for background processing by a service. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-45` |
| job | A job is a declared kind of background work with a queue, payload format, ordering contract, and retry policy. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-46` |
| domain command outcome | A domain command outcome is the typed business result of a selected decision: acceptance, rejection, or an intentional no-op. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-47` |
| implementation hole | An implementation hole is an explicit boundary where application code supplies behavior outside the keiro-dsl specification. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-48` |
| create-once file | A create-once file is a file that scaffolding creates initially and preserves on subsequent runs. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-49` |
| projection revision | A projection revision is a declared schema and behavior version that can be deployed and rebuilt as one implementation. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-50` |
| projection generation | A projection generation is a physical instance of a projection revision's data. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-51` |
| promotion | Promotion is the controlled action that makes verified rebuilt projection data available for service. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-52` |
| external read contract | An external read contract is a versioned query interface for consumers outside a projection's process. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-53` |
| replay-only transition | A replay-only transition reconstructs historical events without letting new commands select the retained behavior. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-54` |
| fold version | A fold version is an application-maintained identifier for handwritten logic that reconstructs aggregate state from events. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-55` |
| replay audit | A replay audit checks candidate behavior against stored event histories for replay failures and reconstructed-state changes. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-56` |
| workflow step | A workflow step is a named action whose saved result is reused when workflow execution resumes. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-57` |
| child workflow | A child workflow is a separately identified durable workflow started by another workflow. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-58` |
| continue-as-new | Continue-as-new is a workflow operation that starts a new journal generation with explicitly selected state. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-59` |
| mapped type | A mapped type is a keiro-dsl declaration that connects a specification type to an existing application-owned Haskell type. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-60` |
| structural binding | A structural binding is a total conversion in both directions between an application-owned type and a DSL-declared structural shape. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-61` |
| hydration | Hydration is reconstruction of aggregate state from stored events, optionally using a compatible snapshot. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-62` |
| upcaster | An upcaster converts an older stored event payload to a format that the current application can decode. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-63` |
| idempotency | Idempotency is the property that repetition of an operation does not repeat its intended effect. | `mori://shinzui/keiro/okf/terminology/concepts/TERM-64` |
